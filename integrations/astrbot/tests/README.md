# 饥荒助手查询回归

使用 Python 3.12，在安装 AstrBot 4.29.3 的独立测试环境运行：

```bash
python -m pip install -r integrations/astrbot/tests/requirements.txt
python -m unittest discover -s integrations/astrbot/tests -v
```

未安装 AstrBot 时，核心逻辑仍可测试，框架适配用例会跳过。完整验收必须确认框架测试实际运行，不能只看最终 `OK`。
CI 安装上述固定版本依赖，实际运行框架适配用例。

| 场景 | 验证内容 |
| --- | --- |
| 常见问法 | `query_scenarios.py` 维护合成昵称、KU、房间别名与预期意图；每条读取问法叠加礼貌前缀和标点变体，验证解析目标及实际调用的固定 API |
| 菜单与消息结构 | 所有显示名称可执行，重复 At、At 前后位置、菜单数字与昵称表单均经过真实唤醒、白名单、插件分发及模型分流阶段 |
| 多轮与范围 | 房间选择、明确切换房间、重名候选、引用、隔离用户和旧菜单不会误选其他目标；离线档案不依赖当前在线人数 |
| 模型边界 | 原因分析、否定、条件、复合请求和普通聊天继续进入模型；完整快捷查询不请求模型，也不调用管理 API |
| 权限与副作用 | 普通群员不能使用管理菜单，原生权限与房间范围不能被别名、模型参数或只读标记绕过；写请求用替身验证去重及不确定结果不重发 |
| 数据与异常 | 核心查询超时保留失败原因，附加读取失败保持未确认；背包保留中文、存档时间与覆盖说明，缺失信息不当作 0 |
| AI 卡片 | 使用真实框架响应和完成钩子验证单项卡片与历史一致；错目标、混合工具、多结果、权限/来源变化、图片和流式各自验证边界 |
| 通知与模板 | 播报单一投递者、游标与原回执保留，模板不能隐藏业务证据，失败/冲突保存不生效，群设置不能扩大权限 |

批量问法以 unittest 的 `subTest` 运行，问法数量与测试方法数分别统计。全部使用合成数据，QQ 发送、模型和游戏 I/O 使用替身，不产生真实管理操作。这些回归验证确定的行为和失败边界，不代表穷尽自然语言，也不代替实际 QQ 收信、模型质量、端到端时延和游戏兼容性验收。
