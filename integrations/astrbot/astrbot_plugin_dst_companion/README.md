# DST Admin 饥荒助手

一个插件提供常用直查、AI 工具和游戏事件播报。技术插件名仍为 `astrbot_plugin_dst_companion`，可直接升级旧伴随助手，适用 AstrBot 4.29.3 / Python 3.12。

1. 在 AstrBot 添加面板 MCP：`https://panel.example/mcp?view=bot`，使用面板创建的访问密钥。已有连接无需再添加。
2. 导入 `astrbot_plugin_dst_companion.zip`。只有一个可用 DST MCP 时自动识别；多个连接时，管理员发送 `/dst 使用连接 连接名`。
3. AstrBot 管理员在自己的群里发送 **`/dst 启用本群`**，自动识别群与房间，不需要填写群号、平台 ID 或 roomId。

也支持 `/dst 启动本群 聊天播报 开` 一次开启群接入和聊天播报。`/dst` 显示设置帮助，`/dst 设置` 核对保存结果；这些命令不调用模型。修改插件文件后需要定向重新加载，在插件详情确认 `dst` 命令（处理器 `dst_command`）已注册。启用 AstrBot 白名单时，须先允许目标群；管理员豁免不代表全群已授权。

随后可以 `@机器人 菜单`、`1服谁在线`、`查背包 昵称`；菜单发出后 2 分钟内，同一用户可以直接回复序号。常用查询直接访问面板，其他自然语言默认继续交给原有 AI。

菜单显示的名称也可直接发送，例如 `玩家信息`、`玩家背包`、`在线玩家`、`房间状态`；未指定玩家时先询问昵称，不会把“当前在线 0 人”当成没有玩家档案。支持 `1服查询玩家信息`、`1服查一下 昵称 的背包`、`现在有谁在线`、`目前谁在线` 等常见表达。房间前后的查询词使用相同规则，明确房间后不会改查其他房间。真实 @ 前后的多余独立 `@` 不会让菜单落入模型；纯文字假 @ 仍不能唤醒插件。

也支持 `查询 昵称 背包`；未指定玩家且没有已确认的上下文时会询问昵称。开启群成员会话隔离时，群接入和播报按真实群号识别，菜单及查询上下文仍按用户隔离。原生白名单需允许目标群，不能只依赖管理员豁免或单成员会话。

背包中的原版物品使用包内与面板同源的中文词库，保留玩家自定义名称，未知模组显示原名或 Prefab；不额外调用模型或逐件查询。存档只有剩余保鲜时间时显示时长，不猜新鲜度百分比。

`/dst 订阅房间 房间名称` 可缩小本群范围，`/dst 订阅房间 全部` 同步面板允许的房间；不会按列表顺序给房间编号。`/dst 播报 开/关` 控制进退服和服务状态，`/dst 聊天播报 开/关` 控制公开聊天，`/dst 禁用本群` 同时关闭查询和播报。其他群不会自动启用。

引用本群的进服或退服播报说“查背包”即可定位玩家，支持按成员隔离的会话和已离线玩家；读取来源仍以面板为准。新播报的发送关联最多保留 128 条、24 小时，插件重载后可继续引用。不能确认的引用会要求昵称，不改查上一次的玩家，也不从引用推断管理操作目标。

聊天默认约 3 秒检查一次，只播报启用后的新公屏，不补发历史；连续消息合并，进退服详情读取不阻塞已入队聊天。高级 `chatPollInterval` 可设 2～30 秒；失败退避，无订阅则停止轮询。`/dst 设置` 显示实际检查间隔和投递拦截原因；投递结果不确定时不会自动重发。

查询密钥只开放查询。播报需要有读取事件/聊天权限的同源 MCP，插件会自动复用已有连接；缺少权限时明确提示，不影响查询。单个具备上述权限的 MCP 可以同时承担查询与播报；游戏写操作仍需原生管理员、显式角色及写能力授权。旧双插件可自动迁移播报游标和去重记录，确认保存后关闭原播报器。

高级自定义、升级与权限说明见[接入指南](https://github.com/lcy0828/dst-admin-go/blob/master/docs/astrbot-companion.md)。源码包不含凭证或用户记录；自动测试替换 QQ、模型和游戏 I/O，真实 QQ 收发需在自己的测试群验证。

管理员发物品需要单独配置游戏管理连接、`game_admins` 和 `writeAllowlist: ["player.give_item"]`；`/dst 设置` 可查看当前身份的授权状态。授权后可直接说 `给 测试玩家 发 3 个肉丸` 或 `给 测试玩家 三个肉丸`，插件会解析昵称、确认玩家所在分片并执行一次固定发放，不经过模型。只支持已知原版物品、食物和装备，单次 1–40 个；不确定结果只回读，不自动重发。普通群员保持只读。详细 API/MCP 参数及权限配置见接入指南。

### 消息外观与模板

默认回复使用房间短名称、世界状态图标、分区标题和北京时间。世界、玩家、模组各自保留可用性说明：读取失败不会显示成无人在线或模组为 0；离线背包保留存档时间和覆盖范围。

在 AstrBot → 插件 → DST Admin 饥荒助手 → **消息模板（全局）**，添加所需类型后编辑多行正文。每种类型提供内置正文与变量说明，不添加表示继承内置样式。保存插件设置后可在管理员会话预览。面板和游戏世界无需重启。

管理员也可在已启用的群中编辑覆盖，无需填写房间 ID 或群号：

```text
/dst 模板 列表
/dst 模板 查看 聊天播报
/dst 模板 编辑 聊天播报 💬 {room_name} · 游戏聊天
{lines}
/dst 模板 预览 聊天播报
/dst 模板 保存
```

编辑和恢复先进入个人草稿，5 分钟内保存才会生效；预览全部使用模拟数据，不会执行游戏操作。每条管理命令均由插件处理，不经过模型。可用 `/dst 模板 取消` 放弃，`/dst 模板 恢复 聊天播报` 后保存清除本群覆盖、继承上层。上述操作在“模板”后加“全局”即可管理所有群的默认值，例如 `/dst 模板 全局 预览 房间概况`。

| 类型 | 标识 | 主要变量 |
| --- | --- | --- |
| 聊天条目 / 聊天播报 | `chat_line` / `chat_batch` | `player_name`、`message` / `lines` |
| 进服 / 离服 | `player_join` / `player_leave` | `player_name`、`character`、`world_name`、`details`，另有玩家年龄、在线人数和世界天数 |
| 开服 / 停服 / 异常 | `server_start` / `server_stop` / `server_error` | `world_name`、`reason` |
| 房间概况 / 在线玩家 / 玩家资料 | `status` / `players` / `profile` | `title`、`body`、`room`、`player` |
| 背包 / 模组 / 连接质量 | `inventory` / `mods` / `network` | 同查询变量 |
| 扩展查询 / 管理回执 | `query` / `action` | 同查询变量 |

所有类型还可使用 `room_name`（短名称）、`room_full_name`、`time`；数据缺失时明确显示未确认。查询的 `time` 提醒查看各数据采样记录，不能当成全部数据的同一采样时刻。异步管理回执仅有原任务关联信息，不额外读取玩家或房间补变量。详细字段用“查看”核对。

优先顺序为 **本群覆盖 → 全局覆盖 → 旧版查询模板（如适用）→ 内置默认**。每份模板最多 2000 字、32 处变量，整组最多 64 KiB。不支持表达式、属性访问、脚本、循环或 CQ 指令；变量内容不会再次解析。查询与管理必须保留 `{body}`，聊天必须保留 `{message}` / `{lines}`，进退服保留 `{details}`，异常停服保留 `{reason}`；业务正文与结果证据不能通过模板隐藏。非法命令编辑会被拒绝；外部写入的无效配置在读取时回退，不会影响查询权限或关闭播报。

保存失败不会发布新模板；冲突需取消后重新编辑。模板只影响新生成消息，已经入队的通知保持原文，不补发历史。每房间最多 5 条聊天合批、原顺序与结构化玩家引用关联继续保留。模板不增加后台任务、面板请求或模型调用，也不会改变群、房间和管理员权限。

模板控制插件自己的查询、回执和通知。显式使用 AI 查询一个明确的房间状态、玩家、背包、网络或模组，并且只调用本插件读取工具、得到一张匹配卡片时，非流式最终回复会保留该卡片，防止来源、存档时间或缺失说明被改写。多房间、复杂分析、混合其他工具、图片与流式回复保持模型输出，并提供饥荒回复格式提示；不能撤回已经发送的流式内容。其他话题沿用原有人格。新通知的引用根据投递回执关联玩家，不能依赖自定义文本猜人；缺失回执时会要求明确玩家。
