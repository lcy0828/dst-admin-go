# AI 助手与 OpenAPI

[English](ai-assistant.en.md)

右下角的 **AI 助手** 可在任意管理页面打开；侧栏 **运维工具 → AI 助手** 提供完整对话、接入配置和操作记录。

## 开始使用

1. 在“接入配置”启用 AI，填写模型地址、名称和密钥，保存并测试连接。
2. 选择房间，直接描述要检查或执行的操作，例如“帮当前房间开启自动备份，每天凌晨 4 点，保留最近 7 份”。
3. 回复优先显示结论；处理过程默认折叠，可展开查看真实接口结果。下载结果以按钮展示。

模型需支持 **OpenAI Chat Completions 工具调用**。地址可填写 `https://api.example.com/v1` 或完整的 `/chat/completions` 地址。可信内网模型可使用 HTTP，无密钥服务允许留空。

页面助手使用当前管理员身份。已明确要求的管理操作直接执行；目标、参数有歧义时会先询问。状态检查本身不会修改设置。房间选择器是当前对话的默认对象，明确要求时可以操作其他房间或全部房间。

对话按管理员账户保存在当前浏览器，保留最近 32 条消息与草稿；切页、收起窗口、切换房间和刷新不会清空。更换浏览器或清理站点数据无法恢复。刷新会中断等待，已提交的任务可能继续执行；系统不会自动重发操作。操作记录保存在管理中心。

## 管理能力

页面助手和外部 MCP 共用已发布的 OpenAPI 管理接口，覆盖房间与世界配置、启停和存档、模组、玩家、备份与定时任务、游戏安装和更新、运行节点、通知及系统设置等领域。新增管理接口通过同一契约进入工具目录，无需维护另一套 AI 操作实现。

- 常用查询有简短工具：运行状态、分片 CPU/RSS、真实玩家、已配置模组、备份、定时任务、日志、任务与命令回执。
- 生成生物或发放物品时，优先使用内置命令，回执包含可确认的[生成位置与去向](command-spawn-records.md)。不完整或缺失的记录不能用于推断没有生成。
- 其余操作通过 `find_api` 按领域或 `operationId` 发现，再调用对应的 `api_<operationId>` 工具。页面按需加载匹配的参数定义，避免每次提问都发送全部接口。
- 工具说明包含作用范围、前提与副作用，参数说明与公开 OpenAPI 保持一致。兼容接口通过 `deprecated` 和 `x-dst-replaced-by` 标注：新调用使用 `listCommands` 和 `listWorldStates`，旧的 `listRoomCommands`、`refreshWorldStates` 仍可按原名称调用。常规搜索优先推荐对应新入口。
- 已安装的本地模组也可读取、逐世界启停和修改配置，使用 `local:<目录名>`；工坊操作继续使用数字 ID。本地详情须指定机器与安装，不能通过 Steam 下载。具体目录和 Agent 要求见[模组管理](mod-management.md#本地模组)。
- `configureRoomBackupSchedule` 支持启用、修改和暂停备份。未指定的设置保留；首次创建默认每天 04:00、`Asia/Shanghai`、保留 7 份。多个计划需明确选择，结果返回实际启用状态和下次执行时间。
- 密码、密钥和 Steam 验证码可通过输入框旁的“私密输入”按钮提供；内容加密保存，模型只收到名称和引用，执行时再验证实际值。
- 文件可通过输入框旁的附件按钮上传，再交给导入、备份上传等实际管理接口；每个文件最多 2 GiB，临时附件总量最多 4 GiB。附件按调用者隔离，24 小时后失效，并在后续上传时清理。
- 下载操作返回需登录的临时链接；生成链接不代表内容已被检查。接口返回的新密钥等私密内容加密暂存，管理员可通过“下载结果”获取，模型和对话记录只收到脱敏结果。

操作仍经过页面相同的身份、部署角色、参数、版本修订、容量、Placement 和 Runtime 校验。本机走进程内 Runtime，远程及跨机器房间按已应用的部署位置执行，不会退回控制端操作。

任务提交、操作执行和游戏实际就绪是不同状态。助手应查询返回的任务或命令回执后再报告完成。超时或回执不明时标为“结果待核实”，应先检查实际状态再重试。停止的世界没有实时采集属于正常情况；容量预估也不代表当前故障。

模型连接短暂中断或服务暂时不可用时，仅重试一次模型请求，不重放管理操作。模型回复中断后仍保留平台回执，并尽可能读取已提交任务的实际状态；请先核对任务结果，再决定是否重试。单次模型等待沿用配置中的单轮总时限，活动对话通过心跳维持连接。

## 外部 AI 和 API 客户端

在“接入配置”创建有名称和有效期的接入密钥，选择“游戏查询”“游戏管理”或“面板管理”用途，以及允许访问的房间。游戏用途必须限定房间；旧密钥保留原有面板管理权限。明文只显示一次，同时用于 **MCP 和 REST API**；到期、撤销或关闭 AI 后，新请求会被拒绝。用途限制由服务端实际执行，不能通过更换工具名或 REST 入口绕过。

QQ / AstrBot 可使用[官方伴随助手](astrbot-companion.md)，常见查房、在线名单、昵称定位与背包查询直接调用面板，复杂问题继续交给已有 AI 人格；按角色仅向模型呈现少量工具。

MCP 使用 **Streamable HTTP**：

```json
{
  "mcpServers": {
    "dst-admin": {
      "type": "http",
      "url": "https://panel.example.com/mcp",
      "headers": { "Authorization": "Bearer <ACCESS_TOKEN>" }
    }
  }
}
```

字段依客户端而异，请选择 HTTP / Streamable HTTP 传输。外部客户端使用自己的模型，无需配置面板内模型。连接沿用管理 IP 白名单和来源检查，跨网络使用 HTTPS。

REST API 的契约可登录后下载：`GET /api/v2/system/openapi`，也可查看仓库的 [OpenAPI](openapi-v2.yaml)。

```bash
curl -H 'Authorization: Bearer <ACCESS_TOKEN>' \
  https://panel.example.com/api/v2/rooms

curl -X POST \
  -H 'Authorization: Bearer <ACCESS_TOKEN>' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: backup-schedule-001' \
  -d '{"enabled":true}' \
  https://panel.example.com/api/v2/rooms/<ROOM_ID>/backup-schedules/actions/configure
```

REST 写操作必须提供 `Idempotency-Key`；使用 Cookie 登录时还必须提供 `X-CSRF-Token`。MCP 修改工具使用 `requestId`。重试同一操作应沿用编号；同编号配不同参数会报冲突。页面助手自动管理这些字段。

外部客户端上传附件使用 `POST /api/v2/system/ai/attachments`，表单字段为 `file`，使用同一 Bearer 密钥。返回的 `id` 可作为管理上传工具的 `body.file.attachmentId`。下载结果也使用同一认证身份。

前端接口映射来自 OpenAPI；修改契约后运行 `go run ./cmd/openapi-manifest`，前端副本通过 `-out <前端目录>/src/api/openapiOperations.json` 生成。CI 检查路由、操作编号、参数和响应 Schema 引用，以及生成文件是否同步。

## 对话与资源设置

“接入配置 → 页面对话限制”可设置每轮查询轮数、调用次数和总时限，默认 **8 / 12 / 150 秒**，填 **0** 可取消对应限制。保存后从下一次提问生效，无需重启；达到限制后会尽量汇总已有结果。外部 MCP 客户端自行管理对话循环。

AI 未使用时不启动采集、模型轮询或后台任务。同时最多处理 2 个 AI 请求、2 个实际工具调用。日志、返回结果与上下文有大小边界，大结果保留摘要和可追溯的任务编号；完整内容仍可在相应管理页面查看。

状态、日志及必要的工具结果会发送到配置的模型服务。常见密钥字段会脱敏，自由文本无法保证全部识别，请勿在普通提问中粘贴密码或密钥。模型密钥和临时私密结果使用配置目录下的 `ai/provider.key` 加密；备份管理数据时应一并保留该文件。外部接入密钥仅保存摘要。

### MCP 工具目录与分类

默认连接 `/mcp` 提供精简的常用工具与两个完整能力入口，避免一次向模型传入数百个工具：

1. 调用 `find_api`，用关键词或 `tags`、`access`、`risk`、`runtime` 查找能力。需要了解参数时传 `includeSchema: true`。
2. 调用 `call_api`，传返回的 `operationId`，把符合 `inputSchema` 的参数放在 `arguments` 内。写操作的 `requestId` 也放在 `arguments` 内。执行仍经过原接口校验、幂等和 Runtime 保护。

需要规范工具列表的客户端可修改连接 URL：

| URL | 工具列表 |
| --- | --- |
| `/mcp?tags=backup&access=read` | 备份领域的只读规范工具 |
| `/mcp?tags=mod,player` | 模组或玩家领域的规范工具 |
| `/mcp?view=all` | 全部规范工具，不含弃用别名 |
| `/mcp?view=legacy` | 包含旧便捷工具和弃用别名的兼容列表 |

列表每页最多 64 项，通过 MCP 标准 `nextCursor` 继续获取；下一页应使用相同 URL。多个标签按“或”匹配，其他维度按“且”匹配。工具调用名称继续兼容，列表筛选不改变执行权限。旧客户端若依赖全量发现，可使用 `view=legacy`；工具数量受限的模型建议保留默认连接。

每个工具的 `annotations` 提供标题、只读、幂等、破坏性及外部交互提示；多标签、读写类型、风险和运行条件在 `_meta["io.github.lcy0828.dst-admin/tool"]`。这些是行为描述，不增加审批流程。`runtime` 的 `any` 表示没有统一的运行中要求，仍需遵守接口声明的停止状态等条件。`docs/openapi-operations.json` 也包含相同分类，新增同领域接口会自动继承标签。

## 当前数据与操作范围

房间名称、ID 和对话上下文可以跨轮复用；天数、季节、天气、日志、玩家、
性能和配置等当前事实需要本轮对应查询。页面助手发现缺少这类查询结果时，
会在管理员设置的工具预算内补查一次；仍未取得有效结果则说明无法确认，
不会把旧对话当作刚刚查询的结果。普通解释和对象澄清不要求工具调用。
这项检查不能代替对模型答案的判断；工具返回的时间、范围和不完整状态仍是依据。

只读检查直接执行。指定单个分片的启停使用 `runRoomAction` 的 `body.worldIds`，
不得省略为整房间操作。外部 MCP 客户端获得相同的工具使用说明，但最终回答
由外部客户端生成，页面助手的回答检查不作用于外部模型。

中文工具描述、场景词、结果字段和客户端索引接入见 [MCP 工具发现与返回结果](mcp-tool-discovery.md)。

游戏更新或模组冲突排查也可直接使用[游戏与模组分析](mod-diagnostics.md)，页面与 MCP 共用只读报告，包含错误上下文及更新前后的摘要比较。

玩家活动与历史轨迹请使用[玩家活动记录](player-activity.md)：与页面共用持久化证据，可查询活动、位置和战斗并修改采集间隔。缺口、未采集或已过期的数据不能由 AI 补全。


## 机器人主动通知与性能报表

在 **连接 → 机器人接收平台通知** 中配置 Webhook；不需要另一套通知配置。没有接收接口的 MCP 宿主可以定时调用 `readNotificationEvents`，按返回游标补读通知并唤醒模型。平台不会因普通 MCP 连接而自动唤醒外部机器人。详见[通知接入与补读](notifications.md#机器人补读通知)。

查询历史性能时，通过 `find_api` 查找 `getRoomPerformanceReport` 并获取参数结构。使用真实房间 ID 作为 `path.roomId`；`query` 可包含 `worldId`、RFC3339 `from` / `to` 和 `maxPoints`（AI 建议 60）。优先读 `worlds` 中的整段统计、覆盖率和规则分析，再按需查看曲线及运行事件。分数反映模拟推进比例，不能当作 FPS；缺测和暂停不记作零分，也不能从时间接近推断模组导致卡顿。采样与保留设置使用同一套 OpenAPI。见[性能与报表](performance-reports.md)。

### 排查管理服务自身异常

除游戏世界日志外，AI / MCP 现在可查询控制端和 Agent 的持久化服务日志，按任务 ID 或请求 ID 关联排查。入口、参数和保存边界见[服务日志](service-logs.md)。
