# 定时任务与房间备份

[English](automation.en.md)

在“定时任务”中选择房间，然后添加任务。游戏命令可选择命令模板（包括自建模板），或直接填写多行 Lua 脚本；命令在指定世界执行。管理员保存的计划支持全部命令风险等级，每次执行保留任务结果与控制台记录。

在“房间设置 → 自动维护”分别启用模组和游戏服务端自动更新。新计划默认每 15 分钟检查，可调整间隔或为游戏更新填写自定义 Cron；默认不自动启用。模组配置与“模组管理 → 更新策略”共用，默认无人宽限时间为 60 秒。

发现更新后，系统主动确认所有受影响房间的在线人数，有人或无法确认时等待下次检查。共用安装的房间一并检查；跨机器房间的游戏安装一起更新，避免 Master/Caves 版本不一致。模组在无人时下载，等待宽限时间后再次确认并重启。游戏更新先创建保护备份，再更新并校验启动结果。只恢复原本运行的世界，没有更新时不重启。游戏更新中断后自动维护暂停该安装的后续更新，请在“游戏服务端管理”查看更新记录并恢复；不会用下一轮更新覆盖恢复记录。

“备份管理”选择房间后，可添加多个独立定时备份计划，修改时间、时区或暂停。支持五位 Cron（分、时、日、月、周），也支持第一位为秒的六位表达式。例如 `0 4 * * *` 表示每天 04:00，`0 */6 * * *` 表示每六小时。执行历史在“任务与记录”查看。

定时备份包含房间的全部世界。本机、远程或跨机器房间统一在全部世界运行时使用热备份。部分世界运行时会短暂停止并恢复原运行世界，已经停止的世界不会被启动。热备份失败会记录错误，不会自动改为停服备份。计划可设置保留最近 1–100 份自动快照，新计划默认 7 份，留空则不自动清理。清理只在备份成功后执行，不删除手动备份、保护备份或恢复操作正在使用的备份。保留数量作用于该房间全部计划创建的快照；多个计划建议设置相同数量。旧 ZIP 快照与新备份集分别计算保留数量。已有计划未配置保留数量时，沿用原行为。

计划由管理服务调度，关闭浏览器不影响执行；管理服务停止期间不会执行任务。任务取消或超时后，清理不会继续处理下一份备份；正在删除的单份备份会完成收尾，已删除的备份不会自动恢复。

系统设置中的备份入口跳转到房间计划，不再用一个全局开关覆盖全部房间。旧版本已启用的间隔备份计划继续运行，在该房间的定时备份区域可查看和暂停。

新备份集支持下载和删除。下载得到常规房间 ZIP，包含 `cluster.ini` 等共享文件和各世界目录，可从存档导入页面重新导入。跨机器房间导出共享配置时采用 Master 的文件，导入后需按目标机器检查网络配置。删除需确认备份名称；仍被恢复、模组发布或游戏更新使用的保护备份不能删除。

页面中的手动备份使用一致性备份流程，并保留旧 ZIP 的查看、下载、恢复和删除入口。旧 ZIP 创建接口只支持已停止的房间。

上传临时文件写入对应功能的数据目录，需要为上传及后续处理预留磁盘空间。HTTP 上传读取上限为 2 小时，反向代理也需允许相应大小和时长。异常退出遗留的上传、导出临时文件会在服务启动或下次同类操作时清理；正在上传或下载的临时文件受保护。
