# 游戏通知功能说明

## 页面用途

“游戏通知”只管理真实发送到 DST 游戏内的消息，不再维护没有投递能力的后台公告。

- 即时通知：优先从运行中的主分片执行一次 `c_announce`，由 DST 转发到相连分片；主分片未运行时选择其他运行分片。
- 操作前提醒：停止、重启、游戏更新和 Mod 重启生效前按房间策略倒计时。
- 自动化通知：定时任务使用 `notification.send`，并进入同一发送历史。
- 发送历史：保存消息来源、Job、房间及逐分片成功、失败、跳过、取消和目标节点。

## 倒计时行为

- 默认开启，默认提前 30 秒，可配置 10-600 秒；页面提供 15、30、60、120、300、600 秒选项。
- 在起始时间、30 秒和 10 秒节点中发送适用的提醒。
- 维护前即时查询各运行分片的游戏在线名单，按玩家 ID 去重；确认无人时不公告、不等待。暂停不等于无人，数据库旧人数不参与判断。
- 人数查询失败时明确显示“无法确认”，按房间策略保留通知等待。
- 停止/重启确认弹窗显示本次在线人数、通知设置，并提供“立即执行”；该入口只跳过本次通知与等待，不更改策略。执行时再次读取人数，避免把弹窗打开时的空服结果沿用到稍后的操作。
- 定时玩家采集在暂停时仍合并日志中的最后离线事件，保持人物属性的原始采样时间。
- 多房间游戏更新使用一条统一时间线，不会按房间串行累加等待时间。
- 投递失败会记录但不会阻止维护；取消 Job 会同时取消倒计时和后续操作。

## 部署与分片

投递通过 Placement 感知的 Runtime Driver 完成，因此本机、Agent 和混合部署使用同一行为。已停止的分片，以及由游戏转发而无需重复投递的分片，均在历史中标记为“跳过”并注明原因。控制台接收不代表已确认每个玩家收到；分片之间断连时，广播无法保证送达断开的分片。

## API

```text
GET  /api/v2/game-notifications
POST /api/v2/game-notifications
GET  /api/v2/rooms/:roomId/game-notification-policy
PUT  /api/v2/rooms/:roomId/game-notification-policy
GET  /api/v2/rooms/:roomId/maintenance-preview
```

旧 `/api/v2/announcements` 路由不再注册。旧公告代码和表仅暂留用于识别历史数据，不参与新功能。
