# TMIR 功能对照矩阵

对照模组：Steam Workshop `3638290455`（Too Many Items Revisited / TMIR）。

本矩阵基于本机已下载源码中的 `circle_button_list.lua`、`circle_commands`、`debug_button_list.lua`、`debug_commands` 和 `items_commands`，不是只根据 Workshop 介绍页判断。

## 实现边界

- 后台只发送固定白名单和参数化 Lua，不开放任意 Lua 输入。
- 所有状态变更统一使用普通确认弹窗；房间、世界和 KU ID 均来自当前选择，不要求手工输入确认文本。
- God 和 Creative 复用玩家管理 API；保存、回滚、关服、重生成、管理员和角色重选复用项目现有页面。
- 常用实体由内置目录提供，其他 Prefab 通过 Beacon 实体目录查询。Prefab 仍经过后端格式校验。

## 部分实现，仍可继续迁移

| TMIR 功能 | 当前差异 | 建议 |
| --- | --- | --- |
| Prefab 计数 | TMIR 可统计附近或全图数量；当前范围操作会记录受影响数，但没有只读计数结果 UI。 | 增加只读命令，并把结构化结果接入任务日志或运行结果。 |
| 跨分片迁移 | 当前召集/前往/召回/交换限同一分片。 | 需要接入 shard migration 目标和入口 ID，不能用同分片坐标替代。 |
| 天体任务和寄居蟹任务 | TMIR 使用客户端弹窗读取阶段并选择跳过；当前没有对应管理 UI。 | 可拆为只读状态 API 和白名单阶段推进 API。 |
| 裂隙事件 | TMIR 只发送模组内部 `tmir_incident_rift` 事件；脱离模组后该事件没有处理器。 | 必须按游戏组件重新实现具体裂隙动作，不能照抄空事件。 |
| 生肖占位项 | TMIR 对尚未受游戏支持的生肖只显示提示；当前仅列可实际应用的活动。 | 游戏加入对应活动 ID 后再进入白名单。 |
| 操作反馈 | 当前确认请求已发送，具体游戏内失败主要写入服务器日志。 | 后续可从运行日志解析统一结果码并回显。 |

## 后台无法等价复刻

以下功能依赖 TMIR 客户端 HUD、鼠标位置、相机、客户端 RPC、地图网格或本地持久化数据。后台可另做管理工具，但不能声称与模组等价：

- 超级视野、全图显示/隐藏、观战、展示和相机跟随。
- 地图点击传送、地标面板、自定义传送点和生物群系传送。
- 地皮绘制、道路编辑、阵列规划、拖放搬迁和虫洞交互式配对。
- Vault Maze 房间弹窗及其他依赖 TMIR Widget/RPC 的交互。
- 圆形菜单布局、快捷键、搜索历史、自定义物品分类和本地显示设置。

## 关键语义约束

- 重复开启能力不能覆盖“开启前状态”；关闭隐身或无仇恨时必须保留另一个能力需要的标签。
- God 与水上行走共享原始 `ShouldDrown`，按独立来源恢复，关闭其中一个不能破坏另一个。
- 临时配方解锁覆盖存档结果，关闭时恢复原配方；永久解锁不再恢复。
- Wormwood 阶段、阶段进度和生长方向分别处理；Wurt 鱼人王装备是切换操作。
- 所有 Prefab、枚举、KU ID、数量、半径和倍率在后端再次校验，前端限制不作为安全边界。
