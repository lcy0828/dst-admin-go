# 工作台查询、预览与确认

工作台、MCP 和官方 AstrBot 插件使用同一组服务端固定操作。可以按“闪电”“月雹”“隐身”“踏水”“阿比盖尔三级”“冻结附近生物”等具体动作查找，不必记住父命令名称。新增说明不会增加顶层任务工具的数量，也不会自动扩大群权限。

## 查找操作

MCP 任务视图使用 `dst_find`：

```json
{"query":"冻结附近生物"}
```

返回至多三个已授权候选。其中 `workbench.act_nearby_entities` 会提示 `action: "freeze"`，并列出还需提供的玩家和半径。目录中的 `actions` 仅包含名称、搜索词、说明和固定枚举建议，不含可下载执行的代码。服务端执行时重新校验固定命令、参数与权限，不信任调用者声称的风险或只读属性。

支持新版目录的插件可把明确指令交给固定操作处理；否定、条件、讨论、多动作等复杂表达继续交给 AI。AI 也不能代替用户完成危险操作确认。旧插件可继续使用父能力及其参数，新子动作的自动预填需要更新插件。

## 查询玩家模式

调用 `dst_world`，数据仅来自指定世界的本次观测：

```json
{"room":"示例房间","world":"地面","view":"player_modes"}
```

原生工具为 `api_queryRoomWorld`：

```json
{"path":{"roomId":"ROOM_FROM_LIST","worldId":"WORLD_FROM_LIST","queryId":"player_modes"}}
```

成功结果的 `data` 示意：

```json
{"kind":"player_modes","players":[{"id":"KU_EXAMPLE","invincible":"enabled","creative":"disabled","panelGod":"disabled","panelInvincible":"enabled"}],"count":1}
```

- `invincible`、`creative`：游戏当前可观测的免伤和自由制作状态。
- `panelGod`、`panelInvincible`：当前角色上由面板请求的综合无敌和普通免伤。
- `enabled` / `disabled` / `unknown`：已开 / 已关 / 无法确认。没有字段、旧记录或未知来源不能当成关闭。

应一并检查外层 `status`、`complete` 和 `observedAt`。只读查询不切换模式、不保存世界、不启动维护任务。玩家迁移中不推断其所在世界。

综合无敌沿用原入口 `api_setRoomPlayerGodMode`：免伤、持续补满三维、体温湿度保护和移动保护。普通免伤使用 `workbench.set_player_invincibility`，参数为 `player_id` 和明确的 `enabled`，不补满属性、不改变碰撞。两者均属于游戏管理操作。

关闭时仅解除本面板持有的效果；原本已无敌、原本已自由制作，或模组随后替换的方法与碰撞范围会被保留。已补满的属性、已经制作的物品不会撤回。发现来源冲突或没有可靠的开启记录时返回 `MODE_OWNERSHIP_UNCERTAIN`，请核对当前状态，不能声称已恢复原状。其他模组直接写入与面板相同的布尔值，无法可靠区分来源；隐身的外观等历史开关也不保证能恢复第三方状态。旧入口不自动跨登录、换角色或换世界重新开启。扩展入口的显式模式记忆见下文。

## 附近操作先预览

灭火 `extinguish`、冻结 `freeze`、催眠 `sleep`、平息仇恨 `pacify`、删除 `delete` 和击杀 `kill` 保留第一版回执。拾取、种植和角色设置使用下文的第二版回执。这些操作即使省略 `phase`，也只做预览。预览仍要求游戏管理权限，不向普通查询用户开放。

开发者使用 `api_executeBuiltinRoomCommand` 预览：

```json
{
  "path":{"roomId":"ROOM_FROM_LIST"},
  "body":{"commandId":"act_nearby_entities","worldId":"WORLD_FROM_LIST","arguments":{"player_id":"KU_EXAMPLE","action":"freeze","radius":10,"prefab":"spider","phase":"preview"}},
  "requestId":"preview-example-001"
}
```

确认回执包含 `batch.state: "preview"`、`previewId`、中心坐标、符合条件的对象数量，以及 `expiresIn: 30`。此时没有修改游戏。

面板显示“确认本次预览”，插件要求用户在30秒内直接回复“确认”。可信客户端执行时使用相同参数，将 `phase` 改为 `execute`，传入原 `preview_id`，外层 `confirmed: true`，并为执行步骤分配独立的请求编号。原生任务 MCP 对危险执行要求转到面板或可信插件确认，不能通过模型填写 `confirmed` 绕过。

预览绑定接入身份、房间、世界、玩家实例、原中心与目标对象。玩家移动不会改变中心；后来进入范围的对象不加入旧预览。换世界、重启、对象失效或保护条件变化会使执行拒绝或跳过。相同预览最多消费一次，部分执行也不能重放。机器人共用密钥时由插件额外绑定群和用户。

取消使用同一参数及 `phase: "cancel"`；插件回复“取消”会清除确认表单，游戏端的只读预览在30秒内过期。批次为短时同步执行，不能打断正在运行的游戏组件方法，也不承诺撤销已发生的效果。

执行结果区分：

| `batch.state` | 含义 |
| --- | --- |
| `preview` | 只预览，尚未修改 |
| `cancelled` | 已取消预览 |
| `completed` | 全部目标效果已确认 |
| `partial` | 已结束，但有跳过、失败或未确认效果 |

`matched` 是预览合格目标数；`attempted` 是实际尝试数；`verified`、`unconfirmed`、`skipped`、`failed` 分别表示已确认、效果未确认、跳过和失败。例如添加寒冷但尚未冻住，会计入 `unconfirmed`，不会称为已冻住。没有有效输出、输出截断、只有发送成功，都不能当成完成；查询原回执，不自动重发。

## 资源限制与兼容

预览最多保留16份，每份30秒；一次空间查询最多接受512个候选、40个合格目标；预览和执行均有4毫秒协作式 Lua 预算。不在后台常驻扫描。游戏引擎的同步空间查询、单次模组组件方法不能被该预算强行中断，因此这些上限不等于实际游戏延迟保证。

尚未接入上述两版预览协议的其他附近动作，保留原有管理员入口和保守确认；传入 `phase` 会拒绝。它们有遍历、生成、嵌套查询与耗时上限，达到预算后可能已部分执行，应先检查实际状态。材料按总量提前校验，最多生成40个材料实体；整组物品另限制实际单位数。组件内部的连带掉落不等于面板直接生成数。

原有模式归属与范围预览需要 Runtime 2.4.21；旧 Runtime 不支持时返回 `WORKBENCH_UPDATE_REQUIRED`，不会降级为无保护 Lua。面板安装更新不会把本说明中的新模式自动应用到正在运行的玩家；已有旧模式缺少归属记录时保守报告无法确认，需要操作者核对。

接口保留原名称和父能力 ID。新增目录字段是可选字段，不写入旧插件严格解析的参数 Schema。行为修订变化会使尚未执行的准备任务失效；已提交的任务仍在当前权限下读取原记录。修改说明文字不会让准备任务失效。面板更新不自动下载安装插件代码。

## 拾取、种植与角色设置

以下固定操作使用 `preview-confirm-v1` 交互和第二版效果回执，需要 Runtime 2.4.23 及支持该交互的面板／插件。旧 Runtime 在修改前返回升级提示；其他已有查询继续使用原有契约。普通启动房间不会更新游戏管理脚本，应通过已有的 Runtime 更新入口完成更新。

| 命令／动作 | 范围与限制 |
| --- | --- |
| `act_nearby_entities.pick` | 拾取中心玩家附近无持有者的地面物品，进入该玩家主物品栏；支持有证据的堆叠合并、部分接收，不自动访问背包或其他容器。 |
| `.repair` | 地面装备的使用次数与护甲耐久；不补燃料、不充能、不深入容器、不修改旁人的装备。 |
| `.fertilize` | 可施肥的原版草、树苗、普通浆果丛及芦苇适配；只处理原生组件判断确实需要施肥的对象。肥料由管理员补充，不扣玩家材料，不代表恢复整个农田的营养。 |
| `.grow` | 对支持的植物推进一个生长阶段；不清零其他计时器。 |
| `.ripen` | 与推进一阶段分开，支持的原版农作物最多推进到第 5 阶段，并核对可收获状态；草、树苗、普通浆果丛和芦苇使用原生再生方法。不会保证巨大化。 |
| `.harvest` | 首批采摘草、树苗、普通浆果丛和芦苇；需要主物品栏有空间。随机农作物掉落、巨大作物、锅、晾肉架及模组私有产出不在此适配范围；合并后无法关联产物身份时仍会显示待确认。 |
| `.repair_burnt` | 重建原版科学机器和炼金引擎，保留位置、朝向和可用皮肤；不找回烧毁前已丢失的数据。箱子、锅、船及其他建筑不采用通用替换。此动作仍需危险操作权限。 |
| `set_player_hunger_rate` | `mode=set` 时提供 `multiplier`（0–5）；`mode=remove` 只解除面板自己的倍率，其他模组效果保留。离线、换世界或 Runtime 更新后不自动重新施加。 |
| `set_wanda_age` | `age=young|normal|old`，使用原生年龄与生命联动，对应约 26／50／74 岁的目标段位；正在受伤或变身时拒绝，不恢复技能冷却。 |
| `restore_woodie_human` | 通过原生兽化值与状态机恢复人形；忙碌、骑乘、乘船或迁移时拒绝。不替换玩家，不补满属性。 |

农作物阶段适配包含胡萝卜、玉米、南瓜、茄子、榴莲、石榴、火龙果、西瓜、番茄、土豆、芦笋、洋葱、大蒜及辣椒。未知植物、改写的组件方法、特殊阶段和超出预算的对象不会用通用计时器或循环生长兜底。

准备年龄或饥饿设置同样需要 `player_id`，只读取这一名玩家，不扫描附近对象。示例：

```json
{
  "path":{"roomId":"ROOM_FROM_LIST"},
  "body":{"commandId":"set_player_hunger_rate","worldId":"WORLD_FROM_LIST","arguments":{"player_id":"KU_EXAMPLE","mode":"set","multiplier":0.5,"phase":"preview"}},
  "requestId":"hunger-preview-example-001"
}
```

插件动态能力名为 `workbench.set_player_hunger_rate`、`workbench.set_wanda_age`、`workbench.restore_woodie_human`；附近动作继续使用 `workbench.act_nearby_entities`。任务 MCP 仍通过 `dst_find` 和原有执行入口发现、准备操作，不增加一批顶层工具。模型可以准备预览；最终修改由面板或可信插件的原用户确认。管理员程序直接调用 API 时承担其凭据的管理权限。

官方插件可直接处理“给示例玩家附近的作物施肥”“示例玩家附近催熟”“示例玩家附近拾取掉落物”“把示例玩家的饥饿消耗改为一半”“让示例玩家恢复人形”。也可使用目录中的动作名后接昵称。含糊的“修复附近”、否定、条件和讨论会交给 AI 理解，不强制使用 `AI:` 前缀。

服务端返回的 `interaction` 位于参数 Schema 之外，示意：

```json
{"kind":"preview-confirm-v1","resultVersion":2,"effectVersion":"1"}
```

客户端只识别固定的交互枚举，不能执行目录提供的脚本。动作的权限、效果或交互契约变化会使未提交的旧确认失效；仅改名称和搜索词不会使它失效。

第二版 `batch` 包含 `version:2`、原请求编号、动作、预览起止时间、汇总和有界逐项结果。执行结果满足 `matched = verified + unconfirmed + skipped + failed`；`attempted` 表示已开始调用修改方法的对象。`units` 只统计已确认收到的物品单位数。调用抛错可能发生在修改之后，按待确认处理，不能解释为没有修改；缺失、截断或身份不匹配的回执也不会解释为成功。历史第一版回执保持原字段、30 秒预览及严格解析。

一次检查最多 512 个候选、40 个对象、40 个组件步骤／临时物品和 200 个产出单位；重建最多 10 个对象。数量过多时要求缩小范围，不自动拆批。空间查询和单个原生方法都是同步调用，4ms 是检查后续工作是否继续的预算，不是能中断引擎调用的时限保证。

角色切换最多短时观察 5 秒，沿用原任务回执；暂停或未完成时显示待确认，不自动解除暂停或重发。结果不确定的对象会阻止新的重叠操作；先读取原任务，不能靠点击“已核对”让仍可能执行的操作重新运行。其他无关对象仍可管理。持续倍率的清理由游戏端负责，不需要控制端保持在线。

参考模组名为“日食”的功能实际修改全天白昼／黑夜分段。本项目提供 `set_daylight_mode`，按实际效果命名，并可恢复本入口记录的原分段。跨世界迁移、地皮编辑、阵列、道路和模式记忆的支持范围见下文。

## 胡须与角色适配

`workbench.set_character_power` 的 `beard_none`、`beard_short`、`beard_medium`、`beard_long`
同时支持威尔逊和韦伯。按角色使用原生生长阶段：威尔逊为 4／8／16 天，韦伯为 3／6／9 天。
需要玩家在线、存活并且对应胡须组件可用；未知角色、缺失组件或缺失目标生长回调时不修改。
这不会发放剃须产物。威尔逊的胡须储物槽随原生组件调整，缩短或移除胡须可能让物品掉到地上。
原命令 ID、参数与游戏管理权限保留；插件可从目录中的“韦伯长胡须”等名称找到这些操作。

工作台的具体支持范围见[工作台能力范围](workbench-support.md)。


## 扩展工具与八种模式

扩展需要 Runtime 2.4.24。功能对照见[支持范围](workbench-support.md)。本机和 Agent
运行同一份管理脚本；更新面板后仍需更新对应机器的运行脚本才能使用新功能。

在页面选择房间、世界和在线玩家后，打开“更多工具”。资源卡片的右键菜单和更多按钮
可直接带入物品与数量；鼠标中键的六种快捷行为同样只打开准备操作。触屏可使用菜单。
左键选择物品后仍须提交，不会因为误点卡片修改游戏。

收藏、皮肤选择和界面偏好只存于当前浏览器，最多各记500项，不改变服务端授权。
皮肤只有在游戏确认目标玩家拥有、且生成回执已确认后才记住；清空皮肤代码可恢复原皮肤。
制作分类来自已读取世界的配方事实，旧目录缺少这一信息时不推断该物品能制作。
地图选点携带存档标识；切换世界、地图来源不匹配或存档更换后重新选点。
每次选点生成／铺地是一批新的预览和确认，不授权无限连续写入。

### 发现与调用

顶层任务 MCP 不增加一批新工具。示例：

```json
{"query":"给玩家开启穿墙模式"}
```

`dst_find` 返回 `workbench.set_player_mode`，固定建议 `mode: "noclip"`，还需玩家和明确
的 `enabled`。开发者 API 的预览示例：

```json
{
  "path":{"roomId":"ROOM_FROM_LIST"},
  "body":{"commandId":"set_player_mode","worldId":"WORLD_FROM_LIST","arguments":{"player_id":"KU_EXAMPLE","mode":"noclip","enabled":true,"phase":"preview"}},
  "requestId":"mode-preview-example"
}
```

确认继续使用原 `preview_id` 和完全相同的参数，执行请求明确确认。请求绑定原调用身份、
世界、存档、玩家实例与原始对象，30秒过期且只能消费一次。不能伪造只读、内置或风险字段
跳过验证，也不能改自定义命令来扩展固定白名单。

只查询同类数量使用 `workbench.count_world_entities`，参数为 `prefab` 和
`include_inventory`。结果同时区分实体个数与堆叠总数。它仍位于管理工作台；向普通用户
开放读取请使用 `dst_world`／`api_queryRoomWorld` 的固定只读查询，不开放工作台执行入口。
数量公告是单独的写操作 `workbench.announce_entity_count`，需要预览确认。

### 模式和记忆

`set_player_mode` 支持 `invincible`、`super_god`、`creative`、`health_lock`、`one_hit`、
`invisible`、`water_walk`、`noclip`，均提供明确的开启／关闭。
`mode: "clear_all", enabled: false` 尝试解除该入口持有的全部模式。
必杀不作用于其他玩家；隐身以游戏目标标签和清除附近仇恨实现，不强改其他模组的显示状态。
恢复只撤销面板仍持有的设置；发现组件或方法已被其他来源接管时保留第三方设置并报告待核对。

`set_mode_memory` 默认关闭。开启后记录该玩家在本世界通过统一模式入口设置的模式，
玩家再次进入同一世界时按事件恢复；不会自动赋予原来未设置的模式，也不跨世界迁移记忆。
关闭清除该玩家记忆，当前模式通过模式开关另行解除。仅磁盘写入已确认后才报告记忆已生效；
损坏记录不覆盖，写入失败或还在写入时查询返回未确认。最多64名玩家、32 KiB。

`dst_world` 的 `player_modes` 结果可增加 `panelModes` 和 `modeMemory`。
八模式表中的 `enabled/disabled` 表示统一入口持有的模式；旧脚本缺少字段时不能当作关闭。
`invincible/creative` 等原字段仍描述原有观测，不合并成一个推测状态。

### 限制与结果

- 完整世界扫描最多50,000个实体；按4毫秒片段继续原迭代器，最多4秒。未扫完不生成可执行预览，也不返回数量0。
- 写入每批最多40个对象；阵列最多25个主体，地图生成最多20个；铺地最多5×5格，农田养分最多25格。
- 地皮物品单次20个。普通附近批量生成可选拥有的皮肤；不支持的预制物、森林／洞穴限制或落点检查失败均拒绝。
- 地图探索按需分帧处理，最大1024×1024格；修改是永久探索，不影响其他玩家。
- 多帧执行继续已消费的原批次。不会重做已尝试的生成；组件调用异常后的效果为待确认，不能据此自动重发。
- 迁移使用同一集群已连接分片的原生流程。源侧玩家消失不代表目标到达；没有到达证据保持待确认。
- 道路移除会保存并重载，玩家会断线；先备份。存档和重载会中断连接，结果不确定时先检查原任务和世界状态。
- 原生空间查询、预制物构造和模组组件调用是原子方法，不能被 Lua 预算中途抢占；预算约束片段间调度，不保证第三方方法的耗时。

提示方式分为面板详情、面板简要、面板消息、游戏内附近可见、游戏内全服公告、关闭额外提示。
后两种游戏消息仅随主动写操作发送；纯查询不会发送。关闭提示仍保留回执和审计。
所有回执仍区分已确认、部分执行、失败和不确定。`sent`、没有输出、只打印已提交均不是效果成功。
