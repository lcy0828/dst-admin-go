# 玩家活动记录

在 **玩家管理 → 玩家活动** 查看房间内所有玩家的记录。在玩家的操作菜单选择 **活动记录**，可以直接筛选该玩家；离线后仍可查询。无需配置 AI。

默认对所有玩家开启记录。运行节点需加载支持此功能的 DST Admin Runtime；远程世界还需配套 Agent。页面分别显示配置是否已保存、各世界是否已经应用，以及最近节点输出和同步时间。停止或离线世界的配置会在恢复连接、Runtime 运行后应用，不能把保存成功当成已开始采集。

## 记录范围

- 加入、离开、死亡、复活。
- 采样位置及动作发生时的位置；重复动作合并展示次数。
- 拾取、丢弃、采集、进食、制作、建造和完成工作。
- 主动攻击、受到攻击、击杀事件；按对象、世界和运行实例汇总。
- Boss 参与与击杀分别展示。只有游戏事件提供的已结算伤害才计入确认伤害；缺失伤害显示未知。

模组对象使用实际 Prefab，不依赖预置白名单。模组绕过游戏标准事件实现的自定义行为可能无法记录。功能启用前的行为、已过保留期的数据不能补录。对象 GUID 只用于同一运行实例内关联。

## 动态设置

在 **采集设置** 修改，运行世界无需重启。设置对房间内全部玩家生效。

| 设置 | 默认 | 范围 |
| --- | --- | --- |
| 位置采样间隔 | 15 秒 | 5–300 秒 |
| 最小移动距离 | 10 游戏单位 | 0–100 |
| 战斗合并窗口 | 10 秒 | 5–120 秒 |
| 动作合并与节点写入间隔 | 5 秒 | 2–30 秒 |
| 控制端同步间隔 | 10 秒 | 5–60 秒 |
| 保留时间 | 7 天 | 1–90 天 |
| 每房间记录预算 | 512 MiB | 16–2048 MiB |

可以分别关闭位置、交互动作、战斗，或关闭全员采集。生命周期记录随总开关控制。关闭后仍会同步关闭前已进入队列的数据。减少间隔会增加记录量；战斗窗口到期后的实际写入还受节点写入间隔影响。

位置只在达到采样间隔、且相对上一次位置发生足够移动时记录。动作合并窗口中的坐标和时间取最后一次动作，不是逐次动作的精确路线。轨迹按世界、运行实例和采集边界分段，不跨洞穴、重启或缺口连线；图示仅包含当前页的坐标，不是地图回放。缺口时间是发现缺口的时间，不能精确标定丢失时刻；本页有缺口的世界只显示点位，避免虚构连线。

## 开销与缺口

Runtime 使用游戏事件和在线玩家列表，不遍历全世界实体，不逐帧采样，不逐条写磁盘或请求网络。无人在线时停止玩家采样与心跳计时器；控制端对空闲、关闭或不可用世界降低查询频率。

其他玩家加入、离开不会重置已有玩家的采样节奏。Runtime 热更新会先批量写出待处理记录，再替换实例；写入失败或超时会延后更新，由原实例继续采集，不会为了更新强行清空队列。

每世界最多保留 512 条待写记录，每批最多 128 条、64 KiB；每玩家的动作分类和战斗对象分别最多 32 组。重要生命周期和击杀事件有队列预留，但极端高负载下仍可能丢失。节点最多循环保存 64 个数据段，控制端每次只取最多 8 个新段，最多同时同步 2 个世界。中断时间超过节点保留窗口，可能无法补齐。

丢弃数量、段序号缺口、运行实例切换会出现在采集状态和时间线中。没有记录不能证明玩家未做某事。进程异常退出也可能丢失尚未写出的队列；实例切换标记不是连续采集保证。

记录容量是 JSON 及记录开销的**逻辑预算**。后台分批清理，因此可能短时超出预算；SQLite 数据库文件可能保留可复用空页，文件大小不等于记录预算。清理只针对玩家活动表，绝不删除游戏存档、备份或其他业务记录。

## API、MCP 与导出

受现有管理员认证保护的 `/api/v2/rooms/{roomId}/player-activity/` 提供 `settings`、`status`、`events`、`trajectory`、`combat`。GET 只查询已保存证据，不触发游戏命令或现场实体扫描。设置写入需要最新 `revision`，冲突返回 409。

MCP 与 AI 助手使用相同 OpenAPI 能力。可询问玩家最近做了什么、去了哪里、参与哪些战斗，或调整采样间隔。AI 无法重建不存在的历史。页面导出只包含当前页 / 当前汇总，避免误认为是全部历史。
