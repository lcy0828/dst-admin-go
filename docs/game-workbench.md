# 游戏工作台

[English](game-workbench.en.md)

在玩家操作中按 **T** 或打开游戏工作台，可管理这个玩家所在的房间和世界。独立的「游戏工具」页面可以切换执行目标。

## 查找资源

实体区域默认显示 **全部**。按材料物品、食物、工具装备、建筑、生物、Boss、自然环境和其他分类；搜索支持中文名、英文名、Prefab 和模组名称。搜索、分类和翻页都在完整目录上进行，不会只排序当前一页。

- 默认 **常用优先**：成功执行的实体操作、搜索后选择的资源和内置常用推荐共同排序，近期记录权重更高。搜索时精确名称/Prefab 优先于使用频次；也可切换最近使用、名称排序。
- 常用记录仅保存在当前浏览器，最多 200 项，90 天后过期；不保存搜索词。失败、取消及结果未确认的操作不算成功使用。展开「更多选项」可清除记录，恢复推荐顺序。
- 原版文字目录已内置，共 6,121 项，来自 DST 747465，无需图片包或运行世界即可浏览。打开实体区时，自动补充所选运行世界注册的原版与模组实体；按 Prefab 去重，同名模组覆盖保留其实际归属，不借用原版分类或图片。
- 未知类别放在「其他」，仍包含在「全部」中。游戏内部实体也会保留，常用资源优先展示。分类只是浏览用途，不代表实体一定可以给予玩家。
- 「更多选项」中可按原版、全部模组或指定模组筛选，并刷新世界目录。输入目录未收录的有效 Prefab，可直接选择后继续给予、生成、清理、操作附近或查找传送。

世界目录只在打开实体区或主动刷新时读取，不在后台轮询，不生成实体、不调用实体构造函数、不修改存档。首次完整读取使用内部批次，每批最多 2,048 项且实体 JSON 不超过 128 KiB；页面先显示原版资源；后续搜索、排序和翻页不调用游戏。管理服务合并同一世界的并发读取，最多同时收集两个世界、缓存两份目录，每份缓存 5 分钟；页面保留实际读取时间。读取期间显示「正在读取」，短暂失败时最多自动重试两次；仍失败会直接显示「重新读取」按钮。世界停止、尚未选定与读取失败分别提示，不会混为「未读取」。手动刷新失败时保留当前世界上次完整目录，并标明其可能已过期。切换世界或关闭工作台取消未完成请求，读取不完整或世界不可达时显示提示，不把残缺数据当作完整目录。

游戏侧每批以约 3 毫秒为调度目标，并在批次之间让出游戏帧，空服暂停时也可采集。首次索引构建上限 10 秒；跨页完整读取上限 30 秒、50,000 项、8 MiB 元数据。超过预算可重试或直接输入 Prefab。缓存不会自动随新装模组刷新，更新模组并重启后可主动刷新目录。

世界需要运行，且 DST Admin Runtime 至少为 **2.4.8**；已有世界可通过 Runtime 管理安装更新后重载组件。远程世界需先将 Agent 更新到包含该 Runtime 的版本。读取失败会显示原因，不会回退到其他机器。

模组来源来自游戏已加载的注册信息。名称使用游戏加载的语言；模组未提供名称时显示 Prefab。只提供贴图或改变已有功能的模组不一定新增实体。目录不会凭注册信息声称某个实体一定可放入背包；给予时由实际组件验证。模组专有技能没有统一接口，可在「Lua / 命令」中添加。

实体图片优先使用已安装的原版图片包，再复用随面板打包的原版图库，其余按需从所选运行节点的游戏或模组图集读取。模组同名实体不会使用原版图片包。图片使用懒加载；节点图集索引和缩略图最多缓存 5 分钟，闲置后释放，单次只解码一张图集，缩略图缓存最多 8 MiB。图片读取不向游戏发送命令，不扫描存档，也不依赖外部图片网站。远程节点需更新 Agent，使其支持 `runtime.entity-artwork.v1`。

支持原版物品栏及小地图图集，以及模组 `images` / `minimap` 目录中具有同名 `<Prefab>.tex` 或 `<Prefab>.png` 元素的 XML/KTEX 图集。模组同名实体不会借用原版图片。无图特效、动态别名、仅有动画、缺失贴图、超过读取上限的图集显示占位图；这不影响实体操作。为限制资源占用，图集最大 2048×2048，单个模组最多读取 512 个 XML 图集、扫描 8192 个目录项。

## 可选图片资源包

在实体目录旁打开 **图片资源包**，选择「下载安装」，也可导入已下载的官方 `.tar.gz` 文件。国内默认使用 ghfast.top 代理，可切换 GitHub；安装页面显示下载进度、速度、资源版本和占用空间。下载失败时可切换来源重试或离线导入。

当前包来自 **DST 747465**，包含 **6,121 条实体目录、2,441 个实体的图片**，去重后为 2,414 张 WebP。安装约 **11.3 MiB**，下载约 **10.8 MiB**；其中官方图鉴 1,883 项均有图片，不代表全部注册实体与模组均有图。图像和游戏数据原始出处为 [Klei Entertainment《饥荒联机版》](https://www.klei.com/games/dont-starve-together)。

图片包是管理服务的显示资源，所有本机和 Agent 房间共用一份，不分发到游戏节点。文件保存在管理服务 `app.conf` 同级的 `resource-packs/entity-artwork/` 内；容器部署随管理配置目录持久化。二进制和镜像不捆绑这份可选包。

安装、更新和卸载立即生效，无需重启管理服务或游戏。卸载只删除该图片包，恢复原有图片来源，不修改游戏、模组或存档。资源包只有用户主动操作时才下载；下载与离线导入都检查固定 SHA-256、解包路径、文件类型和体积，失败时保留原有版本。当前支持导入面板列出的官方版本；新增受信版本随管理服务更新。

## Lua 与命令库

「Lua / 命令」提供全部已有命令和自定义命令。带参数的命令会显示对应表单；也可以新建纯 Lua、直接执行或保存到服务端命令库，供其他浏览器与「命令设置」复用。保存不会执行代码。

内置示例包括世界信息、已加载模组、玩家组件和给予物品。可以插入当前玩家的 `player` 变量；插入的是明确的 KU ID，保存后的代码不会自动换成另一个玩家。

执行前会显示房间与世界并要求确认；修改代码、参数或执行目标会取消先前确认。使用已有的管理员验证、操作记录和 DST 执行回执，未知结果不会自动重放。工作台直接显示每次执行对应的同步 `print` 输出、状态与错误，并可查看最近 10 条执行记录和当时执行的代码。输出随执行 ID 保存，单次最多 16 KiB，超出时明确提示截断；执行失败仍保留报错前的输出。原始输出同时保留在世界日志中。此功能需要游戏内 Runtime **2.4.10**；旧 Runtime 或未收到回执时会提示输出不可用，不会把它显示成“没有输出”。定时任务、延迟回调和提前缓存的其他打印函数不在本次同步采集范围内，其输出仍需查看日志。

代码运行于 DST **服务端 Lua 环境**，可以调用当前世界已加载的模组接口。客户端 UI、鼠标选中对象或仅客户端存在的函数不能直接当作服务端接口调用。一次脚本最多 4096 个 UTF-8 字节。代码在游戏主线程执行；死循环、大范围扫描或大量生成实体可能卡住游戏。请求超时只代表控制端不再等待，不能终止已经执行的 Lua；耗时操作应分批并通过游戏任务调度执行。

新建纯 Lua 使用 `scriptMode: literal`，保留 Lua 表和字符串中的花括号；已有参数命令保持 `template` 模式及原有参数定义。命令导入、导出会保留此模式。
