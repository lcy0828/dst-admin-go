# Workshop 资料与更新检查

模组的名称、作者、介绍保存在现有 SQLite 的 `workshop_metadata` 表中（表名带配置的前缀），每个 Workshop ID、语言只保留一条最新记录。Controller 重启后继续使用；不保存房间配置，也不代替运行机器上的 `modinfo.lua`、`modoverrides.lua` 和 Steam ACF。

- 房间列表复用已有名称、作者，只补缺失项。打开详情时，超过 7 天的工坊页面资料才重新获取。
- 搜索结果中已有的名称、作者直接复用，不再逐个打开搜索结果的工坊详情页面。
- 页面附带的 Steam API 版本信息最多复用 5 分钟，与名称、作者的保存时间独立。API 查询失败时保留展示资料，但不拿旧版本信息判断“最新”。
- 手动和定时更新检查始终直接请求 Steam 批量版本接口，按房间已启用模组，与每台实际运行机器的磁盘文件比较。优先比较 Steam manifest，其次更新时间、版本号；版本号相同、manifest 改变仍提示更新。
- Steam 返回缺项、查询失败或机器版本不可读，均表示检查未完成。保留之前已知更新及本次确认的更新，不推进“最近成功检查”时间，也不进入自动下载或重启流程。
- 工坊 HTML 请求使用正常的 HTML Accept 头、最多两个并发。识别 HTTP 429 和 HTTP 200 内的限流提示，遵守 Retry-After（无该字段时暂停一分钟），取消立即重试。单项失败或作者缺失也短暂退避一分钟。此退避只影响网页资料，版本 API 仍可检查；若版本 API 本身失败，明确报错。
- 更新策略沿用现有调度器及用户保存的模式。新策略的候选间隔为 5 分钟，“仅提醒”也可选间隔；默认仍为手动，不自动改成无人重启模式。页面关闭不影响用户已经启用的定时检查。

这些改动不增加全库扫描、额外下载任务或世界启动检查。

## 房间模组更新与重启

“更新并重启世界”和无人自动更新共用运行节点直接下载接口，与单个机器模组更新一致。按照世界实际位置合并下载：同一安装实例只下载一次，分散在不同机器时各自下载其世界已启用的模组。远程房间不依赖 Controller 的模组目录，不重新发布房间、世界或模组配置。

所有节点下载成功后才进入现有世界重启流程；已停止的世界保持停止。下载失败显示运行目标、Workshop ID 和原始错误，结束任务，不触发重启。多节点部分成功不会回滚已下载文件，重试时依据各节点当前磁盘版本继续。

无人自动更新继续遵守玩家状态和无人宽限设置。使用现有持久化更新时间记录待重启操作，避免节点磁盘更新后下一次检查将其误清除。等待期间出现新版本时先下载，再重新确认无人宽限；重启失败可在保留已下载内容的基础上重试。旧版仅准备 Controller 发布计划的记录必须重新检查运行节点。
