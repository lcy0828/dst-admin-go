# 保存地点与玩家传送

在游戏工作台选择房间和世界，打开“地点”。可以保存在线玩家当前的位置，也可以输入 X/Z 坐标；已有地图支持点击选点后保存。地点仅属于一个世界，普通重启后仍保留。跨世界传送暂不支持。

选择玩家和地点后，点击“传送前检查”。面板显示实际落点，60 秒内点击“传送”即可确认；这一步就是最终确认。原坐标不能落脚时，检查最多尝试半径 6 内的 24 个候选，不会在确认后换到另一个落点。有效地面不代表附近没有怪物或模组伤害。

玩家需要在线并处于同一世界；船上、骑乘、幽灵、切换世界及未支持的变身状态会拒绝传送。不会自动下船、复活、开无敌或改变碰撞。

在地图上先点“在地图上保存地点”，再点选位置；普通浏览地图不会弹出保存框。地点列表显示来源与采集时间。返回工作台时，同一浏览器标签页会找回最近一次传送结果；结果仍需通过服务器核验。

## 地点与存档

- 每个世界最多 100 个地点，一页 50 个。名称最多 48 个字，同一世界不允许重复名称。
- 地点保存在面板数据库中，随面板数据备份。游戏存档备份不包含面板地点数据库。
- 改名不改变准备好的落点；修改坐标、删除地点、世界实例变化会使旧确认失效。
- 地点属于之前的游戏世界时需要重新保存；恢复相同世界的旧存档后，会提示核对基地等建筑是否仍存在，再检查落点。
- 地图是存档快照，选点不会生成新地图，也不会把地图图片当成实时地形。
- 外部手工替换同一 Session 的存档不保证能完整识别；每次传送仍检查游戏中的实际落点。

## AstrBot

使用官方伴随插件 v0.4.3 或更新版本的“面板地址 + 接入密钥”私有连接，配合面板 v1.3.25 或更新版本，在已启用的群中可说：

```text
有哪些地点
把玩家甲当前位置记为基地
把玩家甲传送到基地
确认
```

前三条明确指令直接调用面板，不需要模型。复杂问题可以直接 @机器人。玩家重名或世界不一致时需要补充选择，不会猜测身份。“我”和“这里”不能替代尚未绑定的游戏玩家身份。

机器人确认绑定群、用户及短时表单。可以裸回复“确认／取消”，也可以 @机器人或引用对应确认消息。其他人、错误引用、过期确认和被新请求替换的确认不能提交。网络超时后发送“任务进度”查询原结果；不会自动重新传送。

仅具有游戏管理授权并获得 `player.teleport` / `location.save` 授权，或被允许使用常用工作台操作的用户可操作。普通群成员不会因目录增加能力自动获得写权限。现有群权限可单独调整。

查看已保存地点沿用群内“房间概况”的查询开关，无需开启实时世界查询。关闭该查询类别或单独禁用 `room.locations` 后仍不能查看。搜索“有哪些地点”“保存地点”“传送到基地”会返回相应能力；查找本身不会执行传送。

旧插件仍可查询旧能力。完整地点确认交互需要更新插件；只更新面板不会使旧插件下载或执行新的客户端代码。仅使用通用 MCP 连接的客户端可预检，最终确认请在面板或新版插件私有连接中完成。

## API 与 MCP

OpenAPI 是参数契约；原生 MCP 按同一契约生成。任务 MCP 继续保持九个工具，使用 `dst_find` 查找 `room.locations`、`location.save`、`player.teleport`，分别通过 `dst_read` 或 `dst_run` 调用。

| 原生工具 | 用途 | 权限 |
| --- | --- | --- |
| `api_listRoomLocations` / `api_getRoomLocation` | 列表、详情 | 房间读取 |
| `api_createRoomLocation` | 保存玩家位置或坐标 | 游戏管理 |
| `api_updateRoomLocation` / `api_deleteRoomLocation` | 修改、删除，需 revision | 游戏管理 |
| `api_prepareRoomTeleport` | 实时预检 | 游戏管理 |
| `api_getRoomTeleportPreview` | 查询原预检或执行结果 | 原主体、当前房间权限 |
| `api_executeRoomTeleport` | 消费一次预览 | 可信程序／面板用户确认 |
| `api_cancelRoomTeleport` | 取消尚未派发的预览 | 原主体、游戏管理 |

示例均为虚构标识，请使用列表实际返回的 ID。先保存玩家当前位置：

```json
{
  "path": {"roomId": "ROOM_FROM_LIST"},
  "body": {"name": "基地", "playerId": "KU_EXAMPLE"},
  "requestId": "save-location-example-01"
}
```

使用 `api_prepareRoomTeleport`：

```json
{
  "path": {"roomId": "ROOM_FROM_LIST"},
  "body": {"playerId": "KU_EXAMPLE", "locationName": "基地"},
  "requestId": "prepare-teleport-example-01"
}
```

预检返回 `id`、`playerId`、`worldId`、`locationName`、`x`、`z`、`state`、`expiresAt`、`serverTime`。客户端按服务端剩余时长倒计时，不从模型开始思考时计时。可信客户端通过 `POST /api/v2/rooms/{roomId}/teleport-previews/{id}/execute` 提交空对象 `{}`，使用新的 `Idempotency-Key`。不能提交 Lua、函数名、来源证明或 `confirmed` 标记。

`GET /api/v2/rooms/{roomId}/teleport-previews/{id}?refresh=true` 只补读原回执。状态含义：

| state | 含义 |
| --- | --- |
| prepared | 检查通过，尚未传送 |
| dispatching | 请求正在处理 |
| confirmed | 同次执行回执确认了移动前后坐标 |
| rejected | 已确认未移动 |
| uncertain | 缺少效果证据或移动结果未确认 |
| cancelled | 派发前取消 |
| expired | 预览过期，不能执行 |

HTTP 成功、发送成功或一条普通输出不代表传送成功。取消与提交原子竞争；已经派发时取消不能声称“未执行”。原结果不确定时不重放；原执行许可到期且重新取得实时状态后，才能开始新的移动操作。

MCP 与面板内置模型调用在后端标记为模型通道，不能调用确认接口或通过旧传送／任意 Lua 接口代替人工确认。可信插件的主密钥仅由私有传输持有，不注入模型工具参数；确认发生在群用户消息处理器。直接持有管理员密钥的程序仍属于可信管理程序，应自行保护密钥，不把它交给模型作为自由 HTTP 请求凭据。

## 兼容与资源限制

本功能需要 Runtime 2.4.22。旧节点不支持时应升级节点，不降级执行无检查 Lua。原有玩家到玩家、召回、召集、互换及最近实体接口保留参数，使用同一落点检查。批量移动可能部分完成，不能保证整组原子执行或回滚；最近实体遍历超过 4096 个实体或 4 毫秒预算时拒绝移动，不把不完整搜索说成全世界最近。

当前面板和官方插件对这些旧传送操作也会先检查，固定这次的玩家集合与落点，再要求一次确认。检查后新进入的玩家不加入召集，目标位置不会随玩家走动而改变；落点出现障碍、玩家实例变化或检查过期时拒绝执行。每次最多 40 名玩家，结果中的 `movement.items` 分别记录已确认、未执行或结果不确定。

可信程序调用原有固定命令时，可使用新增的可选参数 `phase: "preview"` 获取 `movement.previewId`、`expiresAt` 和逐玩家落点；保持原参数，加上 `phase: "execute"` 与 `preview_id` 消费该检查，或使用 `phase: "cancel"` 取消。检查有效期为 60 秒，不接受任意脚本。省略 `phase` 的既有可信程序仍按原确认约定执行，并使用统一落点检查；MCP 模型通道不能利用这个旧入口跳过人工确认。使用私有连接的新版插件负责识别真实用户确认，再走固定管理 API。

没有新增闲置轮询或地图生成。控制端最多两个实际预检并发，每世界 10 秒最多四次、同一接入身份两秒最多两次；每世界最多 16 个有效预览。地点列表读取不占预检预算。同步游戏引擎或模组函数不能被协作式 Lua 时间预算强制中断。

自动化测试覆盖预览无写入、重复确认、取消竞争、权限与错误引用、名称与配额、落点及玩家状态变化、效果不确定、地图坐标转换和旧入口参数。测试使用虚构数据及模拟 Runtime；真实 DST、远程 Agent、QQ 群与 2C4G 性能仍需隔离环境验收，不能以这些测试代替实际运行证据。
