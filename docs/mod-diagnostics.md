# 游戏与模组分析

游戏更新后出现报错、启动未完成或世界意外退出时，可以在 **房间诊断 → 模组与版本** 选择对应世界。服务总览中的异常世界也提供“分析日志与模组”入口。打开该页会读取证据并生成报告，无需配置 AI，也无需游戏内的 DST Admin Lua 采集模块正常运行。

## 报告能看到什么

- 对应运行节点实际安装的游戏版本、Steam Build、模组作者版本与 Manifest，以及启用模组的文件状态。Steam Build 与游戏版本分别展示，不混用。
- 作者在 `modinfo.lua` 中声明的 `dst_compatible` 和 `api_version`。没有声明、解析受限或旧 Agent 未返回时显示未知。
- 已有依赖元数据中涉及的未启用模组。依赖可能是可选项，声明也可能不完整，需要结合作者说明核实。
- 当前日志中最早可见的错误及相邻堆栈，列出其中涉及的 Workshop 或本地模组。**堆栈引用只能提供排查线索，不能证明某个模组是原因。**
- 与最近一次游戏更新执行前保存的摘要比较：相同 AppID 下的游戏版本与 Build、模组版本/Manifest、启用清单、配置摘要。摘要不保存配置正文，也不代表那时已经验证兼容。

日志早于最近一次启动时，不用于解释本次启动。缺少启动关联、日志不可读或只读到尾部时，报告会明确标注。版本与模组来自当前文件观察，不会冒充报错时的进程快照。

## 游戏更新前的提示

游戏更新预检和更新/校验确认页面会展示“模组与版本提示”。这些提示不参与更新阻塞判断，也不保证模组支持目标游戏版本。实际更新开始写入游戏文件前，面板自动保存一次观察摘要；同一更新的重试不会覆盖它。摘要保存失败会在更新详情提示，原有备份保护流程保持有效。

分析不会禁用模组、改写配置、操作存档、发送 Lua 命令或启动/停止世界。需要复现冲突时，应在独立测试环境处理。

## 性能与证据范围

分析按需执行，没有新增后台扫描或轮询。分析服务最多同时进行 2 组读取，相同世界的并发分析会合并；单组读取最多 20 秒。预检按房间复用模组事实，不额外扫描模组源码或查询 Steam 最新元数据。

每次最多分析 512 个启用模组、1000 行日志，最多展示 4 段错误上下文、每段 40 行。更新范围超过 128 个世界时，超出部分不分析并显示范围限制。每个世界保留最近 5 份更新前摘要，写入新摘要时清理更早记录。这些限制都会在不完整报告中体现；没有发现问题不等于证明兼容。

可以在页面**导出报告**。文件不包含存档或配置正文，日志会遮盖常见凭据和标识；日志仍可能包含模组输出的其他敏感内容，分享前请检查。

## AI / MCP / OpenAPI

页面与外部 AI 使用同一分析接口：

```http
GET /api/v2/rooms/{roomId}/worlds/{worldId}/mod-diagnostics
```

OpenAPI operationId 为 `analyzeWorldModCompatibility`，可通过 MCP 的能力发现搜索“模组冲突”“游戏更新后启动失败”等词调用。关注 `findings[].kind`、`logCorrelation`、`limitations` 与 `evidence`；不可把缺失观察解释为没有模组，也不可把 `suspected` 写成已确认原因。
