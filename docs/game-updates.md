# 游戏更新与失败恢复

在“游戏服务端管理”检查版本不会停服。确认更新后，面板按实际安装范围停止相关世界、创建并验证保护备份，执行 SteamCMD 更新和文件校验，然后恢复更新前运行的世界。共用安装和跨节点房间纳入同一维护范围。

## 版本信息与更新确认

头部版本入口与游戏服务端管理页共享当前安装和官方版本信息。发现官方新版仅表示值得检查，不保证当前操作系统及 Steam 分支已可更新。页面刷新失败会保留上次信息并显示错误；修改高级选项不会清空已知版本。

点击“更新游戏”会立即打开确认窗口，自动检查实际安装、Steam 目标 Build、磁盘和世界运行状态。检查不会停服。窗口列出共用安装、跨节点房间及每个世界的恢复方式；确认后才提交任务。检查期间关闭窗口不会提交更新。执行计划变化需重新核对并确认。

模组诊断按需读取；明确的问题与其余检查详情分别展示。预检参数 `includeModDiagnostics: false` 只跳过可选诊断扫描，不跳过任何执行条件，也不取消更新前保存版本及配置摘要。此摘要供故障排查，不代表兼容认证。

已有更新任务或待恢复记录时，入口改为查看进度或处理原任务。查询 `GET /api/v2/game/releases?pending=true` 可读取未结束的维护记录，不受最近历史记录数量影响。提交响应丢失时显示结果待确认，只读取任务状态，不自动重发更新请求；安装校验和世界恢复均得到确认后才算完成。

## SteamCMD 校验失败

本机和 Agent 的更新、重试均固定执行 `app_update 343050 validate`。安装日志记录应用 ID、是否校验和尝试次数，不记录登录凭据。

如果 SteamCMD 已退出并明确返回该应用的文件损坏状态（例如 `0x486`），同一次受安装锁保护的操作最多追加一次校验。不会删除安装清单或存档，也不会无限重试。连接中断、超时、登录失败或回执不确定不会触发此自动重试。

Steam Build 相同并不代表安装完整。清单明确提供 `StateFlags` 时，只有完整安装状态 `4` 才可通过验证。校验仍失败时查看安装日志，处理网络、权限或磁盘问题后，在原更新任务继续恢复；不要直接删除数据库中的维护记录。

## LuaJIT 与原版运行时

显式游戏更新会在校验前暂时还原已识别的官方可执行入口，让 SteamCMD 校验和修补原版文件，更新后再恢复 LuaJIT 启动入口，也支持修复此前被手动 Steam 更新覆盖、其余组件完整的入口。不会在普通开服时安装或修复组件。

官方游戏安装完整、但可选加速组件修复失败时，两者的结果分别记录。自动恢复遇到明确的加速模式不可用错误，会再次确认该世界没有进程或会话，再使用原版运行时启动。页面和 MCP 返回 `warningCode: RUNTIME_FALLBACK_GAME` 与实际 `runtimeMode: game`，原计划的运行时偏好保留。启动回执不明确、进程已存在或其他启动错误不会触发此降级。

## 结束维护而不继续启动

如果安装全部已验证，但自动恢复仍受阻，任务详情提供“结束维护，保持当前状态”。此操作重新检查目标 Build、安装完整性和所有世界的当前状态，保留已运行的世界和已停止的世界，不启动、停止或回退游戏。结束后的任务阶段为 `abandoned`，表示放弃剩余自动恢复，并不表示所有世界已恢复成功。之后可修复加速组件或手动启动。

安装写入失败、结果未知、目标版本不符、节点离线或世界状态不明确时，操作会被拒绝，维护保护继续生效。应先在原任务校验修复。保护备份和原任务记录会保留。

MCP 使用已有 `api_retryGameRelease`，参数示例：

```json
{
  "path": { "releaseId": "原更新任务的 ID" },
  "body": {
    "finishWithoutRestart": true,
    "planHash": "从原任务 plan.planHash 读取的 64 位哈希",
    "confirmation": "同一个原计划哈希"
  },
  "requestId": "finish-verified-maintenance-001"
}
```

返回新的 Job ID，用 `api_getJob` 查询；继续用原 Release ID 调用 `api_getGameRelease`。不要将 Job ID 与 Release ID 混用。

本机和 Agent 共用更新校验逻辑；远程目标需要升级 Agent 才能获得新的损坏状态修复和安装状态检查。

## 统一任务展示与停止面板下载

游戏更新、模组更新及世界重启共用页面右下角任务区，可切换、收起并重新展开。
游戏更新使用原维护记录展示停止、保护备份、更新校验、恢复与加载确认阶段，
不会用步骤百分比估算 SteamCMD 下载进度。当前重试任务关联原维护记录，
原发布身份仍保留。离开管理页后，有进行中的任务才继续限频读取进度；空闲时不轮询。

面板自身更新也进入同一任务区，下载时显示实际字节和速度。
在下载、校验或已准备阶段可点击“停止下载”，持久化取消原操作并撤销自动应用意图。
停止完成后，可修改下载源或代理设置，再主动发起下载；保留的部分文件仍需校验，
不会跳过包校验直接安装。已提交的程序切换阶段无法取消，继续观察启动验证或回滚结果。
停止面板下载不停止游戏世界。

对应管理 MCP/API 为 `cancelSoftwareDownload`（MCP 工具
`api_cancelSoftwareDownload`），只接受原操作 ID：

```json
{"body":{"operationId":"0123456789abcdef0123456789abcdef"},"requestId":"example-cancel-001"}
```

旧操作 ID 不能停止新下载；重复读取旧进度不能让已取消的操作重新变为待应用。
取消请求响应不确定时不自动重发，也不自动应用，应回读软件更新状态。
