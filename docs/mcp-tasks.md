# 任务型 MCP 与 AstrBot 群权限

新建外部 AI 连接推荐使用 `https://面板地址/mcp?view=tasks`。按密钥权限显示最多 9 个任务工具，普通游戏查询密钥只显示 6 个读取入口。既有 `/mcp`、`view=compact`、`view=all`、`view=bot`、`view=legacy` 和 `pagination=off` 保持兼容。

OpenAPI 仍提供完整开发接口。任务工具复用服务端固定能力注册表、API 鉴权和 Room/Runtime 执行；描述、搜索词、模型输出均不能改变操作权限或注册 Lua。

## 外部 MCP 工具

| 工具 | 用途 |
| --- | --- |
| `dst_servers` | 房间列表，指定房间查看概况、玩家、模组、性能 |
| `dst_player` | 玩家资料、背包、网络档位、活动、轨迹、战斗 |
| `dst_world` | 指定世界信息、玩家、实体计数、玩家模式状态 |
| `dst_find` | 根据中文需求寻找最多 3 个已授权能力，返回参数结构 |
| `dst_read` | 执行已发现的固定只读能力 |
| `dst_result` | 回读原任务，绝不重新提交 |
| `dst_player_action` | 准备无敌/制作模式、复活、发物品、生成白名单生物、踢人、封禁/解封、提醒、死亡或重选角色 |
| `dst_server_action` | 准备房间启停、保存、备份、定时备份设置 |
| `dst_run` | 准备扩展管理能力，或提交原准备任务 |

示例数据均为虚构。先用 `dst_servers {}` 获取当前授权房间；房间可填写返回的真实 ID 或完整名称，不按排序猜测“一服”。重名玩家、重名房间或多个同类世界会返回选择项。

查询背包，一次工具调用即可完成目标解析和读取：

```json
{"room":"示例房间","player":"示例玩家","view":"inventory"}
```

查询地面蜘蛛巢数量：调用 `dst_world`：

```json
{"room":"示例房间","world":"地面","view":"entity_count","parameters":{"prefab":"spiderden"}}
```

查找扩展能力：调用 `dst_find {"query":"定时备份"}`，再按返回结构填写 `parameters` 对象。不能传 JSON 字符串、Lua、函数名、伪造只读标记或自定义操作映射。

管理采用准备与提交两个内部步骤，避免客户端重试造成重复发物品：

```json
{"room":"示例房间","player":"示例玩家","action":"give_item","parameters":{"item":"肉丸","count":3}}
```

上例传给 `dst_player_action`，返回 `state=prepared` 和 `taskRef`；此时尚未修改游戏。随后调用 `dst_run`：

```json
{"mode":"execute","taskRef":"00000000-0000-4000-8000-000000000001"}
```

提交时不能再附加或替换玩家、数量、房间。重复提交同一 `taskRef` 返回原任务。结果不确定时只用 `dst_result {"taskRef":"原任务编号"}`，不能重新准备并重发。准备有效期为 5 分钟；读取记录按容量和时间淘汰，写任务句柄保留最多 30 天。过期或删除的句柄不能重新执行；底层写入去重记录不会随读取记录一起删除。

`state` 区分待补充、准备、处理中、成功、部分结果、失败和不确定；`result` 保留来源、观测时间、完整性及执行证据。`sent` 不等于成功，无输出不等于零。复活等工作台指令的执行回执不一定证明游戏效果，仍需读取当前状态。网络 `netScore` / `performance` 是原始档位，不换算成毫秒。

### 玩家管理权限与模式开关（面板 v1.3.22 起）

“无敌模式”和“上帝模式”是同一操作；“制作模式”“制造模式”“创造模式”和“自由建造”指同一制作开关。它们属于**游戏管理**，不需要授予面板管理权限。

| 能力 | `dst_player_action.action` | 原生 MCP 工具 | 必填参数（除玩家外） |
| --- | --- | --- | --- |
| 无敌 / 上帝模式 | `god_mode` | `api_setRoomPlayerGodMode` | `enabled`，布尔值 |
| 制作 / 创造模式 | `creative_mode` | `api_setRoomPlayerCreativeMode` | `enabled`，布尔值 |
| 所在世界广播提醒 | `announce` | `api_announceToRoomPlayer` | `message`，1–300 字符；不是私聊 |
| 封禁玩家 | `ban` | `api_banRoomPlayer` | `confirmation` 完整房间名称、`reason`、`duration` |
| 解除封禁 | `unban` | `api_unbanRoomPlayer` | `confirmation` 完整房间名称 |
| 使玩家死亡 | `kill` | `api_killRoomPlayer` | `confirmed: true`，仅在用户明确确认后填写 |
| 重选角色 | `reset_character` | `api_resetRoomPlayerCharacter` | `confirmed: true`，会影响玩家角色和进度 |

任务入口会解析昵称并在角色操作中生成目标玩家 ID 的原接口确认值；直接调用原生 API 时仍按该 API 的 schema 填写 `confirmation`。封禁时长支持 `1h/6h/12h/1d/3d/7d/30d/permanent`。无敌和制作模式必须明确开启或关闭，缺少 `enabled` 会要求补充，不会猜测。大多数角色操作要求玩家在线；未指定世界时由已有玩家执行器定位并检查当前分片，本机与 Agent 使用相同路径。

例如向外部 MCP 的 `dst_player_action` 提交：

```json
{"room":"示例房间","player":"示例玩家","action":"god_mode","parameters":{"enabled":false}}
```

返回示意（任务编号以实际返回为准）：

```json
{"state":"prepared","taskRef":"00000000-0000-4000-8000-000000000001","capabilityId":"player.god_mode"}
```

此时尚未执行；按前述 `dst_run` 提交并用 `dst_result` 回读。排队或结果不确定时不能宣称游戏效果成功，也不能新建任务重发。

本次一并补齐复活独立 API 的游戏管理权限；既有 `player.resurrect` 工作台能力的参数与回执不变。游戏管理员可以读取玩家详情、刷新玩家状态及查看房间备份列表。只读密钥继续使用公开玩家列表/固定查询，不能查看包含封禁原因的玩家管理详情，也不能调用这些修改操作。所有入口仍限制在密钥授权的房间。

通用 Lua、自定义指令、修改管理员名单、读取集群令牌、删除房间、拓扑迁移及影响共享安装的更新仍属于面板管理；不能仅凭 API 的“玩家/房间”标签扩大权限。精简视图不逐一列出所有原生工具，可用 `find_api` + `call_api`；任务视图用 `dst_find`。修改连接权限或升级后，让 MCP 客户端重新加载工具目录。

AstrBot v0.4.1 的玩家工具与群权限命令支持上述操作名称。**已有群授权不会自动扩大**：维护者先在全局 `group_permissions.owner.write`（群角色模式）或 `writeAllowlist`（旧模式）加入所需能力 ID，例如 `player.god_mode`、`player.creative_mode`，保留原有条目；群主随后可用 `/dst 权限 管理员 无敌模式 开`、`/dst 权限 管理员 制作模式 开` 在该上限内授权。普通成员与禁用项继续受限制，模型提出的修改仍等待用户确认。

只更新面板、仍使用插件 v0.4.0 时，已明确授权的新能力可从目录被发现，通过通用 `dst_run` 按能力 ID 调用；新的专用 `action` 枚举和中文群设置别名需要插件 v0.4.1。无需开放通用 Lua 作为替代。

回归覆盖真实 MCP `tools/list`、`find_api`、原生工具与分发器、REST 权限、模式开/关、遗漏参数、伪造字段、跨房间、任务去重、群授权与撤销。测试使用合成玩家和执行替身，不对实际世界修改模式。

对应 HTTP 契约：

- `GET /api/v2/bot/protocol`
- `POST /api/v2/bot/tasks/queries/{tool}`
- `POST /api/v2/bot/tasks/preparations/{tool}`
- `POST /api/v2/bot/tasks/{taskRef}/execute`
- `GET /api/v2/bot/tasks/{taskRef}`

准备及查询不产生游戏写入；执行入口仍检查当前密钥、房间、能力与参数版本。每实例最多并发处理 2 个任务入口，单请求最多 30 秒；底层固定查询继续执行自身限频、扫描和输出限制。

## AstrBot：一条连接，按真实群身份授权

插件 v0.4.0 在原快捷指令、菜单、引用识别和播报基础上，增加私有面板连接与群角色模式。

1. 维护者在插件配置填写 `panel_url` 和 `panel_token`，使用完整面板权限密钥。此连接由插件内部使用，不注册成模型可直接调用的底层工具。不要把密钥发到群里。
2. 保留原群、房间、模板和播报配置；由维护者在目标群启用并分配房间。
3. 维护者发送 `/dst 权限模式 群角色`，或在配置选择 `permission_mode=group`。已有部署默认保留 `legacy`，升级本身不扩大群权限。
4. `/dst 权限` 显示当前识别身份与开放操作。群主可发送 `/dst 权限 管理员 重启房间 开`，但只能在维护者全局上限内配置本群。

默认混合模式下，`/dst 需求` 或 `@机器人 需求` 会先尝试快捷操作，未识别的表达自动进入 AstrBot 的 AI 对话，无需添加 `AI:`。旧口令保持兼容，但不是提问条件；显式选择 `shortcut` 的部署保留仅快捷指令的行为。已识别设置的参数错误会直接说明原因，不会交给模型假装保存成功。

群主或维护者可直接说 `/dst 给管理员添加所有权限`，也可 `@机器人 给管理员添加所有权限`，等同于 `/dst 权限 管理员 全部 开`。这会开放本群在维护者上限内的查询、管理和工作台权限；全局禁用项仍生效，不开放其他群、面板连接或插件维护权限。`/dst 权限 管理员 全部 关` 会关闭该身份的本群查询与管理。询问“这样是否合适”等讨论进入 AI，不直接变更权限。

| 身份 | 初始权限 |
| --- | --- |
| 普通成员 | 本群已开放的信息查询 |
| QQ 群管理员 | 查询、复活、发物品、踢人 |
| QQ 群主 | 上述能力、房间启停/保存/备份、常用工作台、本群设置 |
| AstrBot 维护者 | 连接、群/房间分配、全局权限、插件更新 |

通过 `group_permissions` 的 `member/admin/owner` 配置 `read`、`write`、`workbench`、`deny`；各群可在全局 `owner` 上限内设置 `rolePermissions`。关闭操作优先于开放；未知能力不会因新增目录自动授予普通成员。既有类别开关仍生效。群主不能管理其他群、改变全局连接或修改全局模板。

QQ 身份从 OneBot `get_group_member_info` 获取，写入前重新检查；无需把 QQ 管理员再加入 AstrBot 管理员或旧用户白名单。身份读取失败时仅保留成员允许的查询。私聊不继承群管理员身份。不支持真实群角色读取的平台继续使用成员权限或由维护者使用旧模式。

模型默认只看到新的任务入口。插件内部与快捷指令使用同一目标解析、授权器和执行器；参数为对象，不再要求模型拼 JSON 字符串。插件的 `dst_run` 使用 `capability_id`，无须模型自行准备 `taskRef`。模型提出的修改先向用户显示动作、房间与参数，收到用户的确认后才提交；模型不能代确认。明确的快捷管理指令仍按原有权限直接处理。收到结果中的任务编号后用 `dst_result(task_ref=...)` 回读本人任务。外部原生 MCP 的 `dst_run` 则使用前述 prepare/execute 契约，两者输入说明以各自工具 schema 为准。

活动、轨迹、战斗等扩展读取会同时向模型返回摘要和结构化事实，最多 24 KiB；`output.truncated` 和 `omittedPaths` 标明展示截断，优先保留底层覆盖缺口与分页游标。`timeEvidence` 提供原始记录时间对应的北京时间，区分事件发生、采样与读取时间，不用查询范围起点代替事件时间。未展示部分不能当成没有记录，超出预算时提示缩小范围或分页读取。读取任务也可用返回的 `taskRef` 回读，插件重载后仍有效；读取句柄独立保存，最多 256 条、24 小时，不挤占写入去重记录。

共享安装更新、面板系统维护等未进入固定群能力的操作仍通过面板或受控原管理入口处理；不能用某个群的房间授权直接执行影响其他房间的更新，也不能绕到通用 Lua。新增能力目录不等于开放所有 API。

## 目录兼容与程序更新

能力目录按需读取、分页校验、整份替换，兼容 v1/v2。兼容的新能力无需升级插件即可进入目录与菜单；超出插件输入类型的能力提示需要升级。新面板保留 v1；旧面板无协商接口时新版插件回退 v1。

程序更新独立于面板版本，设置 `plugin_updates.mode`：

- `manual`：默认，不后台检查或自动安装。
- `notify`：有有效连接且插件启用时，每约 6 小时检查；通过更新状态查看提示。
- `auto`：自动安装通过验签且环境兼容的正式包。当前限定已验证的 AstrBot 4.29.3–4.29.x、Python 3.12–3.13、支持目录原子交换的 Linux/macOS；其他环境保留手动更新。

维护者直接发送 `/dst 检查插件更新`、`/dst 安装插件更新`、`/dst 插件更新状态`、`/dst 取消插件下载`、`/dst 恢复上一版插件`。下载可取消，更换代理后重新检查；开始切换后等待加载检查或回退。配置可指定 HTTPS 清单镜像与下载代理，仍验证同一签名和文件摘要。使用 SOCKS5 代理时，AstrBot 环境须已安装 httpx 的 socks 支持。

程序包必须带受信公钥，发布清单使用 Ed25519 签名，同时检查版本、发布序号、有效期、文件大小、SHA256、环境和状态格式。未带公钥的开发包只支持手动维护，不会信任下载地址提供的新密钥。首次从旧插件迁移需要手动安装一次包含更新器与公钥的正式 ZIP。

发布者在 CI 配置 `ASTRBOT_UPDATE_SIGNING_KEY`（32 字节 Ed25519 私钥的 Base64），打包时写入对应公钥，并生成 `astrbot-plugin-release.json`。不配置签名密钥仍能发布手动安装包，但不产生可信的自动更新清单。私钥不得放入源码、文档或插件 ZIP。轮换根密钥需要先用已有密钥签发包含新信任信息的版本，不能直接换下载源来变更信任。

轮换时先将下一把公钥的 Base64 配置到 CI 变量 `ASTRBOT_UPDATE_NEXT_PUBLIC_KEY`，继续用旧私钥发布包含两把公钥的过渡版；确认客户端已安装过渡版后，再替换签名私钥。跳过过渡版的旧客户端需要手动安装受信包。

更新器由宿主保有，插件卸载不会终止安装。目录切换为原子交换；失败恢复上一份代码。业务配置、令牌、任务去重、消息游标存放于 AstrBot 稳定数据目录，回退不恢复旧游标或旧任务账本。安装中断记录保留在插件数据目录 `updates/installation.json`，`backup` 指向上一份代码；进程异常退出后若插件无法加载，应由维护者检查该记录并通过 AstrBot 手动恢复，不能清空业务记录后重装。

短请求最多等待 10 秒退出，单次宿主加载最多等待 60 秒；加载失败或超时后尝试回退。更新记录损坏时暂停代码切换，保留当前可用插件及原记录，正常查询不因此停止。

## 验证范围

本地测试覆盖权限撤销、冒充角色、越群/跨房间、任务重复提交、不确定结果不重发、昵称歧义、对象参数、私有凭据隔离、协议兼容、签名/环境/路径校验、取消慢下载，以及隔离环境中真实 AstrBot 4.29.3 的完整插件导入、初始化、重载和失败回退流程。QQ、网络与游戏调用均使用测试替身，未操作实际群或世界。

真实群管理身份、两个模型的任务选择正确率，以及 2C4G 部署下的延迟/资源曲线，仍需部署验收；不把本地测试数量或工具数量下降解释成真实场景的 98% 正确率。

## 工作台子动作与范围预览

`dst_find` 可以直接搜索闪电、月雹、隐身、踏水、阿比盖尔三级、冻结附近生物等具体动作，返回固定枚举参数建议；不会因为搜索而执行。模式观测、范围预览及旧客户端兼容见[工作台查询、预览与确认](workbench-actions.md)。
