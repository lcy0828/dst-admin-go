# 游戏服务端管理

**简体中文（默认）** | [English](game-installation-management.en.md)

打开 **游戏服务端管理**（`/servers/releases`），在“游戏服务端安装”区域查看本机
Runtime 和各 Agent 的安装状态、游戏版本、游戏目录、存档目录及 SteamCMD 状态。
顶部管理范围可切换全部机器或某台机器；同机登记的多份安装分别展示。没有房间的
安装也会显示，节点离线或检测失败不会被误报为“未安装”。

## 安装与更新

1. 在目标机器配置 SteamCMD（可执行文件、安装目录或 PATH 中的命令），并登记游戏目录、存档目录。
2. 在对应机器与安装位置点击“安装游戏服务端”或“更新 / 校验”，等待只读预检完成。
3. 查看受影响世界，选择是否在完成后恢复运行，再确认执行。运行中的世界会明确标注“将停止”。
4. 首次安装后可创建房间、导入存档，或继续安装下方的 LuaJIT2。

原生本机部署需在启动管理服务前创建已配置的目录，空目录即可，无需先下载游戏。
All-in-One 部署会准备持久化目录。

下载与校验由所选 Agent 自己执行，本机由进程内 Runtime 执行。控制端只派发任务
和显示结果，不中转 Steam 游戏文件。无需预先创建房间。任务结束会检查游戏程序
和版本信息，SteamCMD 正常退出但文件不完整时仍会报错。

安装需要 Linux x64、Native Runtime（包括常规 All-in-One）、可用的 SteamCMD
及至少 6 GiB 可用空间。不会自动安装操作系统依赖或 SteamCMD。远端需要支持
`runtime.game-install.v1` 的新版 Agent。尚未登记安装路径的 Agent 会显示配置提示，
需先在 Agent 配置中登记；页面不会任意创建新的可信目录。独立分片容器驱动暂不支持。

“更新 / 校验”复用游戏发布流程：创建并验证保护备份 → 停止相关世界 → 执行
SteamCMD 更新和校验 → 按选项恢复原本运行的世界。原本停止的世界保持停止。
共用安装及跨节点房间会一起纳入预览，避免同一房间混用版本；同机其他无关安装不受影响。
即使版本已是最新，也会实际校验文件。校验可能下载 Steam 当前版本，不是只读检查。

检查中、节点离线、状态未知或面板外游戏进程占用时不能确认；页面会给出原因和
“重新检查”入口。执行前再次核对计划，范围或运行状态变化时需重新确认。
首次安装或没有受管世界的空闲安装直接使用安装任务。运行中可离开弹窗，通过任务
状态或“查看更新记录”查看进度和失败原因；失败不会盲目重启世界。

显式更新会保留已有、可识别的 Linux x64 LuaJIT2 启动入口，用更新后的游戏程序
恢复入口并检查可用性，不下载或升级 LuaJIT 包。失败时可重试；普通开服不修复文件。

游戏更新失败后，只要任务仍可重试，其更新前保护备份就不能删除。重试会检查原备份
的文件和完整性；缺失或损坏时停止更新并提示恢复处理，不会用更新后的数据替换原保护备份。

## 可选 Steam 账号登录

在对应节点点击 **Steam 登录**。默认匿名；需要账号时选择“Steam 账号登录”，
输入登录账号名和密码，点击“保存并验证登录”。Steam Guard 要求验证时，输入
邮件或手机验证器中的当前验证码，或按提示在 Steam 手机应用中批准登录。
验证完成后再安装、更新或重试下载。

游戏安装、游戏更新（包括无人自动更新）和模组下载共用所选节点的登录设置。
同一节点使用同一 SteamCMD 程序的安装位置共用账号。Agent 自行登录和下载，
控制端不保存远端密码；旧 Agent 需升级以支持 `runtime.steam-login.v1`。

密码加密保存在管理服务或 Agent 配置目录下的 `steam-auth/`，目录中的密钥和
配置需一起保留。密码不会返回页面，也不会出现在进程参数、任务日志和 Agent
命令历史中。已保存的同一账号可留空保留密码；切换匿名并保存会清除面板保存的账号和密码。

登录验证最多持续四分钟，只在登录期间读取状态；关闭页面后不会无限保持登录进程。
自动下载遇到 Steam Guard 会报出验证提示，不会等待人工输入或自动改回匿名。
匿名下载失败也可能由网络、磁盘或权限引起，账号登录并不能解决所有下载错误。
可选的容器启动前 `DST_ADMIN_BOOTSTRAP_DST=true` 下载仍使用匿名，账号模式通过页面安装。

保存的凭据或密钥损坏时，页面会提示“重置登录设置”，下载暂时拒绝执行，不会自动
改用匿名。管理员确认重置后，仅清除此 SteamCMD 共用的面板登录配置；随后可使用
匿名登录或重新配置账号。其他 SteamCMD 的账号、游戏文件和存档不受影响。

## 使用机器上已有的服务端

当已登记的安装位置为空或不存在时，可点击“使用已有服务端”，填写**所选机器**
上的绝对路径。页面先检测程序和版本，再由用户确认接入。修改路径后必须重新检测；
检测到的程序或版本在确认前变化时，任务也会拒绝。

容器部署中的路径必须在该容器内可见。All-in-One 默认将宿主 `/opt/dst`
挂到容器 `/opt/dst`，页面填写 `/opt/dst/...`；使用其他宿主目录时需先显式挂载。
单独挂载的源目录必须在后续容器重建时继续保留，才能让接入关系持续有效。

接入在已登记的游戏位置创建指向现有游戏目录的目录链接。游戏文件继续保存在
原位置，不复制、不搬动、不覆盖；重启 Agent 后仍有效。页面同时显示登记位置
和实际游戏目录。后续更新及 LuaJIT 安装将作用于这份实际游戏，因此接入前需停止
所有使用它的世界。只支持 POSIX 目录链接；macOS 的 Steam 客户端安装仍由 Steam 维护。

游戏目录选择**不包含存档导入**：系统继续使用页面显示的原存档目录。
已有存档请从房间管理单独导入。游戏位置已有内容时不覆盖；源目录与存档目录或
登记位置重叠时拒绝接入。底层安装器不删除存档或自动启停世界；页面中的受管更新由游戏发布任务协调启停。

## API 与工作量

接口均位于 `/api/v2`，游戏安装与接入返回后台任务，登录设置直接返回脱敏状态：

| 接口 | 用途 |
| --- | --- |
| `GET /runtime-targets/game-installations?targetId=…` | 按管理范围查看所有登记安装 |
| `POST /runtime-targets/game-installations/preview` | 只读检查占用及更新范围，返回可确认的计划或阻断原因 |
| `POST /game/releases` | 按预检返回的安装选择、策略和计划哈希创建更新 / 校验任务 |
| `POST /runtime-targets/game-installations/probe` | 检测已有目录 |
| `POST /runtime-targets/game-installations/actions/install` | 安装或校验登记位置 |
| `POST /runtime-targets/game-installations/actions/adopt` | 确认接入已有目录 |
| `GET /runtime-targets/game-installations/steam-login` | 查看指定节点的登录方式与验证状态 |
| `POST /runtime-targets/game-installations/steam-login` | 保存设置、验证账号、提交验证码或取消验证 |

操作必须携带准确的 `targetId` 和 `installationId`。检测还需 `path`；接入再携带
检测返回的 `fingerprint`。安装不接受任意目标路径。远端失败不会回退到本机。
安装通过租约、Agent 操作日志和安装目录锁协调；同一操作重试不会重复执行。

页面打开、切换范围或手动刷新时才读取安装状态；不扫描磁盘寻找游戏，不检查
Steam 最新版，不在空闲时轮询。只有未结束的任务才每两秒读取任务进度。

预检仅在点击操作或重新检查时扫描所选安装的进程并检查关联节点；不增加空闲后台轮询。
调用方应先执行预检：`release` 模式提交返回计划的 `selectedInstallations`（字段名改为 `installations`）、
`policy` 和 `planHash`（同时作为 `confirmation`）；`install` 模式仅在 `ready=true` 时调用底层安装接口。
