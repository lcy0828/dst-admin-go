新增世界性能报表，修复导入集群、玩家列表与活动采集中的问题，并完善后台新版检查和机器人通知。

- **性能与报表：** 持续记录各世界的模拟速度评分、进程 CPU 与内存，可按房间、世界和时间范围查询曲线、统计、关联运行事件并导出 CSV。每个世界只显示一张统计卡，评分使用当前算法的有效区间；暂停、休眠、停止和缺测会说明原因，不填零或混算旧评分。CPU、内存历史继续保留。首页保持紧凑布局，数字评分仅在原有性能信号格的悬停提示中显示。
- **采集与开销：** 性能采集默认每 30 秒读取现有 Runtime 快照，可按房间调整间隔和保留期限。页面关闭后仍采集，不扫描实体、不读取完整存档，也不发送控制台查询。评分表示模拟时间推进比例，不是 FPS；高 CPU 本身不会扣分。
- **导入集群与 Runtime：** 按游戏实际使用的主分片身份校验遥测，修复导入配置中自定义分片 ID 导致的状态读取失败。运行清单跳过隐藏维护目录，避免误识别为房间或世界。Runtime 维护在成功启动后按世界重试，玩家采集遇到版本不一致时会请求已有的自动维护流程。
- **玩家与活动记录：** 玩家列表使用独立的请求序号，避免被其他面板刷新打断；进入运行房间遇到空缓存时按需采集一次。兼容 Lua 将空事件字段编码为数组的情况，恢复旧分段中的进出服、位置和动作记录。已补回的缺口显示为同步历史，运行实例切换不再暗示玩家离线。
- **后台检查与机器人通知：** 软件新版检查与通知订阅解耦，默认每 30 分钟检查，无需打开页面或先创建渠道。AI 连接页可配置机器人 Webhook；新增 `readNotificationEvents`，支持按游标分页补读、去重和历史过期提示。新版通知提供结构化版本信息。MCP 宿主仍需定时读取事件或接收 Webhook，普通 MCP 连接不会自动唤醒模型。
- **模组配置与代理设置：** 修复配置弹窗滚动区域和长选项的展示，保留数值、布尔与字符串选项的原始类型。HTTP 代理地址可直接查看和编辑，嵌入的账号密码仍不返回；修改其他设置不会覆盖原代理凭据。

**升级：** 控制端可在 **系统设置 → 软件更新** 在线升级，前端已内嵌；建议同时更新独立 Agent，以获得完整的进程采样字段。托管 Runtime 升至 **2.4.20**，通过现有自动维护机制更新。Docker 用户也可使用 `v1.3.11` 或 `latest`，国内使用阿里云镜像，其他地区使用 Docker Hub。升级保留配置、数据库、游戏存档和历史记录；暂停、休眠或缺测的旧时段不会补造评分。外部 MCP 客户端请刷新能力清单。

Adds world performance reports, repairs imported-cluster telemetry and player/activity collection, and improves background release checks and bot notifications.

- **Performance reports:** retain simulation-speed scores, per-process CPU and RSS history, with room/world/time filters, charts, runtime-event correlation and CSV export. Each world has one summary card. Scores use valid intervals from the current algorithm; paused, sleeping, stopped and missing intervals explain why no score is available. Resource history remains available across algorithm versions. Dashboard scores appear in the existing performance-bar tooltip without adding a numeric column.
- **Collection cost:** read existing Runtime snapshots every 30 seconds by default, with per-room interval and retention settings. Collection continues with the UI closed, without entity scans, full-save reads or console queries. Scores measure simulation progress, not FPS, and high CPU alone does not lower them.
- **Imported clusters and Runtime:** validate telemetry against the shard identity actually used by the game. Ignore hidden maintenance directories during room/world discovery. Retry managed Runtime maintenance after successful world startup and request existing maintenance when player collection detects an outdated Runtime.
- **Players and activity:** isolate player-list request sequencing from other refreshes and collect once on entry when an active room has an empty cache. Accept Lua empty-table arrays in event fields, allowing retained segments to recover. Distinguish recovered gaps and runtime-instance boundaries from actual missing history or player departures.
- **Background checks and bots:** check for software releases independently of delivery subscriptions, every 30 minutes by default. Configure bot Webhooks from AI connections or use the new cursor-based `readNotificationEvents` operation. Events include structured release facts and explicit retention gaps. MCP hosts must schedule reads or receive Webhooks; an ordinary MCP connection cannot wake a model by itself.
- **Mod configuration and proxies:** fix configuration-dialog scrolling and long options while preserving typed values. Display editable proxy endpoints without returning embedded credentials or overwriting them during unrelated settings changes.

**Upgrade:** use **System settings → Software updates** for the Controller with embedded UI. Updating standalone Agents is recommended for complete process samples. Managed Runtime **2.4.20** uses the existing automatic maintenance mechanism. Docker users may use `v1.3.11` or `latest` from Alibaba Cloud mirrors or Docker Hub. Configuration, databases, saves and history are preserved. Historical paused or missing intervals do not receive invented scores. Refresh external MCP tool lists.
