新增管理服务与 Agent 的持久化服务日志及 MCP 排查能力，修复自动备份回执兼容问题，并优化部署角色切换和首页世界布局。

- **服务日志：** 新增 **日志管理器 → 服务日志**，可选择管理服务或远程 Agent，按时间、级别、关键词、任务 ID 和请求 ID 查询，查看日志详情与上下文，导出当前查询页。默认保存 7 天、上限 100 MiB，支持调整保留策略和自动过期的临时调试。
- **排查与 MCP：** 记录任务排队、执行、阶段变化及失败原因，关联请求 ID 和异常堆栈。新增服务日志查询、来源状态、上下文、关联诊断及设置等 OpenAPI/MCP 操作，支持中文能力检索。离线、旧版 Agent、过期日志、查询截断和缺失证据会明确提示。
- **日志可靠性与开销：** 支持文件轮转、凭据脱敏、重复日志合并、有界队列及查询限流。磁盘写入失败时退避重试并保留终端输出；关闭持久化也保留终端日志。兼容从旧版启动器在线升级，升级后即可保存服务日志；新版启动器进一步保存子进程标准输出、标准错误和崩溃输出。
- **自动备份：** 修复 `cross-shard snapshot barrier failed` 中 `json: unknown field "commitRequested"` 导致的失败。保存回执的提交标记仍不会被当作保存完成的证据。回执解析失败有独立错误码和可读提示；重复错误不再堆叠，恢复清理保留原始失败原因。
- **部署角色：** **仅管理本机 ↔ 本机 + 集中管理** 可在世界运行时切换，无需停止或重启游戏。关闭集中管理前检查远程房间的现有部署与待迁移目标，离线节点同样检查。变更本机执行器、移交控制权或同时修改运行目录时，仍需先停止相关世界；后台任务和软件更新仍保持互斥。
- **首页布局：** 恢复桌面端紧凑的世界信息横排，压缩状态与操作区间距。长文本省略并提供悬停详情，异常诊断移至独立位置；窄屏继续使用响应式布局。

**升级：** 可在 **系统设置 → 软件更新** 在线升级控制端和内嵌页面；需要读取远程服务日志时，请同步更新对应 Agent。面板在线更新不会主动停止或重启游戏世界，请等待正在执行的后台任务完成。Docker 用户可使用 `v1.3.12` 或 `latest`，国内使用阿里云镜像，其他地区使用 Docker Hub。配置、数据库和游戏存档保持保留。外部 MCP 客户端请刷新能力清单。

Adds persistent panel and Agent service logs with MCP diagnostics, fixes automatic-backup receipt compatibility, and improves live deployment-role switching and dashboard world layouts.

- **Service logs:** query panel or Agent logs by time, level, keyword, job ID and request ID; inspect details and surrounding entries or export a bounded page. Persistence defaults to 7 days and 100 MiB per source, with configurable retention and temporary debug logging.
- **Diagnostics and MCP:** correlate task lifecycle events, failures, request IDs and recovered panic stacks. Add typed OpenAPI/MCP operations for log discovery, queries, context, diagnostics and settings, including Chinese discovery descriptions and explicit missing-evidence indicators.
- **Reliability and resource use:** rotate files, redact credentials, coalesce repeated messages, and bound queues, reads and query concurrency. Failed writes use backoff while terminal output remains available. Online upgrades from older launchers retain process-owned persistence; updated launchers also capture child stdout, stderr and crash output.
- **Backups:** accept the snapshot receipt's `commitRequested` compatibility field without treating it as save-completion proof. Distinguish receipt decoding failures, deduplicate repeated errors and retain the original diagnosis through recovery cleanup.
- **Deployment roles:** switch between local-only and local-plus-controller without stopping running worlds. Check current and desired remote placements before disabling centralized management, including offline nodes. Executor, ownership and concurrent path changes retain their stopped-world checks, and background operations remain mutually exclusive.
- **Dashboard:** keep world details compact on desktop, with truncation, hover details and separate failure diagnostics; preserve responsive layouts for narrow screens.

**Upgrade:** use **System settings → Software updates** for the Controller and embedded UI; update Agents to read their service logs. Panel online updates do not deliberately restart game worlds; wait for active background operations to finish. Docker users may use `v1.3.12` or `latest` from Alibaba Cloud mirrors or Docker Hub. Configuration, databases and saves are preserved. Refresh external MCP tool lists.
