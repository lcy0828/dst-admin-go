新增只读玩家背包查询，改善国内网络下的在线更新，并修复玩家档案、本地模组信息和 AI 回答依据问题。

- **玩家背包（#10）：** 查询在线玩家的装备、物品栏、手持物品和标准嵌套容器；离线或停服时读取当前存档快照。支持已知玩家 ID、本机及远程 Agent，不触发游戏保存。来源不明确时提供候选，读取不完整时明确标记。内置 Runtime 更新至 **2.4.15**。
- **在线更新（#18）：** 控制端与 Agent 可保存下载源、代理和超时设置。自动模式依次尝试已配置代理、官方直连和镜像；支持校验后的断点续传，以及可选的控制端中转。下载中断后可继续原版本，完整包校验通过后才应用。
- **新版通知：** 邮箱和 Webhook 可分别订阅控制端、Agent 新版提醒；后台检查仅在有订阅时运行，默认每 6 小时检查一次，可调整。按渠道、节点和版本持久化去重，“仅失败”过滤不会屏蔽已订阅的新版通知。
- **本地模组（#19）：** 列表和详情补充安装包中的名称、版本、作者和描述，支持中英文及受限的动态元数据读取。缓存按依赖失效，多节点信息不一致时明确显示差异，远程节点不可用时不会回退读取本机。
- **玩家档案（#20）：** 按世界 Session 区分当前存档和历史档案，重置世界后不再沿用上一局年龄、角色和生命属性。历史记录可查看，过期数据不再显示为实时。
- **头像（#21）：** 未知角色和图片加载失败使用静态占位，仅真实选角或加载状态显示等待动画。
- **AI 助手（#22）：** 当前状态问题要求本轮相应领域查询；缺少查询结果时补查或说明无法确认。指定单个世界的操作保持该世界范围，不扩大到整个房间。同步 OpenAPI、MCP 指导和前端契约。

**升级：** 在 **系统设置 → 软件更新** 更新控制端，独立 Agent 在 **机器管理** 中更新。Docker 用户也可拉取 `v1.3.5` 或 `latest` 后重建容器；国内推荐阿里云镜像，其他地区可使用 Docker Hub。前端随程序和镜像提供。背包实时查询需要对应节点及受管 Runtime 更新到本版。

**使用范围：** 背包覆盖标准组件，不保证读取任意模组的私有存储。首次确认新 Session 时，无归属的旧玩家记录进入历史，当前玩家由新采样恢复。AI 检查约束查询依据，不能替代对所有回答事实的判断；外部 MCP 客户端自行生成最终答复。

Adds read-only player inventory queries, improves online updates on restricted networks, and fixes player records, local Mod metadata and AI query evidence.

- **Inventory (#10):** inspect live equipment, inventory, held items and standard nested containers, or read the current saved snapshot while offline or stopped. Supports known player IDs, local installations and remote Agents without saving the game. Ambiguous sources and partial results are explicit. Bundles Runtime **2.4.15**.
- **Updates (#18):** persist Controller and Agent download sources, proxies and timeouts. Automatic routing tries the configured proxy, direct official access and a mirror. Adds validated resumable downloads and optional Controller relay; interrupted downloads retain their selected version and packages are verified before application.
- **Release notifications:** subscribe email or Webhook channels to Controller and Agent releases. Checks run only while subscribed, every six hours by default, with a configurable interval. Persistent deduplication covers channel, node and version; failure-only filtering preserves subscribed release alerts.
- **Local Mods (#19):** display installed names, versions, authors and descriptions, including localized and bounded dynamic metadata. Cache invalidation follows dependencies; differences across nodes remain visible, with no local fallback for unavailable remote nodes.
- **Player records (#20):** separate current and historical records by world Session. World resets no longer reuse the previous game's age, character or vitals. Archived records remain available, and stale values are not presented as live.
- **Avatars (#21):** use a static fallback for unknown characters and failed images; animate only during actual character selection or loading.
- **AI (#22):** require current-turn domain queries for current facts, retry missing evidence within bounds or report it as unavailable. Single-world operations retain their selected scope. OpenAPI, MCP guidance and frontend contracts are synchronized.

**Upgrade:** update the Controller under **System settings → Software updates**, and standalone Agents under **Machines**. Docker users can pull `v1.3.5` or `latest` and recreate containers. Use Alibaba Cloud mirrors in mainland China, or Docker Hub elsewhere. The frontend is embedded. Live inventory queries require the corresponding node and managed Runtime to be updated.

**Scope:** inventory covers standard components, not arbitrary Mod-private storage. Legacy player records without a confirmed Session move into history on first identification; fresh observations repopulate current players. AI evidence checks do not formally verify every claim; external MCP clients generate their own final answers.
