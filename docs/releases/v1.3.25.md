# v1.3.25

游戏工作台新增“地点”，可以保存基地等常用位置，检查落点并确认后传送玩家。配套 AstrBot 插件升级到 v0.4.3，支持地点查询、保存和传送的群内交互。

- **保存常用地点：** 按房间和世界管理地点，支持保存在线玩家当前位置、输入坐标，或在已有地图上选点；可查询、改名、修改和删除。地点随面板数据库保存，普通世界重启后保留。
- **传送前先检查：** 选择玩家与地点，查看落点后在 60 秒内确认。同世界、在线且状态合适的玩家才能传送；船上、骑乘、幽灵、切换世界等情况会拒绝操作。检查确认后的落点保持固定，落点或玩家状态发生变化时重新检查。
- **结果更明确：** 通过同次执行的前后坐标确认移动结果，区分成功、未执行与尚未确认。超时或缺少回执不自动重发；取消只能撤销尚未派发的操作。原有召回、召集、互换与最近实体移动也使用统一的落点检查，并提供逐玩家结果。
- **机器人可以直接操作：** 支持“有哪些地点”“把玩家甲当前位置记为基地”“把玩家甲传送到基地”。明确指令直接访问面板，复杂问题仍可直接 @机器人。传送确认绑定原群、原用户和本次请求，模型不能代确认；普通群员不会自动获得管理权限。
- **修复查询与检索：** 地点查询沿用房间概况的读取授权；补充自然语言检索词，修复 MCP 将传送推荐给不支持该操作的工具的问题。任务型 MCP 继续使用九个工具，不需要加载全部底层 API。

## 升级与兼容

面板升级保留存档和正在运行的世界。本功能需要 Runtime 2.4.22；远程运行机器需同步升级 Agent，旧节点不支持时会提示升级。普通启动不会为了本功能重写世界配置。

完整的机器人传送确认需要 AstrBot 插件 v0.4.3，并使用“面板地址 + 接入密钥”的私有连接。仅升级面板不会自动替换旧插件代码；使用通用 MCP 的 AI 可查询和预检，最终确认请在面板或新版插件中完成。旧插件查询及既有参数继续兼容，MCP 与内置模型不能通过旧移动或任意 Lua 入口绕过人工确认。

本版暂不支持跨世界传送。真实落点检查不能保证周围没有怪物或模组伤害；批量移动可能部分完成。详见[使用与兼容说明](../locations-and-teleport.md)。

## 验证

已通过后端自动化回归与并发检测、339 项插件测试、980 项前端测试及检查构建；另完成 38 项部署后 API 检查、22 项插件与面板集成场景、4 项原生 MCP 检索检查，以及桌面和移动端页面检查。集成消息使用模拟用户并截获回复，未向真实 QQ 群发送测试消息。真实玩家传送闭环、远程 Agent 实机组合与 2C4G 压力测试仍未验收。

本版完成 [#30](https://github.com/lcy0828/dst-admin-go/issues/30) 的地点与传送阶段，其他工作台扩展继续跟进。
