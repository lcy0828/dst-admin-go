# v1.3.27

简化游戏服务端更新：确认一次即可开始，可设置停服等待时间，并选择更新前备份或直接更新。右下角持续展示执行阶段，备份失败时由用户选择如何继续。

- **修复更新无法提交：** 解决检查和提交使用不同范围写法时，即使实际更新对象相同也提示“游戏更新计划已变化”的问题。普通更新不再要求传递和重复确认计划哈希。
- **停服等待可调整：** 支持 0～360 秒，页面默认 60 秒。先发送游戏公告，发送后开始完整倒计时；0 表示不额外等待，没有运行世界时跳过等待。
- **备份由用户选择：** 更新前备份默认开启，也可关闭后直接更新。手动更新备份失败时，可重试、明确确认跳过剩余备份，或取消更新并恢复原先运行的世界；已完成的备份保留。旧客户端和无人值守自动更新默认在备份失败后结束并恢复世界。
- **进度和结果更准确：** 右下角展示倒计时、停止、备份、更新校验和恢复。跳过备份、等待用户选择与取消更新分别显示；不会把等待中的任务显示为 100%，也不会把取消后的恢复显示为未执行。原先停止的世界保持停止。
- **保持必要检查：** 停止失败不能绕过，安装仍需校验；未知执行结果只读取原任务，不自动重发。等待备份选择的任务在面板重启后仍可继续处理。

## 升级与兼容

更新包包含配套页面。API / MCP 新提交支持 `confirmed: true`、`policy.stopDelaySeconds` 和 `policy.skipBackup`；旧版 `planHash` / `confirmation` 提交继续兼容，原有通用执行接口和权限不变。详细示例见[游戏更新与失败恢复](../game-updates.md)。

本次不改变游戏管理脚本版本，AstrBot 插件仍为 v0.4.4。发布新版、更新面板程序本身不会主动重启游戏世界；只有用户确认执行游戏服务端更新时才会停止相关世界。

## 验证

后端相关包竞态测试、前端测试、代码检查、构建及 OpenAPI 一致性检查通过。新增回归覆盖 3 个房间、6 个世界、其中 4 个运行的本机、Agent 和跨机器部署，以及可选备份、备份失败后的选择、倒计时和不确定回执。上述部署回归使用隔离测试替身，没有操作线上游戏世界。

## English

- Simplify game updates to one confirmation with a configurable 0–360 second shutdown warning and optional backups.
- Fix false plan-change errors caused by representing the same selected scope differently during preview and submission.
- Let interactive backup failures pause for an explicit retry, skip, or cancel-and-restore decision. Preserve legacy and unattended abort-and-restore defaults.
- Show accurate countdown, backup, update, restoration, waiting and cancellation states in the shared task dock. Preserve originally stopped worlds and never replay uncertain writes automatically.
- Keep legacy API/MCP hash confirmation compatible. The game runtime script version and AstrBot v0.4.4 are unchanged.

Relevant backend race tests, frontend tests, lint/build and API contract checks passed. Local, Agent and split-placement update regressions use isolated test doubles rather than production game worlds.
