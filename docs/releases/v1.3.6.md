修复多房间游戏更新在保护备份后失败的问题，完善更新恢复流程，并增强 MCP 中文工具发现和返回结果说明。

- **游戏更新（#24）：** 预检和关键操作后按需刷新受影响安装的运行清单，修复保护备份超过 90 秒后误报 `PLAN_CHANGED` / `TOPOLOGY_CHANGED`。正常流程统一为停服、保护备份、更新验证、恢复原运行世界；原本停止的世界保持停止，保留各世界的 Lua 运行模式。
- **更新恢复：** 持久化停服、写入和启动意图以及节点更新回执。重试先核查原操作，已验证安装不重复下载；仅启动确认失败时直接继续恢复。上游再次更新时可重新预检并确认新版本；回执丢失时提供显式校验修复，避免未知结果下重复写入。页面分别显示写入状态、目标版本、实际版本和恢复建议。
- **安装与维护：** 合并游戏安装和更新入口，更新或校验前显示影响范围，再自动保护并恢复房间。本机与 Agent 按安装和实际目录协调互斥，覆盖共享目录、符号链接和重复登记；游戏更新保留已有且可识别的 Linux x64 LuaJIT2 启动入口，不自动下载或升级 LuaJIT 包。
- **MCP（#23）：** 工具提供中文用途、操作表达、故障场景词及返回结果摘要，页面助手与外部客户端共用。可按需获取完整业务返回 Schema；保留认证、脱敏和参数校验，不引入常驻模型或向量数据库。工具元数据包含内容指纹，便于客户端缓存与重建检索索引。
- **MCP 更新调用（#24）：** 补齐完整参数示例，明确嵌套 `path`、哈希字符串确认、原 Release ID 与重试 Job ID，以及维护备份阶段和旧更新日志接口的适用范围，减少模型猜参数和误判维护停服。

**升级：** 在 **系统设置 → 软件更新** 更新控制端，独立 Agent 在 **机器管理** 中更新。建议两端都升级；未知写入回执的显式校验修复需要新版 Agent 的 `runtime.game-update-repair.v1` 能力。Docker 用户可拉取 `v1.3.6` 或 `latest` 后重建容器；国内推荐阿里云镜像，其他地区可使用 Docker Hub。前端随管理程序和镜像提供，升级保留配置、数据库和游戏存档。

**使用范围：** SteamCMD 安装执行时可用的最新 Build，不提供历史 Build 固定或自动降级。保护备份与游戏程序更新结果分别记录，不以任务进度 100% 作为成功或回滚证据。外部 AI 客户端仍需根据实际任务结果生成答复。

Fixes game updates failing after protection backups across multiple rooms, improves recovery, and adds Chinese MCP discovery metadata and result contracts.

- **Game updates (#24):** refresh affected installation inventories on demand before checks and after mutations. Protection backups exceeding 90 seconds no longer cause false `PLAN_CHANGED` / `TOPOLOGY_CHANGED` failures. The normal sequence stops worlds once, creates protection backups, updates and verifies files, then restores the original running worlds and Lua modes. Originally stopped worlds remain stopped.
- **Recovery:** persist stop/write/start intentions and node update receipts. Retries inspect the original operation before writing and skip verified installations. Launch-confirmation failures resume restoration without another download. A fresh preview can confirm a newer upstream build; lost receipts have an explicit guarded validation-repair path. The UI shows write evidence, expected/actual versions and recovery guidance separately.
- **Installation maintenance:** unify installation and update controls, preview affected rooms, then protect and restore them. Coordinate local and Agent maintenance by installation and actual directory, including shared paths, symlinks and duplicate registrations. Preserve recognized Linux x64 LuaJIT2 launchers during game updates without downloading or upgrading the LuaJIT package.
- **MCP (#23):** publish Chinese purposes, actions, symptoms and concise result summaries shared by the page assistant and external clients. Complete business result schemas are available on demand, with existing authentication, redaction and validation retained. No resident model or vector database is added. Metadata includes a content fingerprint for client index caching.
- **MCP update calls (#24):** provide complete argument examples and explain nested paths, hash-string confirmation, original Release IDs versus retry Job IDs, maintenance backup stages and the legacy update-log API boundary.

**Upgrade:** update the Controller under **System settings → Software updates** and standalone Agents under **Machines**. Updating both is recommended; lost-receipt validation repair requires the new Agent's `runtime.game-update-repair.v1` capability. Docker users can pull `v1.3.6` or `latest` and recreate containers. Use Alibaba Cloud mirrors in mainland China or Docker Hub elsewhere. The frontend is embedded; configuration, databases and game saves are preserved.

**Scope:** SteamCMD installs the latest available Build at execution time, without historical Build pinning or automatic downgrades. Protection backups and game-file results are recorded separately. Progress 100% does not establish success or rollback. External AI clients remain responsible for interpreting actual task results.
