新增玩家活动记录与游戏/模组分析，完善控制台和 AI 的执行回执，并修复游戏更新进度与房间并行启动。

- **玩家活动记录：** 在玩家管理或玩家操作菜单查看加入、离开、位置、交互动作与战斗记录。默认对所有玩家记录，可按房间动态调整采集类别、采样与同步间隔、保留时间和容量预算；轨迹按世界、运行实例和缺口分段，不把缺失记录当成没有发生。页面、OpenAPI、MCP 共用同一数据。
- **采集开销与稳定性：** 使用游戏事件和定时位置采样，不遍历全世界实体；无人在线时停止玩家采样与心跳。修复玩家进出重置采样周期，以及持续战斗阻塞 Runtime 热替换的问题；更新前有界批量写出待处理记录，失败或超时保留原实例继续采集。修复玩家活动弹窗切换房间、重新打开时的数据加载竞态。
- **游戏与模组分析：** 在房间诊断查看节点实际游戏版本、启用模组、作者兼容声明、最早可见错误与相邻堆栈，并与最近游戏更新前的摘要比较。无需 AI，不会自动禁用模组、操作存档或扫描模组源码；模组引用与版本差异只作为线索，不冒充已确认冲突。支持报告导出及 OpenAPI/MCP 查询。
- **控制台与 AI 回执：** 统一首页控制台和游戏工作台的同步 `print(...)` 输出，明确区分执行中、无输出、未确认、失败及输出截断。短时间内可重新读取原 Runtime 回执，避免因延迟重复执行 Lua；AI 工具同步提供输出和执行结果契约。异步回调输出和 Lua 返回值不属于同步回执。
- **生成位置记录：** 内置生成、给予物品、蓝图、配方材料及驯牛命令记录玩家执行时的位置和可确认的对象去向。区分世界坐标、物品栏和未知落点，记录随原命令回执持久化；不改写任意自定义 Lua，也不为记录再次执行命令。
- **游戏更新进度：** 页面顶部展示“停止世界 → 保护备份 → 更新并校验 → 恢复世界 → 确认加载”及各步骤完成数量；自动追踪后台发起和重新进入页面后的更新。详情使用房间、世界和机器名称，`local` 显示“本机”。完成后显示实际 Steam Build 和恢复结果，原本停止的世界保持停止；SteamCMD 下载与校验阶段使用不定进度，不把任务处理进度当成下载百分比。
- **共享安装启动：** 修复 Master、Caves 等世界共用游戏目录并行启动时误报“安装维护中”；更新、校验和其他会写游戏文件的维护操作仍互斥，保留中断维护的恢复保护。

**升级：** 在 **系统设置 → 软件更新** 更新控制端，独立 Agent 在 **机器管理** 中更新，建议两端一并升级。前端已内嵌，Runtime 升至 **2.4.17**。Docker 用户也可拉取 `v1.3.8` 或 `latest` 后重建容器；国内推荐阿里云镜像，其他地区使用 Docker Hub。升级保留配置、数据库和游戏存档。玩家活动无法补录启用前或已过保留期的历史，采集状态可在页面检查。

Adds player activity history and game/mod diagnostics, improves console and AI command receipts, and fixes game update progress and parallel world startup.

- **Player activity:** view lifecycle, sampled positions, actions and combat from player management or a player's action menu. Recording covers all players by default. Configure categories, collection/sync intervals, retention and storage budgets per room without restarting worlds. Trajectories respect world, process and collection-gap boundaries. UI, OpenAPI and MCP share the same data.
- **Collector stability:** use bounded game events and timed position samples, with no world-wide entity scans. Position and heartbeat timers stop when no players are online. Player churn no longer resets sampling deadlines, and continuous combat no longer prevents Runtime handover. Bounded draining retains the original collector on failures or timeouts. Fix dialog reload races when changing rooms or reopening activity history.
- **Game/mod diagnostics:** inspect installed versions, enabled mods, author compatibility declarations, visible errors and nearby stacks, and compare against the latest pre-update observation. No AI is required. Analysis does not disable mods, change saves or scan mod source; references and version differences remain diagnostic leads rather than proven causes. Reports can be exported or queried through OpenAPI/MCP.
- **Console and AI receipts:** consistently show synchronous `print(...)` output on the dashboard and workbench, distinguishing pending, empty, uncertain, failed and truncated results. Read the original late Runtime receipt during the recovery window without replaying Lua. AI tools expose the same output and execution semantics. Lua return values and delayed callback output are outside the synchronous receipt.
- **Spawn records:** built-in spawn/give, blueprint, recipe-material and domesticated-beefalo commands persist observed origins and destinations with the command receipt. World positions, inventory delivery and unresolved destinations remain distinct. Custom Lua is not rewritten or replayed for auditing.
- **Game update progress:** show stopping, protection backups, update/validation, restoration and load confirmation with observed completion counts. Track externally started updates and resume tracking after page navigation. Display room/world/host names, actual Steam builds and restoration outcomes. Originally stopped worlds remain stopped. SteamCMD uses indeterminate progress rather than presenting task-step percentages as download percentages.
- **Shared installations:** allow Master, Caves and other worlds to start concurrently from one game directory without false maintenance errors. File-writing maintenance remains exclusive, including interrupted-update recovery protection.

**Upgrade:** update the Controller under **System settings → Software updates** and standalone Agents under **Machines**; updating both is recommended. The frontend is embedded and Runtime is **2.4.17**. Docker users may pull `v1.3.8` or `latest` and recreate containers. Use Alibaba Cloud mirrors in mainland China or Docker Hub elsewhere. Configuration, databases and game saves are preserved. Activity history cannot reconstruct events before collection began or after retention expired; inspect collection status in the UI.
