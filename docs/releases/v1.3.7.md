修复玩家跨分片重复计数与背包查询位置不明的问题，统一页面、API 和 AI 助手的玩家位置语义。

- **玩家归属与人数（#25）：** 使用分片本地 `AllPlayers` 实体确认玩家所在世界，集群连接名单用于补充连接信息。房间在线人数按玩家去重，各世界只统计本地实体，排除虚拟 Host；选角、加载和迁移中的连接仍保留在线状态，不会被无人维护误判为无人。
- **背包查询（#25）：** 位置观测过期后，在本次查询中按需重新确认，修复超过 15 秒后频繁出现 `PLAYER_LOCATION_UNCERTAIN` 的问题。手动刷新会重新定位；迁移或实体重叠最多复核一次，指定世界时不跨世界读取。节点离线、采集失败或位置不明时，不用旧存档冒充实时背包。
- **页面与 AI：** 玩家当前位置与最后确认位置分开显示，未确定位置时显示“位置确认中”。分片人数、房间总在线人数及背包结果共用同一证据，OpenAPI、MCP 和页面助手同步提供位置确认信息。
- **Runtime 2.4.16：** 更新受管采集模块及本机、Agent 共用的控制台回退探针。沿用 Runtime 自动维护机制，不增加常驻轮询、额外存档保存或全量存档读取；保留原有背包嵌套容器、装备与查询资源限制。

**升级：** 在 **系统设置 → 软件更新** 更新控制端，独立 Agent 在 **机器管理** 中更新，建议两端一并升级。Docker 用户可拉取 `v1.3.7` 或 `latest` 后重建容器；国内推荐阿里云镜像，其他地区可使用 Docker Hub。前端随管理程序和镜像提供，升级保留配置、数据库与游戏存档。已有运行世界若仍使用旧 Runtime，可在方便时正常重启，使新版采集模块完整生效。

感谢 [@hxyinan](https://github.com/hxyinan) 在 [#25](https://github.com/lcy0828/dst-admin-go/issues/25) 提供的详细复现、接口对照与参考脚本。

Fixes duplicate shard player counts and unreliable inventory location detection, with consistent player location semantics across the UI, API and AI assistant.

- **Player location and counts (#25):** use shard-local `AllPlayers` entities to confirm world ownership, supplemented by cluster connection metadata. Room counts deduplicate players, shard counts include local entities only, and virtual Hosts are excluded. Connections selecting characters, loading or migrating remain online and do not trigger empty-room maintenance.
- **Inventory queries (#25):** refresh expired location evidence on demand, fixing frequent `PLAYER_LOCATION_UNCERTAIN` errors after the 15-second location window. Explicit refresh confirms location again; migration or overlapping entities get at most one recheck. A specified world is never silently replaced. Offline nodes, failed collection and uncertain locations do not fall back to saved data presented as live inventory.
- **UI and AI:** distinguish confirmed current locations from last known locations and show pending location confirmation when needed. Shard counts, room totals and inventory results share the same evidence, exposed through OpenAPI, MCP and the page assistant.
- **Runtime 2.4.16:** update the managed collector and the console fallback shared by local execution and Agents. Retain automatic Runtime maintenance, existing nested inventory/equipment support and resource limits, without adding resident polling, extra saves or full save-file scans.

**Upgrade:** update the Controller under **System settings → Software updates** and standalone Agents under **Machines**; updating both is recommended. Docker users can pull `v1.3.7` or `latest` and recreate containers. Use Alibaba Cloud mirrors in mainland China or Docker Hub elsewhere. The frontend is embedded; configuration, databases and game saves are preserved. Normally restart worlds still using the old Runtime when convenient to fully activate the updated collector.
