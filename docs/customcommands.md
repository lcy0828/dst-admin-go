# 游戏内 Runtime 扩展

DST Admin 通过各分片的 `customcommands.lua` 受管加载块加载游戏内 Lua 模块，用于玩家、世界状态、事件、受控管理动作和按需诊断。它与 Workshop Mod 共存，鉴权、任务、备份和跨机器编排仍由管理服务负责。

## 安装与维护

从页面的 Runtime 状态入口执行安装、升级、修复、卸载或回滚。安装只维护自己的加载块，不覆盖已有用户脚本；操作保留备份并检查 Lua 内容。修改文件本身不会让正在运行的 DST 自动重载，按页面提示热加载或重启。卸载及回滚需要停止相关世界并确认目标。

普通房间启动使用目标机器当前文件，不会自动重装 Runtime 或覆盖配置。日志、快照和动作回执由世界所在 Runtime 读取，远程世界不会改读控制端目录。

## 状态含义

- `live`：当前实例产生且仍有效的数据。
- `stale`：最后一次观察值，不证明世界当前仍在运行。
- `unavailable`：没有可信数据或目标不可访问。
- fallback：Runtime 快照不可用时使用兼容探针，页面会区分来源。

世界暂停可能使周期快照停止前进。停止、失联和暂停是不同状态；失联不会直接推断玩家离线。操作已发送但没有回执时不会自动重复执行危险动作。

## 诊断与限制

诊断仅在用户请求时运行，样本数和时间均有限制。不要把任意宿主命令或长期任务放入 `customcommands.lua`。模块与游戏、Mod 共享 Lua 环境，变更后应检查实际世界日志；测试用例不能代替目标游戏版本和 Mod 组合的验证。

API 以 [OpenAPI](openapi-v2.yaml) 为准；管理接口不要直接修改正在运行世界的存档或删除锁文件。
