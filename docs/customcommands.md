# 游戏内 Runtime 扩展

DST Admin 通过各分片的 `customcommands.lua` 受管加载块加载游戏内 Lua 模块，用于玩家、世界状态、事件、受控管理动作和按需诊断。它与 Workshop Mod 共存，鉴权、任务、备份和跨机器编排仍由管理服务负责。

## 安装与维护

控制端启动、Agent 升级或重新接入时，系统会自动检查已启用 Runtime 的受管世界。每个运行节点安装自己程序内置的配套版本：停止的世界更新文件，运行中的世界热加载并校验新实例及采集结果，正常更新无需重启游戏。相同版本且健康的实例不会重复加载。Agent 版本过旧或内置版本不匹配时，页面会提示先升级 Agent。

房间正在备份、迁移，或 Runtime 正在执行命令、诊断时，更新会暂缓并在本次维护窗口内有限重试，不会因等待该房间阻塞其他房间的检查；窗口结束后仍未完成，可在 Runtime 状态页查看原因并重试修复。

同一世界的重复检查不会覆盖正在进行的更新。状态页按当前运行节点和安装目录显示结果；迁移世界、更换安装目录或 Agent 实例后，会重新确认安装状态。已安装版本与进程运行版本不同时，页面会保留两个版本并提示激活，旧实例不会仅因版本不同被显示为采集不可用。

检测到旧控制通道、重复进程或非受管进程时，维护会停止改写 Runtime 文件。请先处理页面提示的进程冲突，确认相关分片已停止后再重试。

更新只维护系统加载块和受管 Lua 文件，不覆盖用户脚本，不修改或删除存档。更新前保留原文件；激活失败会尝试恢复原文件和旧实例，等待期间新增的用户脚本内容也会保留。受管文件存在人工修改时停止覆盖或恢复，并在 Runtime 状态中提示原因，可在页面检查并重试修复。已卸载的 Runtime 不会被自动装回。

首次手动启用仍可使用 Runtime 状态页的安装按钮，本机和远程 Agent 使用相同入口；卸载及回滚需要停止相关世界并确认目标。

新建导入存档会在临时目录中准备采集组件；替换导入和备份恢复沿用目标世界的采集启用状态，已卸载的组件不会因导入包包含它而重新启用。准备失败时不发布新存档，用户的加载块外 Lua 内容会保留。远程节点也需升级 Agent；旧 Agent 不支持保留采集配置时，系统会在停止世界或写入存档前提示升级。

普通房间启动使用目标机器当前文件，不会自动重装 Runtime 或覆盖配置。日志、快照和动作回执由世界所在 Runtime 读取，远程世界不会改读控制端目录。

## 状态含义

- `live`：当前实例产生且仍有效的数据。
- `stale`：最后一次观察值，不证明世界当前仍在运行。
- `unavailable`：没有可信数据或目标不可访问。
- fallback：Runtime 快照不可用时使用兼容探针，页面会区分来源。

Runtime 2.4.13 在首次世界初始化完成时立即准备采集，不依赖下一次游戏时钟。普通暂停使用静态调度；部分 DST 构建在无人休眠时会停止所有 Lua 更新，此时保留本次进程的最后有效采样，并显示暂停状态。面板不会为刷新数字而解除暂停或推进游戏时间。

无人休眠期间执行管理命令时，会按需确认采集器就绪并刷新过期数据，再发送一次用户命令。停止、失联和暂停是不同状态；旧进程或其他分片的健康文件不能放行操作，发送后没有回执时不会自动重发。

模拟性能诊断在已确认暂停时返回暂停原因。保存保护按真实时间限制：超时后不能发布一致备份，恢复保存或再次管理时会清理过期保护。

## 诊断与限制

### `BOOTSTRAP_UNAVAILABLE` / `REFRESH_UNAVAILABLE`

如果启动日志同时出现 `Filename [../dst-admin/bootstrap.lua] is not allowed by PersistentStorage`，说明旧版加载器使用了游戏不允许的父目录路径，导致采集模块没有加载。它会影响玩家和世界状态采集；无需修改 `server.ini`，也无需删除或重新生成存档。

1. 更新管理服务；使用独立 Agent 的机器也更新 Agent。
2. 系统会自动更新受影响的受管世界，并尝试激活新模块。无需修改 `server.ini` 或操作存档。
3. 在 Runtime 状态页检查结果。若更新失败，按原因处理目录权限、Agent 版本或手工修改的受管文件，再点击修复重试。
4. 日志出现 `[DST-ADMIN-RUNTIME READY] version=2.4.13 protocol=2`（或更新版本），且页面采集恢复，说明模块已加载。

从 Runtime 2.4.11 起，游戏从各分片的 `save/mod_config_data/dst-admin/runtime/` 加载脚本，长命令请求使用同目录上一级的 `command-requests/`；`dst-admin/` 中保留清单和维护源文件。安装时会检查加载文件是否完整，并保留用户的 `customcommands.lua` 内容。

模块不可用时，系统不再持续发送无效刷新命令；兼容控制台探针按分片逐步延长重试间隔，从 30 秒到最多 5 分钟。等待重试期间保留上次数据并标记过期，不会把旧结果作为新采样；模块恢复后，下一次正常文件读取即可恢复采集。

诊断仅在用户请求时运行，样本数和时间均有限制。不要把任意宿主命令或长期任务放入 `customcommands.lua`。模块与游戏、Mod 共享 Lua 环境，变更后应检查实际世界日志；测试用例不能代替目标游戏版本和 Mod 组合的验证。

API 以 [OpenAPI](openapi-v2.yaml) 为准；管理接口不要直接修改正在运行世界的存档或删除锁文件。
