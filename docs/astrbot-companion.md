# AstrBot 伴随助手

常见问题直接通过面板查询，不经过模型分类或生成回复；复杂问题继续使用已有 AI 人格。游戏数据、存档读取、执行任务和 Runtime/Agent 路由仍由面板负责。

## 安装与接入

1. 从 `integrations/astrbot` 构建插件 ZIP，在 AstrBot 导入 `astrbot_plugin_dst_companion.zip`，或将该插件目录放进 AstrBot 的插件目录。保持原有分页兼容设置和其他插件。
2. 在面板 **AI 助手 → 接入配置** 创建“游戏查询”密钥，并选择实际允许的房间。旧密钥保留面板管理权限，不会自动降权。
3. 在 AstrBot 添加 Streamable HTTP MCP 连接，例如 `dst-read`，地址为 `https://panel.example/mcp?view=bot`，使用 `Authorization: Bearer <ACCESS_TOKEN>`。客户端应支持分页；不支持时可使用项目已有的 `pagination=off` 兼容开关。bot 视图包含 14 个插件依赖入口，仍按密钥用途过滤；不会把数百个接口加载给模型。旧面板不认识 bot 视图时可暂用 view=all，固定查询可兼容，但新动态能力和可恢复写入需要新面板。
4. 在插件配置选择这个连接，填写明确允许的会话 `unified_msg_origin`、房间 ID 和可选别名。房间 ID 使用 `api_listRooms` 的真实返回值；别名示例 `{"1服":"example-room"}` 仅用于解释配置，不能照抄为真实房间 ID。多房间未配置默认值时会询问选择。
5. 配置群内可见查询：状态、名单、玩家档案、背包、网络、帮助、模组。位置/背包是否对群员公开由管理者决定；只读不意味着所有日志、系统信息都应公开。
6. 检查 AstrBot 原生工具权限。快捷路径也检查原接口权限，原生设为管理员的能力不会因为换成快捷入口而开放。新插件默认关闭、允许会话和房间默认空；完成配置后再开启。

插件仅修改配置的 DST 来源的模型工具视图，保留其他插件、人格和聊天增强；未开放会话不会获得本插件或其 DST 来源的模型工具。

普通用户的模型工具仅 3 个：

| 工具 | 参数 | 能力 |
| --- | --- | --- |
| `dst_rooms` | 无 | 允许访问的房间及真实 ID |
| `dst_room_query` | `room_id`、`query`、可选 `parameters` | `status`、`players`、`network`、`mods`；`capabilities` 发现已开放的动态读取，`cap:能力ID` 执行 |
| `dst_player_query` | `room_id`、`player`、`query` | `profile`、`inventory`、`network` |

这些工具不接受 Lua、函数名、任意 operationId 或调用者声明的只读属性。接口失败、未知 Schema、超时和数据覆盖不足均明确返回，不由模型自动补执行。

## 不调用模型的常见表达

```text
@机器人 1服查房
@机器人 帮我看看1服有哪些人
@机器人 查玩家 玩家甲
@机器人 玩家甲在哪
@机器人 查背包 玩家甲
@机器人 查玩家甲网络
@机器人 帮助
```

也支持 `/dst 查背包 玩家甲`。必须真实 @机器人、使用配置前缀或在已开放私聊中唤醒；文本中写一个假 @ 或 @其他群员不会唤醒。名字中的空格、表情和游戏装饰字符会保留。“不要重启”“如果重启会怎样”“查背包功能怎么实现”等讨论不会执行操作。

玩家以房间与 KU 为稳定身份。唯一精确昵称或规范化昵称可以读取；重名或模糊命中显示服务端返回的候选；目录覆盖超出一页时提示继续缩小昵称或使用 KU，选择后固定 KU，不因谁在线就猜谁。大目录覆盖不足会明确显示不可用，不把第一页一个人当作唯一命中。

候选有效 2 分钟，只有发起者能选择。引用选项回复序号无需再 @；不引用时须按正常唤醒规则。新请求会替代旧的待选状态。可信引用只来自同一适配器、机器人与会话中的实际发送消息 ID；复制或转发相似文本不能伪造关联。适配器不返回消息 ID 时降级为昵称/ID 查询。

先查玩家后再问“他为什么卡”，AI 会收到当前用户在当前会话中最近快查的目标、时间和简短证据。上下文最多 8 条、有效 10 分钟，序列化状态总预算 4 MiB；旧响应不能覆盖较新的目标。历史查询不会被标成实时数据。“查我”需要管理员登记经过验证的 QQ→KU 关联，同名不构成绑定。

网络回复保留原生 **netScore** 和可用的客户端性能档位。目前没有证实的逐玩家 RTT（ms）或 FPS 时会显示未采集；不换算档位，不把缺失指标当作 0，不把服务器 CPU 当成玩家网络。玩家所属世界未确认时也不会把历史位置当作当前位置。

背包复用面板实时/存档读取，不为了查询保存游戏；明确标注来源、采样时间和部分覆盖。不能证明模组私有容器内容已被读取。

## 可选游戏管理

另建一个“游戏管理”密钥与独立 MCP 连接，并在插件 `management_mcp_server` 中指定。固定管理连接建议使用 `?view=bot`；需要下文的管理员发现入口时使用 `?view=legacy`，同时包含具名接口和 `find_api/call_api`。两种目录均保留现有分页规则。配置允许管理的 QQ；还必须同时具备 AstrBot 原生管理员身份。群管理员身份本身不会自动成为游戏管理员。管理连接留空时不开放管理角色或显示管理菜单。

固定管理支持：房间启动、停止、重启、立即备份和踢人。模型增加 `dst_game_action`、`dst_job`，总计 5 个。管理时保留原来的运行模式，仍遵守容量、备份、维护锁及 Runtime 安全规则。

```text
@机器人 1服立即备份
@机器人 重启1服
@机器人 踢出 KU_example
@机器人 任务进度
@机器人 停止跟踪
```

写请求在下发前保存稳定 requestId、来源、目标和连接身份指纹。持久化失败就不发送；连接中断不自动重放。插件重载、相同消息重复投递只回读原任务，不新建一次备份。任务 `queued/running` 表示提交/执行中，只有 `succeeded + outcome=full` 才显示完成；100% 和 `sent` 不能代表成功。

一个按需启动的跟踪器共享最多两个 MCP 在途名额，每次仅一个后台读取，最多跟踪 32 项、默认 5 分钟。完成后发一条结果；到期仍读不到结果时明确提示结果未确认，发送不确定时不重发。权限撤销后停止向原调用者发送。重载停止旧跟踪器，已提交的游戏任务继续；使用“任务进度”接续读取持久化的原任务。“停止跟踪/算了”只停止当前用户的后续回复，不取消游戏任务。

面板管理员可在明确开放的私聊中增加 `dst_find_api` 与 `dst_call_api`，总计 7 个工具。确需更广的管理接口时，该独立连接使用“面板管理”密钥；配置中的角色不能扩大密钥本身的权限。发现返回完整嵌套参数 Schema；首发通用入口只允许契约声明为只读、且 `path.roomId` 属于开放范围的接口。固定管理工具覆盖之外的写操作及系统级接口通过面板执行。详细配置和原始管理数据不会默认送进群聊模型上下文。

## 面板密钥的实际限制

用途预设是服务端权限，不是目录标签：

- **游戏查询**：固定读取白名单；禁止通用 Lua、自定义命令、公告、保存世界和修改操作。玩家列表须指定 `includeAccessLists=false`。
- **游戏管理**：上述读取和明确列出的游戏操作、备份计划及所属房间任务回读；通用控制台仍禁止。
- **面板管理**：可信管理员使用的管理接口，可选限制房间。未限制时保留原有管理员能力。

范围同时检查具名 MCP 工具、`call_api`、旧兼容入口、普通 REST、资源和任务回读。受限密钥不能绕到旧 API 或凭工具名/元数据扩权；缓存和幂等结果回放前也先检查当前范围。房间列表只返回允许的房间。

`resolveRoomPlayer` 的 MCP 示例：

```json
{
  "tool": "api_resolveRoomPlayer",
  "arguments": {
    "path": {"roomId": "example-room"},
    "query": {"query": "示例玩家", "offset": 0}
  }
}
```

业务结果包括 `status`（`resolved/ambiguous/not_found/unavailable`）、`match`、`coverage`、`total`、`items`、`hasMore` 和 `normalizationVersion`。`current_directory` 仅指现有玩家目录，不保证完整历史名称或实时在线覆盖；`directory_limit` 不可用于确认唯一身份。精确 KU 使用索引读取，名称规范化扫描最多 4096 条现有记录，不读存档或访问游戏控制台。

## 与事件播报一起使用

已有 v0.1.1 播报可继续独立运行。升级为本目录 v0.1.2 时保留原插件名称、配置与 `broadcast_state_v1`，不要安装第二个重复播报实例。播报继续使用原来已授权的 MCP 连接；游戏查询预设不包含事件流和聊天接口，不要直接用新查询密钥替换播报连接。新版仍由原播报器唯一投递，不迁移或清空游标；增加可选玩家对象关联，共用在途预算，并每两分钟核对已订阅房间的世界列表。

伴随助手开启且会话/房间匹配时，进退通知以 OneBot 实际消息 ID 关联玩家。引用通知问“查他背包”可直接使用该 KU；伴随助手缺失或范围未匹配时保留原播报路径。不确定投递不会换一个发送者重发。只转发已授权的公开 `say`，不启用私聊转发或 QQ→游戏写回。

`@机器人 自检`、`@机器人 配置预览` 或 `/dst 自检` 向 AstrBot 管理员显示连接、必要能力、队列和合并计数；不会测试真实重启或主动发群消息。

## 验证边界

自动测试覆盖快捷路由与反例、重名选择、可信引用、跨用户隔离、并发目标顺序、原生权限、受限密钥、多入口绕过、结果分层、超时、取消隔离、请求合并、持久化失败、未知回执和单一播报投递。框架适配测试使用 AstrBot 4.29.3 的真实权限包装器与工具序列化；外部发送和游戏写操作由替身接管。

真实 QQ 收信、线上高并发时延及逐玩家 Ping/FPS 仍需单独验收。后台版本主动通知继续使用面板原有通知机制与订阅配置；普通 MCP 连接不会自行唤醒机器人。


## v0.2 配置与无模型菜单

在 AstrBot 插件设置中将 `configuration_version` 设为 **2**，使用 `defaults` 编辑全局设置。推荐新安装使用 `mode=shortcut`：被 @ 或前缀唤醒后，未命中指令会返回简短帮助；明确写 `AI: 你的问题` 才交给模型。`mode=mixed` 保留未命中时的普通聊天。旧配置可由 AstrBot 管理员执行 `/dst 迁移配置`，保存一份有界原配置备份并转为模式 2；保留原来的 mixed 行为和权限。迁移保存不确定时检查 WebUI 最终值，不自动重载其他插件。旧配置模式 1 继续读取原来的 `room_ids/public_queries/room_aliases` 等字段并保留 mixed 行为，不会悄悄改变群聊天规则。

`菜单`、`有哪些服` 支持序号、上一页/下一页和取消。缺少玩家时可以继续回复昵称；新指令会替换旧选择。菜单选择、参数、房间与引用都限定在发起者和当前会话，不借用别人的目标。

v2 可配置房间、房间别名、指令别名、菜单内容与顺序、停用能力、可见类别、明确开放的写能力、已验证的 QQ→KU 绑定、分页大小、模板、展示方式、任务通知和超时。模板仅允许 `{title}`、`{body}`、`{room}`、`{player}`；不执行表达式、对象访问或函数。来源、覆盖情况和管理结果不随模板消失。`detailed` 会补充目标 ID；默认 concise 保持简短。

会话覆盖使用原生 `session_overrides` 表单。**只有 `overrideFields` 选中的字段覆盖全局**；其他值即使被 AstrBot 自动填成默认值也继续继承。明确选中的 `false` 和 `[]` 会生效。会话只能缩小全局房间、数据类别和写能力范围。

```json
{
  "session": "example-adapter:GroupMessage:example-group",
  "overrideFields": ["pageSize", "taskNotifications", "writeAllowlist"],
  "values": {
    "pageSize": 8,
    "taskNotifications": false,
    "writeAllowlist": []
  }
}
```

`menuItems` 使用固定命令 kind 或能力 ID 排列菜单，例如 `["players","status","room.performance","*"]`；`*` 追加其余项，空列表只隐藏菜单项。实际禁止执行应使用 `disabledCapabilities`，会话只能增加停用项，不能撤销全局禁用。菜单隐藏不会改变权限。

指令别名示例：`{"在线":"players","报表":"cap:room.performance"}`。别名只引用固定命令或面板已注册的能力，不接受 URL、工具函数、Lua 或脚本。动态参数支持基础类型、有界对象/数组和枚举；世界提供选择，玩家名沿用身份解析。写参数有默认值时会先显示默认值，回复“默认”才使用。

配置预览只读展示当前来源和生效范围，修改仍以 AstrBot 插件设置为准；无效授权配置会关闭相关执行。展示模板无效则回退内置样式。不要同时编辑 WebUI 和其他配置客户端；框架没有跨客户端全局 CAS 保证。插件不请求全量重载 AstrBot。

## 面板新增能力，插件不升级也能使用

服务端维护固定能力注册表，目录只描述已实现的操作。插件按需检查修订（默认 60 秒，可配置 10～300 秒），分页全部成功才替换目录；闲置时不轮询。面板新增加兼容的读取能力，且属于已开放的数据类别，会自动进入菜单。未知类别、未知协议或不支持的 Schema 不执行；新写能力必须显式加入 `writeAllowlist`，并且调用者仍须具备原生管理员身份和独立管理连接。

首批包括房间状态、玩家解析/名单/背包、模组、性能报表、备份设置、固定世界查询，以及启动/停止/重启/保存、立即备份、踢人和自动备份配置。保存和公告不属于只读能力；通用控制台不会暴露给群员。

例如开放 `room.backups.configure` 后，管理者可以直接说“开启自动备份/关闭自动备份”；菜单可以设置开关；修改完整计划可以使用明确的结构化参数：

```text
/dst 功能 room.backups.configure {"enabled":true,"schedule":"0 4 * * *","timezone":"Asia/Shanghai","keep":7}
```

参数未指定的已有计划设置由面板保留。配置成功表示计划已保存，不表示已经生成备份。立即执行仍使用“立即备份”。多个现有备份计划需要提供准确 taskId，不会任意选择。

普通模型仍只获得三个包装工具；`dst_room_query(query="capabilities")` 可以读取兼容目录，`query="cap:能力ID"` 配合 parameters JSON 调用读取。管理员可先用 `dst_game_action(action="capabilities")` 获取已开放写能力的参数，再用 `action="cap:能力ID"` 复用相同目录、写白名单和持久化任务流程，不通过任意 API 或代码执行。

## 稳定 API/MCP 契约

| MCP 名称 | 用途 |
| --- | --- |
| `api_listBotCapabilities` | 按当前密钥范围分页获取能力与参数 Schema |
| `api_queryBotCapability` | 执行一个固定只读能力 |
| `api_runBotCapability` | 提交一个固定写能力，必须有稳定 requestId |
| `api_getBotCapabilityResult` | 用原 requestId 读取原任务/查询，不重新下发 |

发现示例：

```json
{"query":{"protocolVersion":1,"limit":32}}
```

使用返回的 `schemaRevision`，不能把下面的示例修订值直接用于调用：

```json
{
  "path":{"roomId":"example-room","capabilityId":"room.players"},
  "query":{
    "contractVersion":1,
    "schemaRevision":"COPY_FROM_DIRECTORY",
    "requestId":"example-query-request-001",
    "parameters":"{}"
  }
}
```

查询的 parameters 是单个 JSON 字符串；写入 parameters 是 body 中的 JSON 对象。写入顶层 requestId 映射 `Idempotency-Key`。客户端隐藏编码细节；服务端拒绝未知字段、重复键、越界值和错误修订。

业务结果包含 `status/complete/source/observedAt/cached/executionOutcome/mayHaveExecuted`，以及 requestId、可选 jobId/queryRunId、data、error 和 nextAction。HTTP/MCP 成功只说明获得了一份业务回执，仍要检查业务状态。数量没有确认时不表示 0；任务已排队和 100% 不表示完成。

回包丢失时，只调用结果入口：

```json
{"path":{"roomId":"example-room","requestId":"example-write-request-001"}}
```

结果只属于最初接入身份和房间，并按当前权限复核。密钥或连接身份变化不会自动迁移旧任务。旧能力移除后可以在保留权限下读取原结果；不存在/已过期也不能证明没有执行。不要自动换 requestId 重发。

预算：共用最多 2 个 MCP 在途请求，最多排队 32 项；单目录最多 256 项/1 MiB；参数最多 8 KiB、对象深度 4，单份业务结果最多 64 KiB。面板保留终态正文 7 天，之后保留轻量幂等身份；执行中和不确定回执不被普通历史清理淘汰。面板请求身份最多 10000 项，插件管理 journal 最多 256 项，满额时拒绝新提交并保留原记录供核对，不通过删除未确认记录恢复额度。QQ 投递缺少可靠回执时标记不确定，不自动重发。
