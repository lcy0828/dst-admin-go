# AstrBot 饥荒助手

常见问题直接通过面板查询，不经过模型分类或生成回复；复杂问题继续使用已有 AI 人格。游戏数据、存档读取、执行任务和 Runtime/Agent 路由仍由面板负责。

QQ 快查和非流式饥荒 AI 回复使用纯文本展示，不显示 Markdown 粗体、反引号或标题符号。需要补充操作目标时会提示输入玩家昵称或 KU ID。管理回执区分指令执行结果与游戏内实际效果；例如复活指令收到执行回执后，仍需玩家状态证明复活效果，不能仅凭收到回执就宣称玩家已复活。原始指令输出可在面板查看。

## 权限与确认

新安装的默认权限策略为 `access_policy=simple`。旧安装缺少该字段时保留原有自定义限制，升级不会自动扩权：

- **查询对所有人开放**：状态、玩家、背包、网络、模组、性能报表、世界信息、备份设置等全部只读内容。
- **管理操作对管理员开放**：`permission_mode=group` 时为群主和群管理员；`legacy` 时为已登记的游戏管理员。普通群员不能执行任何修改。
- `disabledCapabilities` 与本群 `deny` 列表仍可禁用个别能力。需要按类别和单项授权时，将 `access_policy` 设为 `custom`，沿用原有 `categories`、`writeAllowlist`、`workbenchMode` 与群角色规则。

确认方式只取决于操作风险，直接指令和 AI 工具完全一致：

| 等级 | 例子 | 确认方式 |
| --- | --- | --- |
| R0 查询 | 查服、查背包、最近一天性能 | 不确认 |
| R1 单人、可撤销 | 复活、发物品、无敌/创造模式 | 直接执行 |
| R2 影响全服 | 跳过一天、切换季节/昼夜、重启、踢人、解封、原生备份接口 | 回复“确认” |
| R3 破坏性 | 重置世界、回滚、击杀、封禁、清空背包 | 回复确认短语，如“确认重置” |

面板的预览类操作（附近批量、传送等）仍先预览再确认。确认提示可直接回复，也可引用确认提示回复；引用通知或其他消息不会确认或更换已准备好的操作。

### 重置世界

发送“重置世界”“删档重开”等会准备重置全部世界（地面和洞穴）。默认先创建“重置世界前保护备份”，再重置：

- 回复 `确认重置`：先备份再重置。
- 回复 `确认重置 不备份`：跳过备份直接重置，旧进度无法恢复。
- 直接说“重置世界不用备份”时，提示会写明不备份；仍可回复 `确认重置 备份` 改回备份。

备份失败时不会重置，世界保持原样。重置在面板任务中执行（`POST /api/v2/rooms/{roomId}/actions/reset-worlds`，需要完整房间名确认），未收到游戏回执时报告“未确认”，请查看世界状态，不要重复提交。

### 补充信息与回执

机器人询问玩家昵称等信息时，直接回复即可；如果你接着发的是新请求（如“查看地图”“跳过一天”“最近一天 CPU 怎么样”），会放弃上一个待补充的操作并处理新请求。引用询问消息回复时，内容一定按回答处理。

`查人`、`差人`、`在线名单`直接查询当前房间的在线名单；`查人 昵称`查询指定玩家资料，可加房间前缀。同一用户在同一会话发出新请求时，尚未完成的模型请求会结束，包括模型还在思考、未选中工具的阶段；`/dst` 设置命令同样生效。已经明确使用其他插件工具、且未使用饥荒工具的话题，以及其他用户和会话，继续独立处理。

旧请求不能补发答案、恢复玩家选择或确认，也不能在排队、身份核验或连接刷新后发送尚未提交的修改。已经提交的游戏操作继续执行，保留原任务与执行记录供回读；新提问不会撤销或重复执行它，结果未确认时不会自动重发。

带玩家的管理回执首行显示实际对象，例如“对象：lcy”；沿用上一次的玩家或来自引用消息时会注明“（沿用你刚才操作的玩家）”“（引用的消息）”。

单人复活支持“复活玩家昵称”和“复活 玩家昵称”。同名或缺少玩家时先补充目标；只复活在线幽灵，存活玩家保持原状。

## 自动发现新增功能

私有面板连接协商到 `companion-gateway-v1` 后，模型只接收 `dst_find`、`dst_read`、`dst_result` 和有权修改时的 `dst_run`。功能直接来自原 API 契约与内置工作台；面板增加兼容接口不必同步修改插件关键词。无需 `AI:` 前缀。输入、任务回读、断线恢复和资源发送见 [自动能力发现](ai-capability-discovery.md)。

下面的 MCP 连接和专用门面说明用于已有连接及旧面板兼容路径；使用新版私有连接时，以协商后的四工具模式为准。

## 安装与一键接入

v0.3 将查询、AI 和事件播报合并为 **DST Admin 饥荒助手**，技术插件名仍为 `astrbot_plugin_dst_companion`，已有安装可直接升级。只安装这一个插件。

1. 从正式版下载 `astrbot_plugin_dst_companion.zip` 和校验文件，在 AstrBot 导入；也可以用 `python integrations/astrbot/package.py --output /tmp/dst-astrbot` 构建。已安装旧伴随助手时覆盖升级即可。
2. 在 AstrBot 添加面板 Streamable HTTP MCP，地址如 `https://panel.example/mcp?view=bot`，使用 `Authorization: Bearer <ACCESS_TOKEN>`。已有连接可直接复用。访问密钥在面板 **AI 助手 → 接入配置** 创建；密钥与地址仍须配置一次，插件不会自行获取管理凭证。
3. 唯一可用 DST MCP 自动识别。多个连接时，AstrBot 管理员发送 `/dst 使用连接 连接名` 明确选择，插件不会猜选另一个面板。
4. 管理员在目标群发送 **`/dst 启用本群`**。插件自动识别当前群、平台和真实房间；保存成功后才开放本群。无需抄写群号、平台 ID、roomId 或别名。

新群默认同步该密钥允许的房间；按面板中的唯一房间名称识别，绝不把目录顺序当作“1服/2服”。只想开放一个房间时使用 `/dst 订阅房间 房间名称`，恢复自动同步用 `/dst 订阅房间 全部`。原有明确配置的房间上限会保留，升级不会自动扩大旧范围。

| 群内管理员指令 | 用途 |
| --- | --- |
| `/dst 启用本群` | 接入当前群，重复执行保留已有设置 |
| `/dst` | 查看插件设置帮助，不调用模型 |
| `/dst 启动本群 聊天播报 开` | “启动本群”为启用别名；一次保存群接入和聊天播报开关 |
| `/dst 设置` | 查看当前范围与播报状态 |
| `/dst 订阅房间 房间名称` | 按唯一名称选择本群查询与播报范围 |
| `/dst 订阅房间 全部` | 同步面板授权；仍受原有全局房间上限约束 |
| `/dst 播报 开` / `关` | 播报总开关，含聊天；暂停时保留类别选择 |
| `/dst 聊天播报 开` / `关` | 单独控制公开 say，默认关闭 |
| `/dst 禁用本群` | 关闭本群查询、AI 工具与播报 |

启用时默认开放全部只读查询，管理员可执行管理操作（见“权限与确认”）；`access_policy=custom` 时可在高级设置缩小类别。新群仍须主动启用，已有 AstrBot 群白名单和工具权限继续生效。

开启 AstrBot 群成员会话隔离时，插件仍按实际群接入和播报，查询上下文及菜单选择保留用户隔离。若启用了原生白名单，应允许目标群的真实群号；只允许某个成员的会话或管理员豁免不等于允许全群。旧的单成员群接入与播报记录会备份后迁移，冲突授权不会合并扩大。

`?view=bot` 仅包含插件所需的依赖入口（含房间动态与版本通知），按密钥用途进一步过滤。旧连接可使用下文的专用门面；新版私有连接使用四工具模式。支持分页；不支持分页的客户端可继续使用 `pagination=off`，该兼容开关保持原行为。旧面板也可接入：已有目录发现与查询不要求新增 API；旧版 bot 视图缺少播报依赖时，需使用已有的完整同源连接，或升级面板。

插件仅修改配置的 DST 来源的模型工具视图，保留其他插件、人格和聊天增强；未开放会话不会获得本插件或其 DST 来源的模型工具。

旧专用门面保留以下三个兼容工具（新版四工具模式不将它们同时提供给模型）：

| 工具 | 参数 | 能力 |
| --- | --- | --- |
| `dst_rooms` | 无 | 允许访问的房间及真实 ID |
| `dst_room_query` | `room_id`、`query`、可选 `parameters` | `status`、`players`、`network`、`mods`；`capabilities` 发现已开放的动态读取，`cap:能力ID` 执行 |
| `dst_player_query` | `room_id`、`player`、`query` | `profile`、`inventory`、`network` |

这些工具不接受 Lua、函数名、任意 operationId 或调用者声明的只读属性。接口失败、未知 Schema、超时和数据覆盖不足均明确返回，不由模型自动补执行。

## 不调用模型的常见表达

```text
@机器人 1服查房
@机器人 帮我看看1服有哪些人
@机器人 查玩家 玩家甲
@机器人 玩家甲在哪
@机器人 查背包 玩家甲
@机器人 查询 玩家甲 背包
@机器人 查玩家甲网络
@机器人 帮助
@机器人 玩家信息
@机器人 1服查询玩家信息
@机器人 1服查一下 玩家甲 的背包
@机器人 现在有谁在线
```

也支持 `/dst 查背包 玩家甲`。必须真实 @机器人、使用配置前缀或在已开放私聊中唤醒；文本中写一个假 @ 或 @其他群员不会唤醒。名字中的空格、表情和游戏装饰字符会保留。“不要重启”“如果重启会怎样”“查背包功能怎么实现”等讨论不会执行操作。

所有菜单显示名称均可直接发送，仍受当前权限限制；“玩家信息”“玩家资料”等未提供目标时进入昵称表单，不查询在线人数来推断是否存在历史玩家。查询词可在房间名前后，明确房间不会被剩余文本覆盖。真实 At 组件旁多余的独立 `@` 会被忽略，不会剥去玩家昵称里的 `@`。

玩家以房间与 KU 为稳定身份。唯一精确昵称或规范化昵称可以读取；重名或模糊命中显示服务端返回的候选；目录覆盖超出一页时提示继续缩小昵称或使用 KU，选择后固定 KU，不因谁在线就猜谁。大目录覆盖不足会明确显示不可用，不把第一页一个人当作唯一命中。

候选有效 2 分钟，只有发起者能选择。菜单发出后同一用户可直接回复序号；引用旧菜单不能选择新菜单。新请求会替代旧的待选状态。

引用玩家进退服、死亡或复活播报，再说“查背包”“查他背包”或“查玩家”，可直接使用该玩家的 KU，包含已离线玩家；是否能读出背包仍取决于面板存档来源。开启按成员隔离的 AstrBot 会话也支持群播报引用，个人菜单及其他查询目标仍按用户隔离。播报最多保留 256 条、7 天的已确认发送关联，重载后可继续使用。

旧版本没有保存关联的通知，兼容新旧默认进退服模板及默认死亡、复活模板：仅在一周内、同源投递记录仍在、原消息由当前机器人发于当前群、时间及格式匹配时，回查原消息并通过面板解析昵称；死亡、复活通知还须对应当前房间保留的事件投递记录。QQ 的引用预览被截短时会核验完整原消息。重名需选择。复制、转发、别人的消息、跨群引用及无法确认的引用不会自动选中玩家，也不会退回上一次的查询目标；请补充昵称或 KU。可信引用可为查询和玩家操作选定目标，管理权限、参数和必要的确认仍单独校验。

先查玩家后再问“他为什么卡”，AI 会收到当前用户在当前会话中最近快查的目标、时间和简短证据。上下文最多 8 条、有效 10 分钟，序列化状态总预算 4 MiB；旧响应不能覆盖较新的目标。历史查询不会被标成实时数据。“查我”需要管理员登记经过验证的 QQ→KU 关联，同名不构成绑定。

网络回复保留原生 **netScore** 和可用的客户端性能档位。目前没有证实的逐玩家 RTT（ms）或 FPS 时会显示未采集；不换算档位，不把缺失指标当作 0，不把服务器 CPU 当成玩家网络。玩家所属世界未确认时也不会把历史位置当作当前位置。

背包复用面板实时/存档读取，不为了查询保存游戏；明确标注来源、采样时间和部分覆盖。原版物品的 Prefab/英文默认名由插件包内的面板同源词库转为中文，无需模型或额外逐物品请求；保留玩家自定义名称，未知模组物品继续显示原名或 Prefab。存档只保存剩余保鲜秒数时展示可读时长，不推算新鲜度百分比。不能证明模组私有容器内容已被读取。

离线玩家也能查询已保存的背包、活动、移动轨迹和战斗记录。只读查询中，完整目录确认只有一个昵称匹配时直接读取；多人匹配仍须选择。背包默认展示实时数据；离线有多份存档时，若每个世界只有一个来源且文件时间明确、较新时间唯一，先展示按文件时间选择的最近存档，并提供两分钟内按序号切换其他存档的入口。这不代表下线时的实时背包。时间缺失、相同、异常或同一世界存在多个来源时仍须选择。来源已变化、没有存档、解析失败和读取超时会分别提示，不会自动换来源重试或据此认为背包为空。存档没有物品上限时不推算耐久百分比，剩余次数取近似值展示。

活动、轨迹、战斗记录可直接查询，无需经过模型，例如：

- `查询玩家最近两天做了什么`：查看当前房间全员的已采集活动；引用可信玩家通知时只查该玩家。
- `查询某玩家过去48小时的活动记录`：按昵称解析玩家，离线也可查询。
- `查询某玩家最近两天的移动轨迹`：查看采样坐标；未指定玩家时先补充目标。
- `查询某玩家最近3小时的战斗记录`：查看已保存的战斗汇总；不提供玩家时可查全员。

省略时间默认最近 24 小时，快捷查询接受 1 小时至 90 天；实际记录受采集启用时间和保留设置限制。每次最多读取 20 条活动或轨迹，长消息会减少展示条数；战斗接口沿用面板的扫描上限。缺口、截断和未知伤害会单独提示，不将未采集解释为没有活动，也不会将跨世界或缺口的坐标连成连续路线。需要分析原因、比较或联合查询时，可直接自然提问，由 AI 使用同一受控查询通道读取后分析，无需 `AI:` 前缀。

协商到 `companion-gateway-v1` 的私有连接中，常用快捷查询复用 AI 的受控读取入口，权限、参数校验和错误详情由面板统一处理。旧面板在能力协商确认不支持时继续使用原 MCP 入口；已提交查询遇到失败、超时或不确定结果时，不会切换入口自动重试。

只发“查询 玩家背包”且没有已确认的上下文目标时，会要求补充游戏昵称或 KU ID，不会把“玩家”当作昵称。聊天播报仅转发启用后的新公开消息，默认约 3 秒检查一次，不补发历史；同批连续消息按最多 5 条和输出长度合并，进退服详情查询不阻塞已入队聊天的投递。实际延迟还受面板采集、网络及 QQ 投递影响。可用 `/dst 设置` 查看已保存的开关与投递拦截原因；配置已保存不代表消息已成功投递。

## 旧连接的可选游戏管理

另建一个“游戏管理”密钥与独立 MCP 连接，并在插件 `management_mcp_server` 中指定。固定管理连接建议使用 `?view=bot`；需要下文的管理员发现入口时使用 `?view=legacy`，同时包含具名接口和 `find_api/call_api`。两种目录均保留现有分页规则。配置允许管理的 QQ；还必须同时具备 AstrBot 原生管理员身份。群管理员身份本身不会自动成为游戏管理员。管理连接留空时不开放管理角色或显示管理菜单。

旧专用门面的固定管理支持房间启动、停止、重启、立即备份和踢人，并增加 `dst_game_action`、`dst_job` 两个模型工具。新版四工具模式通过 `dst_run`、`dst_result` 处理管理与结果回读。管理时保留原来的运行模式，仍遵守容量、备份、维护锁及 Runtime 安全规则。

```text
@机器人 1服立即备份
@机器人 重启1服
@机器人 踢出 KU_example
@机器人 任务进度
@机器人 停止跟踪
```

写请求在下发前保存稳定 requestId、来源、目标和连接身份指纹。持久化失败就不发送；连接中断不自动重放。插件重载、相同消息重复投递只回读原任务，不新建一次备份。任务 `queued/running` 表示提交/执行中，只有 `succeeded + outcome=full` 才显示完成；100% 和 `sent` 不能代表成功。

一个按需启动的跟踪器共享最多两个 MCP 在途名额，每次仅一个后台读取，最多跟踪 32 项、默认 5 分钟。完成后发一条结果；到期仍读不到结果时明确提示结果未确认，发送不确定时不重发。权限撤销后停止向原调用者发送。重载停止旧跟踪器，已提交的游戏任务继续；使用“任务进度”接续读取持久化的原任务。“停止跟踪/算了”只停止当前用户的后续回复，不取消游戏任务。

旧专用门面中，面板管理员可在明确开放的私聊增加 `dst_find_api` 与 `dst_call_api`。该独立连接使用“面板管理”密钥；配置中的角色不能扩大密钥本身的权限。此兼容入口只允许契约声明为只读、且 `path.roomId` 属于开放范围的接口。新版私有连接通过四工具模式发现和执行授权接口，支持全局、机器和房间范围；面板级管理仍须维护者授权。详细配置和原始管理数据不会默认送进群聊模型上下文。

## 面板密钥的实际限制

用途预设是服务端权限，不是目录标签：

- **游戏查询**：固定读取白名单；禁止通用 Lua、自定义命令、公告、保存世界和修改操作。玩家列表须指定 `includeAccessLists=false`。
- **游戏管理**：上述读取和明确列出的游戏操作、备份计划及所属房间任务回读；通用控制台仍禁止。
- **面板管理**：可信管理员使用的管理接口，可选限制房间。未限制时保留原有管理员能力。

范围同时检查具名 MCP 工具、`call_api`、旧兼容入口、普通 REST、资源和任务回读。受限密钥不能绕到旧 API 或凭工具名/元数据扩权；缓存和幂等结果回放前也先检查当前范围。房间列表只返回允许的房间。

`resolveRoomPlayer` 的 MCP 示例：

```json
{
  "tool": "api_resolveRoomPlayer",
  "arguments": {
    "path": {"roomId": "example-room"},
    "query": {"query": "示例玩家", "offset": 0}
  }
}
```

业务结果包括 `status`（`resolved/ambiguous/not_found/unavailable`）、`match`、`coverage`、`total`、`items`、`hasMore` 和 `normalizationVersion`。`current_directory` 仅指现有玩家目录，不保证完整历史名称或实时在线覆盖；`directory_limit` 不可用于确认唯一身份。精确 KU 使用索引读取，名称规范化扫描最多 4096 条现有记录，不读存档或访问游戏控制台。

## 统一事件播报与旧插件迁移

同一插件负责进退服、分片状态和可选的公开聊天播报。多个群订阅同一个房间时共用事件流与短时读取结果；投递、游标和去重记录按群分别保存。事件中的玩家关联实际发送消息 ID，引用进服通知问“查他背包”可复用准确 KU。

**查询权限与播报权限各自校验。**“游戏查询”密钥不包含原始事件、聊天和房间详细接口。只有查询密钥时可以使用直查与 AI，播报显示权限不足。已存在同面板、同路径且具备全部播报依赖的连接时自动复用；多个匹配项可通过高级 `broadcastConnection` 明确选择。单个拥有这些读取权限的受信 MCP 连接可以同时承担查询与播报，群成员仍只获得插件的固定读取能力，不能调用任意管理接口。插件不会把不同面板的连接或凭证混用。

升级旧双插件时，统一插件在初始化和旧插件加载完成后检查迁移条件：核对同源连接与原房间范围，先保存待迁移状态，再停止旧任务、读取原 `broadcast_state_v1`，保存游标、队列、去重与投递记录，确认原插件关闭配置已落盘后才接管。保存失败时不启动第二个发送者；中断的迁移可以在重载或再次接入时继续。已处于 `sending/unknown` 的消息不重发，首次接入不会补发历史在线事件或聊天。原来只有播报的群仍只保留播报，不会自动获得背包等查询权限。

迁移成功后旧播报插件保持关闭，可在 AstrBot 插件管理中移除；新部署不再安装独立播报 ZIP。迁移前配置与状态保存在插件 KV 中，不写入公开文档或发布包。不同面板、原群已禁用、无法可靠保存或权限未满足时保留旧实例，检查连接后重载统一插件即可重试。

播报预算：最多 16 个订阅群、8 个不同房间，每房间最多 4 个世界；超过范围会停止相关订阅并提示缩小范围，不暗选前几个房间。没有启用的订阅时不启动后台网络轮询；有订阅时目录按需缓存 60 秒、每 30 秒核对，世界目录每 120 秒核对。MCP 最多两项在途，后台最多一项，事件流断开使用退避重连。权限或范围变化后在发送前再次核对；来源不可用不会被当作崩服，未知投递不会换发送者重试。

`/dst 自检`、`/dst 配置预览` 向管理员显示连接、缺少的能力、范围、队列和统一播报状态，不测试真实游戏管理或主动发测试群消息。后台版本通知继续使用面板已有通知机制；普通 MCP 连接本身不会主动唤醒模型。

## 验证边界

`/dst` 使用原生命令入口，设置命令由插件直接处理。未知命令和无效设置会明确提示，不交给模型宣称启用。只有保存确认才算生效；`/dst 设置` 会单独显示聊天播报开关和实际同步状态。普通成员不能修改群设置。

替换插件文件后应定向重新加载已启用的插件，并在插件详情确认存在 `dst` 命令（处理器 `dst_command`）；仅看到版本号变化不能证明新代码已加载。AstrBot 原生的配置模式插件选择、会话禁用和管理员限制仍生效，不会通过命令绕过。

如启用了 AstrBot 白名单，需要把目标群加入本机器人实际使用的配置。管理员豁免只允许管理员在群里操作，不表示整个群已获准查询和接收主动播报；插件不会自动扩大原生白名单。

自动测试覆盖快捷路由与反例、重名选择、可信引用、跨用户隔离、并发目标顺序、原生权限、受限密钥、多入口绕过、结果分层、超时、取消隔离、请求合并、持久化失败、未知回执和单一播报投递。框架适配测试使用 AstrBot 4.29.3 的真实权限包装器与工具序列化；外部发送和游戏写操作由替身接管。

常见问法使用公开的合成语料回归，包含菜单标签、礼貌前后缀、房间前后的查询词及分析/否定/复合操作反例。多轮测试覆盖“菜单 → 序号 → 昵称”、房间选择、离线玩家和读取失败；独立测试单项 AI 查询的可信卡片与会话历史一致性。运行方法和覆盖边界见 [集成测试说明](../integrations/astrbot/tests/README.md)。

真实 QQ 收信、线上高并发时延及逐玩家 Ping/FPS 仍需单独验收。后台版本主动通知继续使用面板原有通知机制与订阅配置；普通 MCP 连接不会自行唤醒机器人。


## 高级配置与无模型菜单

基础配置只需启用插件；连接名留空自动识别，默认 `mode=mixed`。常用指令直接查询，其他自然语言继续交给原有模型与人格。`shortcut` 仅提供快捷指令，复杂问题需显式 `AI: 问题`。管理连接及管理员名单均可留空，此时写能力关闭。

高级 `advanced` 是可选 JSON 对象，支持原有 `categories`、`commandAliases`、`roomAliases`、`menuItems`、`disabledCapabilities`、`writeAllowlist`、`bindings`、`pageSize`、`style`、`templates`、`taskNotifications`、`queryTimeout`、`inventoryTimeout`、`directoryTTL`；播报可配置 `broadcastConnection`、`leaveGrace`（5～60 秒）、`pollInterval`（状态检查，15～60 秒）与 `chatPollInterval`（聊天检查，2～30 秒，默认 3 秒）。多个群共用每房间的聊天读取及短缓存；失败会退避，空轮询不重写聊天游标。未知字段、无效类型和超限预算会拒绝，不能通过自定义配置扩权。

例如只开放状态、名单与模组，并将菜单每页设为 6 项：

```json
{"categories":["status","players","mods","help"],"pageSize":6}
```

旧配置字段保留为兼容数据并在普通表单隐藏，避免新用户面对重复设置。支持异步保存的框架会备份旧配置并迁入模式 3，保留显式的 shortcut、房间范围、类别、写白名单及会话覆盖；不会自动改掉旧群的权限或交互模式。旧模式 1/2 的有效配置继续兼容。

群聊使用 `@机器人 菜单` 或 `/dst 菜单`；私聊需启用 `allow_private`。菜单发出后的 2 分钟内，同一用户可直接回复序号、上一页/下一页或取消，无需再次 @。重复打开菜单后仅最新菜单生效，引用旧菜单不能选择新菜单里的目标；超时或其他用户的数字不触发查询。查询或管理操作缺少玩家时，同一用户可直接回复昵称；新指令会替换旧选择。被取消或替换且尚未发送的管理请求不会在排队结束后继续发送；已发送的操作仍保留原请求身份，可查询原结果，不自动重发。菜单选择、参数和个人查询目标限定在发起者和当前会话；显式引用本群播报时才共享其已确认玩家关联。未启用群的普通 `/dst` 查询会返回配置提示，不读取房间；只有管理员的明确启用指令可以接入该群。

帮助首页集中显示五个常用查询：服务器列表、房间状态、在线玩家、玩家信息和玩家背包。其他功能按“活动与连接、游戏管理、模组与更新、备份与任务、面板与运行诊断”归类，首页最多十个入口，不展开整份接口目录。只显示当前身份可用且未隐藏的项目；分类示例与数量从实际目录生成，空分类不显示。面板新增兼容能力会自动归类，无需逐项配置菜单。

游戏管理再按玩家状态与模式、物品与装备、生物与附近环境、地图与传送、世界与时间、房间运行与存档分组，根据能力的目标和参数自动归类。选择分类后查看具体操作，每页最多十项；回复 `返回菜单` 可回到首页，管理子分类也可回复 `返回游戏管理`。也可直接发送 `搜索功能 地图`、`找功能 复活` 或 `查找功能 更新`，跨分类按功能名称及目录别名查找。搜索只展示候选，即使只有一个结果也不会自动执行。选择后仍沿用原有参数收集、权限检查和需要时的确认流程。目录暂时不可用会明确提示，不解释为面板没有该功能。房间、玩家和背包来源选择继续使用原有 `pageSize` 配置。

`查房` 汇总最多 6 个开放房间；`1服信息`、`一服详情`查询指定房间的世界状态、已开放的在线名单和模组列表。中文数字首先对应明确配置的数字别名，其次精确匹配房间名称“1服”，不会把目录排序当成房间编号。背包按装备、物品栏、鼠标手持及嵌套容器展示，使用面板提供的物品名称与实际耐久/次数数据；数据不完整或输出截断会提示，不推算缺失百分比。

高级设置可配置房间别名、指令别名、菜单内容与顺序、停用能力、可见类别、明确开放的写能力、已验证的 QQ→KU 绑定、分页大小、模板、展示方式、任务通知和超时。模板仅允许 `{title}`、`{body}`、`{room}`、`{player}`；不执行表达式、对象访问或函数。来源、覆盖情况和管理结果不随模板消失。`detailed` 会补充目标 ID；默认 concise 保持简短。

升级时保留原生 `session_overrides` 兼容数据（高级 JSON 设置）。**只有 `overrideFields` 选中的字段覆盖全局**；其他值即使被 AstrBot 自动填成默认值也继续继承。明确选中的 `false` 和 `[]` 会生效。会话只能缩小全局房间、数据类别和写能力范围。

```json
{
  "session": "example-adapter:GroupMessage:example-group",
  "overrideFields": ["pageSize", "taskNotifications", "writeAllowlist"],
  "values": {
    "pageSize": 8,
    "taskNotifications": false,
    "writeAllowlist": []
  }
}
```

`menuItems` 使用固定命令 kind 或能力 ID 控制可见项目与组内顺序，例如 `["players","status","room.performance","*"]`；`*` 追加其余项，空列表只隐藏菜单项。首页先显示常用查询，其余项目进入所属分类；功能搜索也尊重菜单的隐藏选择。实际禁止执行应使用 `disabledCapabilities`，会话只能增加停用项，不能撤销全局禁用。菜单隐藏不会改变权限。

指令别名示例：`{"在线":"players","报表":"cap:room.performance"}`。别名只引用固定命令或面板已注册的能力，不接受 URL、工具函数、Lua 或脚本。动态参数支持基础类型、有界对象/数组和枚举；世界提供选择，玩家名沿用身份解析。可选参数自动使用经过校验的面板默认值，必填的写参数仍按提示提供；默认值不会替代危险操作确认。

配置预览只读展示当前生效范围；群绑定通过群内指令管理，其他自定义通过插件高级设置管理；无效授权配置会关闭相关执行。展示模板无效则回退内置样式。不要同时编辑 WebUI 和其他配置客户端；框架没有跨客户端全局 CAS 保证。插件不请求全量重载 AstrBot。

## 面板新增能力，插件不升级也能使用

服务端维护固定能力注册表，目录只描述已实现的操作。旧协议插件按需检查修订（默认 60 秒，可配置 10～300 秒），分页全部成功才替换目录；闲置时不轮询。新版私有连接直接按需检索原 API；下面的类别与 Schema 限制仅说明旧目录路径。面板新增加兼容的读取能力，且属于已开放的数据类别，会自动进入菜单。未知类别、未知协议或不支持的 Schema 不执行；新写能力必须显式加入 `writeAllowlist`，并且调用者仍须具备原生管理员身份和独立管理连接。

首批包括房间状态、玩家解析/名单/背包、模组、性能报表、备份设置、固定世界查询，以及启动/停止/重启/保存、立即备份、踢人和自动备份配置。保存和公告不属于只读能力；通用控制台不会暴露给群员。

例如开放 `room.backups.configure` 后，管理者可以直接说“开启自动备份/关闭自动备份”；菜单可以设置开关；修改完整计划可以使用明确的结构化参数：

```text
/dst 功能 room.backups.configure {"enabled":true,"schedule":"0 4 * * *","timezone":"Asia/Shanghai","keep":7}
```

参数未指定的已有计划设置由面板保留。配置成功表示计划已保存，不表示已经生成备份。立即执行仍使用“立即备份”。多个现有备份计划需要提供准确 taskId，不会任意选择。

旧专用门面可用 `dst_room_query(query="capabilities")` 读取兼容目录，再以 `query="cap:能力ID"` 配合 parameters JSON 查询。管理员可先用 `dst_game_action(action="capabilities")` 获取已开放写能力的参数，再用 `action="cap:能力ID"` 执行；新版四工具模式则使用 `dst_find`、`dst_read`、`dst_run` 和 `dst_result`。两种路径都保留授权和持久化任务校验。

## 稳定 API/MCP 契约

| MCP 名称 | 用途 |
| --- | --- |
| `api_listBotCapabilities` | 按当前密钥范围分页获取能力与参数 Schema |
| `api_queryBotCapability` | 执行一个固定只读能力 |
| `api_runBotCapability` | 提交一个固定写能力，必须有稳定 requestId |
| `api_getBotCapabilityResult` | 用原 requestId 读取原任务/查询，不重新下发 |

发现示例：

```json
{"query":{"protocolVersion":1,"limit":32}}
```

使用返回的 `schemaRevision`，不能把下面的示例修订值直接用于调用：

```json
{
  "path":{"roomId":"example-room","capabilityId":"room.players"},
  "query":{
    "contractVersion":1,
    "schemaRevision":"COPY_FROM_DIRECTORY",
    "requestId":"example-query-request-001",
    "parameters":"{}"
  }
}
```

查询的 parameters 是单个 JSON 字符串；写入 parameters 是 body 中的 JSON 对象。写入顶层 requestId 映射 `Idempotency-Key`。客户端隐藏编码细节；服务端拒绝未知字段、重复键、越界值和错误修订。

业务结果包含 `status/complete/source/observedAt/cached/executionOutcome/mayHaveExecuted`，以及 requestId、可选 jobId/queryRunId、data、error 和 nextAction。HTTP/MCP 成功只说明获得了一份业务回执，仍要检查业务状态。数量没有确认时不表示 0；任务已排队和 100% 不表示完成。

回包丢失时，只调用结果入口：

```json
{"path":{"roomId":"example-room","requestId":"example-write-request-001"}}
```

结果只属于最初接入身份和房间，并按当前权限复核。密钥或连接身份变化不会自动迁移旧任务。旧能力移除后可以在保留权限下读取原结果；不存在/已过期也不能证明没有执行。不要自动换 requestId 重发。

旧固定能力协议的预算：前台最多 2 个 MCP 在途请求，最多排队 32 项；通知使用独立的最多 2 个只读在途请求；单目录最多 256 项/1 MiB；参数最多 8 KiB、对象深度 4，单份业务结果最多 64 KiB。面板保留终态正文 7 天，之后保留轻量幂等身份；执行中和不确定回执不被普通历史清理淘汰。面板请求身份最多 10000 项，插件管理 journal 最多 256 项，满额时拒绝新提交并保留原记录供核对，不通过删除未确认记录恢复额度。新版通用路径按需加载单项接口和工作台定义，不受旧全量目录上限约束；预算见[自动能力发现](ai-capability-discovery.md)。QQ 投递缺少可靠回执时标记不确定，不自动重发。

### 管理员发放物品

查询接入不会自动授予游戏修改权限。使用独立的 `game-manage` 密钥，限定允许的房间，将它对应的 MCP 连接填入 `management_mcp_server`；`game_admins` 中的用户还必须是 AstrBot 原生管理员。高级配置 `writeAllowlist` 显式加入 `player.give_item`，原生工具权限将 `dst_game_action`、`dst_job`、`api_runBotCapability`、`api_giveRoomPlayerItem` 和 `api_getRoomPlayerItemGrant` 设为管理员。不要将只读密钥升级为管理密钥，也不要开放通用 Lua 工具。`/dst 设置` 可核对当前账号的管理角色和配置的写能力数量。

管理员可直接发送 `给 测试玩家 发 3 个肉丸`、`给 测试玩家 三个肉丸`、`发给 测试玩家 三个肉丸` 或 `1服给测试玩家发3个肉丸`（房间名称须能唯一匹配）。支持中文数量，按个最多 400 个且最多生成 40 个堆叠。旧面板仍按其公开的数量上限提示，不拆成多次请求。省略“发”时请用空格分开昵称和数量，存在两种玩家名拆分方式时不猜测。这类完整指令由插件直接处理，不调用模型；重名会要求选择。复杂表达由模型按当前协商的工具发现发放能力，再使用返回的参数结构；新版使用 `dst_find` → `dst_run`，旧专用门面保留 `dst_game_action(action="cap:player.give_item")`。

面板提供 `api_giveRoomPlayerItem`，输入如下。仅支持目录中可识别的原版物品、食物和装备，使用完整中文名、英文名或 Prefab；单次按个数发放 1–400 个，并按游戏内实际堆叠大小合并，最多生成 40 个物品实体；不可堆叠物品仍最多 40 个。不接受生物、建筑、未知模组 Prefab、脚本或自定义命令。

```json
{
  "path": {"roomId": "example-room", "playerId": "KU_TEST123"},
  "body": {"item": "肉丸", "count": 3},
  "requestId": "example-grant-0001"
}
```

服务端确认玩家所在分片后，只下发一次内置发放操作。本次同步回执确认后，返回 `status="succeeded"`、`complete=true`、`executionOutcome="confirmed"`、`requested=3`、`granted=3` 和 `runId`。背包满时物品可能落地；堆叠合并后的实体去向可能无法确认，不能通过背包总数反推本次发放是否成功。

`sent`、没有输出和回执截断都保留为不确定。玩家在执行前迁移、离线或尚未选人时，不换分片重发。`api_getRoomPlayerItemGrant` 使用 `path.roomId`、`path.playerId`、`path.runId` 和 `query.refresh=true` 补读两分钟内的原回执，不能执行命令或读取其他类型的控制台脚本。Bot 能力调用使用原 `requestId` 经 `api_getBotCapabilityResult` 回读；错误、重载或响应丢失后不得另发一个发放请求自动补偿。普通群员及 `game-read` 密钥无法调用写入口。

回归测试覆盖固定目录、数量及注入校验、只读标记伪造、分片确认、只读/管理权限隔离、无输出/截断/失联回执，以及重复 Bot 请求不重发；测试使用合成玩家，不向游戏或 QQ 发送测试操作。

### 管理员在玩家附近生成生物

在上述独立管理连接与双重管理员校验基础上，`writeAllowlist` 明确加入 `player.spawn_entity`，并将原生工具 `api_spawnRoomPlayerEntity`、`api_getRoomPlayerEntitySpawn` 设为管理员。普通群员及只读连接不获得此能力。

固定白名单仅包括座狼/狗王（`warg`）、猎犬（`hound`）、蜘蛛（`spider`）、猪人（`pigman`）、兔子（`rabbit`）、蜜蜂（`bee`）、独眼巨鹿（`deerclops`），单次 1–5 只。可直接发送 `在 示例玩家 附近生成三只座狼`，常用完整表达不经过模型；复杂表达仍由模型调用 `dst_game_action(action="capabilities")` 确认授权后使用 `action="cap:player.spawn_entity"`，参数为 `{"playerId":"KU_TEST123","entity":"座狼","count":3}`。AI 路径沿用同一入口和权限，缺少能力时不能退回通用 Lua。

具名 MCP 工具输入示例：

```json
{
  "path": {"roomId": "example-room", "playerId": "KU_TEST123"},
  "body": {"entity": "座狼", "count": 3},
  "requestId": "example-spawn-0001"
}
```

面板先确认当前分片，再在执行时核对玩家并预检附近 6–13 单位的可通行陆地（最多 40 次地图检查）。全部位置确认后才生成。玩家离线、迁移、死亡或附近没有合适陆地时不生成，也不换分片重试。除独眼巨鹿外的其他 Boss、皮弗娄牛、建筑和模组对象不通过该通用入口生成；这些对象可能需要专门初始化，白名单也不代表能保证第三方模组构造器无错误。

成功必须同时有本次 Runtime 回执、`status="succeeded"`、`complete=true`、`executionOutcome="confirmed"` 及确认数量 `spawned`。构造失败可能已有部分副作用，`sent`、无输出、重复或截断输出均不能视为成功。使用 `api_getRoomPlayerEntitySpawn` 的 `path.roomId`、`path.playerId`、`path.runId` 和 `query.refresh=true` 补读原回执；Bot 路径使用原 `requestId` 回读，不重新生成。返回包含本次位置审计，不向普通读连接开放其他管理记录。

### 背包名称与聊天排版

原版背包物品复用面板词库显示中文，无需为每个物品请求 MCP 或模型。玩家自定义名称保留，未知模组名称回退到已有名称或 Prefab。存档只有保鲜秒数时显示剩余时长，不伪造新鲜百分比。

聊天播报使用简短服名并移除游戏字体图标；相同短名会附带房间标识区分，身份解析仍使用原房间 ID。示例：

```text
💬 测试服 · 游戏聊天
示例玩家：我先走了，拜拜
```

### 自定义消息外观

统一插件提供全局与本群消息模板，覆盖聊天、进退服、开关服、查询和管理回执。在 AstrBot 插件配置中添加模板，或由管理员使用 `/dst 模板` 查看类型，按“编辑 → 预览 → 保存”操作。预览仅用模拟数据；本群模板优先于全局，恢复后继承上层。正文、失败与不确定回执、存档时间等证据继续保留。模板不会新增面板请求或后台任务，也不会改变已有权限。完整变量及示例见 [插件说明](../integrations/astrbot/astrbot_plugin_dst_companion/README.md#消息外观与模板)。

普通快捷查询直接展示插件卡片。显式 AI 请求可完整识别为单项读取、只使用本插件的房间/玩家查询工具且仅产生一张与原目标匹配的卡片时，非流式最终回复保留该卡片及来源；发送内容与本轮会话历史同步。数据源或会话权限改变后不展示原卡片。复杂分析、多房间、其他工具混用、图片或流式回复保持模型输出，并附加固定的饥荒排版提示；流式已发内容不能撤回，不能保证任意模型严格遵循提示。其他话题和人格保持原有行为。

## 固定工作台管理

面板将内置工作台配方发布到同一机器人能力目录：复活为
`player.resurrect`，其他内置配方为 `workbench.<commandId>`。
服务端只接受代码维护的指令 ID 和经类型、枚举、范围校验的标量参数；
不接受 Lua、自定义命令或调用者声明的只读/风险标记。玩家操作先确认实际在线分片，
本机和 Agent 均使用原 Runtime 执行及回执通道。

管理员可直接发送 `复活玩家`，按提示补充昵称或 KU ID；也可发送
`复活 示例玩家` 或 `复活示例玩家`。单人复活无需二次确认，仍须具备管理权限。
引用本机器人发出的死亡、复活、进退服或单人查询消息，可以选定该玩家，
适用于背包、资料和已授权的玩家操作；明确填写的昵称优先。引用回执须属于
当前群、机器人和面板，且房间仍在授权范围内，复制通知文字不能代替引用。
`再次复活` 沿用当前用户在本会话最近十分钟内已确认的玩家；没有目标、同名或
上次执行结果不确定时重新询问，不会根据唯一在线玩家猜测身份或自动重发。
`给玩家示例玩家发五个草` 支持带“玩家”称呼：先匹配完整昵称，确实不存在时
再尝试去掉称呼，读取失败或重名时不换人。
查询或管理操作提示选择玩家后，同一用户可在两分钟内直接回复昵称或 KU ID，
无需再次 @。昵称输错时可继续更正，原先的物品、数量等参数会保留；
玩家目录不可用与昵称未找到分别提示。也可直接回复本机器人的玩家通知说
“查背包”“复活”或“发五个草”，无需同时 @；引用仍须通过上述来源校验。
`发五个草给示例玩家`、`给他五个草` 也走固定发放流程；“他”须有已确认目标，
没有目标时先询问。参数补充支持中文数量和“开启／关闭”，仍校验声明的类型与范围。
复活仅向幽灵发出复活事件，存活玩家保持原状。其他配方可通过菜单选择，
或直接发送工作台完整操作名称并依次填写参数。复杂自然语言仍由模型理解，
随后使用同一能力和权限校验。

玩家模式可直接说 `给示例玩家开启一击必杀模式`、`给示例玩家关闭穿墙模式`、
`给示例玩家解除全部模式`。无敌、上帝模式表示完整的超级无敌效果；
`给示例玩家开启普通无敌模式` 或 `给示例玩家开启仅免伤模式` 只免伤、不补状态。
无敌、制造模式优先使用效果相同且已授权的专门能力，切换到工作台入口时保持相同效果，
不会因为权限不同改变模式。Runtime 2.4.26 起，这些入口共享开关与模式记忆，
可从其他入口关闭或解除全部八种模式。
工作台模式在面板声明单人无需确认、目标唯一且预览完整时由插件提交原预览执行；
没有完整回执不会自动重发。可选的“额外提示”沿用面板默认值，不要求填写内部枚举；
必填的开关仍须明确提供。一击必杀只影响非玩家目标，不增强对其他玩家的伤害，
并保留目标的格挡保护。模组改动导致效果不确定时如实提示，不自动重复开启。

`advanced.workbenchMode` 默认为 `standard`：允许已经具备管理身份、原生工具权限
和面板管理令牌的用户使用非 critical 的内置配方。`all` 额外开放危险配方，
每次都须用户在原会话直接回复“确认”，模型传入 `confirmed=true` 无法跳过。
`off` 仅保留 `writeAllowlist` 中显式授权的操作。会话只能缩小全局授权，
`disabledCapabilities` 始终优先。普通群员仍只使用开放的读取能力。

模型通过 `dst_game_action(action="capabilities", parameters=...)` 按需发现能力：

```json
{"search":"复活","offset":0,"limit":8}
```

返回 `items`、`total`、`nextOffset`；后续页沿用搜索条件与 `nextOffset`。
调用 `action="cap:player.resurrect"` 的参数示例：

```json
{"player_id":"KU_EXAMPLE123"}
```

面板底层 MCP 工具是 `api_executeBuiltinRoomCommand` 与
`api_getBuiltinRoomCommandRun`。两者均要求管理权限；后者只读原始内置执行记录，
不能读取任意自定义或原始 Lua 记录。执行入口示例：

```json
{
  "path":{"roomId":"example-room"},
  "body":{"commandId":"resurrect_player","arguments":{"player_id":"KU_EXAMPLE123"}},
  "requestId":"example-resurrection-001"
}
```

`runId` 绑定原执行；`sent`、超时及缺少回执都不代表成功。
`complete=true` 与 `executionOutcome=confirmed` 证明固定指令执行完毕，
游戏中的异步效果仍以同步输出和最新玩家状态为准。响应丢失只回读，
不因迁移或超时重新提交。

播报读取遇到关闭的 MCP SDK 会话时，可使用已配置的同源无会话 JSON MCP
只读恢复通道，不替换共享管理客户端。固定读取白名单、房间授权、响应上限、
并发预算、去重和投递游标仍生效；不会通过恢复通道重发管理操作或未知投递消息。

## 消息显示与升级

常见查询直接显示房间、玩家和已确认的结果；存档时间、部分读取和执行结果待确认等会按实际情况保留。正常回复不再默认附带接口对象或内部世界标识。主动查询原操作记录时仍提供请求与任务标识，方便排查。

已有自定义模板继续保留，不会在升级时覆盖。新增面板能力仍通过原能力目录发现，简单数值可直接展示；复杂而尚未提供专用展示的结果会提示在面板查看。普通用户读取权限、管理员修改权限和不确定操作不自动重发的规则保持原样。

## 房间变化与更新播报

房间维护、季节、版本更新、备份结果、死亡复活、Boss 击杀、模组消息、运行告警及“最近动态”的开关、回档天数含义、断线补读和 API 接入见[机器人事件播报](robot-event-notifications.md)。v0.4.7 起常用播报默认开启，聊天与模组自定义消息单独开启。升级为已使用常规播报的群补齐缺少的类别，保留明确关闭的选项、已关闭播报的群和原有权限；也可用 `/dst 通知预设 玩家群` 或 `/dst 通知预设 管理群` 主动更换类别选择。

### 常见地点传送

可说“传送玩家 示例玩家 到猪王”“把示例玩家传送到月岛”。面板公布支持的名称和别名，插件无需另配地点。首批支持出生点、猪王、月岛、绿洲、龙蝇沙漠和蜂后，仅查玩家当前分片；不会自动跨分片。地点来自实际实体或月岛地形，找不到或扫描未完成时不猜坐标；多点先选择，再检查可落脚位置，60 秒内确认后传送。仍可使用自存地点，名称不完全相同会列出真实候选，不自动按近似名称移动。同名时优先使用当前世界已保存的地点，别名也保留原输入；保存地点属于旧世界时需重新保存，不会自动改用常见地点。新版面板支持按所选保存地点的 ID 检查，改名不会使选择指向其他地点；旧面板继续使用名称与原有重名限制。

管理员可直接使用 `api_prepareRoomTeleport`，`body.locationName` 为上述名称；`needs_selection` 返回 `candidates`，选择其 `id` 放入可选 `body.landmarkRef` 重新检查。`prepared` 后确认并调用既有 `api_executeRoomTeleport`。普通读取者可通过 `api_queryRoomWorld` 使用 `path.queryId="landmarks"` 只读检查地点，不能借此传送。
